# 빈 회원 계정 삭제 실패: 운영 DB 계약 복구

## 확인한 문제

운영에서 새 일반회원 테스트 계정을 만들고 금전·구독·생성·문의 기록이 없음을 확인한 뒤 Auth 삭제를 호출했으나, `credit_accounts_user_id_fkey` 때문에 23503으로 실패했다.

Management API로 PostgreSQL 카탈로그를 직접 읽은 결과:

- `credit_accounts.user_id` → `profiles.id`의 삭제 규칙이 NO ACTION이다.
- `credit_member_has_records(uuid)` 함수가 없다. 단순한 REST 캐시 지연이 아니었다.
- 고아 장부 행은 없다. 지급·구독 등 다른 금전 관련 FK는 NO ACTION으로 정상 보호 중이다.

기존 `202609220003_credit_activate.sql`에는 필요한 정의가 있지만 운영 적용 상태와 달랐다. 이 파일 전체에는 전 회원 전환과 관리자 지급도 있어 재실행하지 않는다.

## 수정

새 `202610020003_member_delete_repair.sql`만 적용한다.

1. 금액을 담지 않는 `credit_accounts`의 해당 FK만 ON DELETE CASCADE로 교체한다.
2. 기존 계약 그대로 `credit_member_has_records(uuid)`를 복구한다.
3. PUBLIC/anon/authenticated의 실행을 막고 service_role에만 허용한다.
4. 같은 트랜잭션에서 REST 스키마 갱신을 통지한다. 잠금 대기는 5초, 실행 제한은 30초다.

회원·지급·구독 행을 수정하거나 삭제하는 DML은 없다. 금전 기록의 FK는 그대로 두므로, 삭제와 지급이 동시에 일어나도 확정된 지급 기록은 보존된다.

관리자 삭제와 본인 탈퇴의 앱 처리도 강화했다. 확인 함수 누락·조회 실패·빈 응답을 `기록 없음`으로 해석하지 않는다. 탈퇴의 처리 중 크레딧 조회 실패도 파일 삭제 전에 중단한다. 이미 기록이 있는 회원의 정지/탈퇴 보존 정책은 유지한다.

## 검증

- 운영과 같은 누락 함수/NO ACTION FK를 임시 PostgreSQL에 재현했다. 복구를 생략하면 테스트가 실패한다.
- DB 6개: 빈 계정 삭제, 회수된 지급 기록 보호, 구독만 있는 회원/금전 감사 기록이 있는 관리자 보호, 반복 적용 시 데이터 불변, 실행 권한, 동시 지급/삭제 보호.
- 앱 72개: 정상 삭제/금전 기록 차단, 누락 함수/빈 응답/보류 조회 실패 시 삭제 API와 파일 삭제가 실행되지 않음, 기존 소유자 보호/탈퇴 정책 회귀.
- 신규 DB 테스트를 PR CI와 릴리스 검증에 연결했다.

## 운영 적용 및 확인

- 적용 전 FK 정의·함수 존재·권한과 장부 합계를 별도 보관한다.
- **전체 db push 대신 이 파일 한 개만** 적용한다. 적용과 새 마이그레이션 이력 등록은 한 트랜잭션으로 처리한다.
- 적용 뒤 해당 FK가 CASCADE, 확인 함수가 존재, 서비스 역할만 실행 가능한지 확인한다. 다른 금전 FK와 기존 데이터 합계는 바뀌지 않아야 한다.
- 새 테스트 계정은 일반 Auth 삭제 한 번으로 프로필·빈 장부까지 제거되는지 검증한다. 빈 장부 수동 삭제를 사용하지 않는다.
- 금전/구독 보호는 운영 DB에서도 트랜잭션 안의 임시 fixture로 검증하고 ROLLBACK한다. 실제 회원 삭제나 지급 변경으로 시험하지 않는다.
- 앱 안전장치는 최종 병합 SHA의 검증된 릴리스로 배포한다. 운영 적용·검증 결과는 PR에 기록한다.

장애 시에는 적용 전 보관한 해당 FK·함수·권한만 복원 대상으로 삼는다. 예전 전체 전환 SQL을 되돌리거나 재실행하지 않는다. 확인 함수가 없는 동안 새 앱은 삭제를 중단한다.
