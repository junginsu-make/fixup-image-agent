# MCS 비용 전략실

**가상 시뮬레이션 도구다.** 운영 DB·크레딧 장부·생성 경로를 건드리지 않는다.
모델별 단가를 이 저장소 코드에서 읽어다 만든 계산기다.

## 어디에 있나

| 무엇 | 자리 |
|---|---|
| 도구 본체 | `apps/web/app/admin/cost-lab/lab.html` |
| 내주는 라우트 | `apps/web/app/admin/cost-lab/route.ts` |
| 문단속 규칙 | `apps/web/lib/admin/cost-lab.ts` |
| 이 문서·검증 | `docs/cost-lab/` |

**주소는 `/admin/cost-lab` 이고 관리자만 열린다.** 관리자 화면에 들어가는
단추가 있다. 이 시스템의 등급은 `member` 와 `admin` 둘뿐이라, 지금 표현할 수
있는 가장 좁은 범위가 관리자다.

HTML 은 **한 곳에만 둔다.** `verify.cjs` 도 그 파일을 읽는다 — 사본을 두면
둘 중 하나는 반드시 낡는다.

독립 실행 HTML 이다. 서버·외부 라이브러리·API 키 없이 브라우저에서 작동한다.

## 코드 검토 범위

저장소: https://github.com/junginsu-make/fixup-image-agent

고정 리비전: `ea1261483b01b9edb284dd070ecde72c710a73a0` (2026-09-11 조회)

이미지 모델의 저장소 가격표, 크레딧 환산, 포스터 기획/이미지 확정, SNS 정산, 상세페이지 배치, 캐릭터 신규 생성, 리디자인 생성/수정 경로를 읽었습니다. 운영 DB, 공급사 실시간 가격, 실제 결제 계약은 검증하지 않았습니다.

### 중요한 차이

- 원가 기준 1크레딧 $0.05, 양수는 올림.
- 포스터 기획은 별도 차감합니다. 기본 시나리오는 최초 기획 1회를 포함합니다.
- 카드뉴스는 이번 회차 그림 비용과 기획 비용을 합산합니다. 글 원가는 코드 추정 7회 × $0.014를 기본 가정으로 사용합니다.
- PDP 이미지는 성공 건수 기준으로 합산하여 올림합니다. 실제 호출의 크기 누락에 따른 정사각 기본 단가를 기본값으로 사용합니다.
- 캐릭터 신규 생성은 원가로 예약하지만 후보/추가 각도 생성 성공 시 이미지 개수로 확정합니다. 개별 각도 추가 API는 이와 다릅니다. 시뮬레이터의 기본 정면 1 + 추가 3은 작업 시나리오입니다.
- 리디자인 부분 수정은 공급사 원가로 예약한 뒤 1크레딧으로 확정합니다.
- 사용자 재생성은 추가 작업/크레딧 사용에 포함합니다. 일괄 배수로 재계산하지 않습니다.

## 계산 경계

기능별 사용 비중은 완료 작업 건수 비중입니다. 전체 작업 원가 / 전체 차감 크레딧으로 평균 원가를 구합니다. 무료 경제형 정책은 리디자인을 제외하고 남은 비중을 재정규화합니다. 이는 아직 구현되지 않은 사업 가정입니다.

자동 재시도율은 성공 작업의 추가 이미지 생성률입니다. 최종 실패는 별도의 실패 건수/성공 건수 비율로 추가하며, 실패 건 원가 발생률을 곱합니다. 두 항목은 서로 중복되지 않는 모집단으로 가정합니다. 이미지 0장 실패, 일부 성공, 재시도 상세 장부를 재생하는 도구는 아닙니다.

결제 수수료는 VAT 포함 결제액에 적용합니다. 목표 마진은 VAT 제외 매출에서 PG와 유료 AI/별도 분석 비용을 뺀 비율입니다. 무료 고객·고정비·고객 대응비는 월 운영 잔액과 손익분기에서 반영합니다. 최소 가격이 전체 사업의 이익을 보장하는 것은 아닙니다. 소진율에 따른 기간 추정으로, 선수금·이월 부채 회계는 구현하지 않았습니다.

## 공유

조건 링크는 URL fragment에 입력 조건을 담습니다. 개인 정보나 비밀을 입력하는 필드는 없습니다. 접근 권한은 별도로 부여해야 합니다. HTML 내려받기는 현재 조건을 파일 내부에 보존하므로 파일 자체를 내부 전달할 수 있습니다. 비교안은 브라우저 로컬 저장이며 공동 실시간 저장이 아닙니다.

## 검증

`node verify.cjs`: JavaScript 문법, 계산 항등식, 손익분기 경계, 목표 가격 역산, 입력 범위, 실패/재시도/환율 민감도, 0명·0비중 처리 등을 확인합니다.

57개 계산·구조 검사를 통과했습니다. 지원되는 브라우저 WebMCP 연결에서 최초 두 도구의 등록, 가격 35,000원/고객 120명 변경, 음수 가격 거부, 실패 시 상태 보존, 초기값 복원을 검증했습니다. 추가 고객 사용 계획 도구도 등록, 혼합 사용 97크레딧 계산, 음수 횟수 거부, 실패 시 상태 보존, 초기화를 검증했습니다. 브라우저 시각 QA는 요청되지 않아 수행하지 않았습니다.

## 고객 사용 가능량

고객 판매단가는 묶음 판매가 / 제공 크레딧으로 계산합니다. 작업 1회 판매가는 차감 크레딧을 곱하고, 이미지 1장당 평균 판매가는 생성 이미지 수로 나눕니다. 모두 부가세 포함 최종 판매금액이며 원가나 목표 마진을 다시 곱하지 않습니다. 기본 자동 모드에서는 목표 마진 또는 비용·사용량을 바꾸면 필요한 판매가를 올림하여 모든 화면에 반영합니다. 직접 판매가를 비교하려면 수동 모드를 선택합니다. 목표 마진을 다시 편집하면 자동 모드로 전환됩니다. 29,000원/100크레딧 기준 포스터 5크레딧은 작업 1회 1,450원, 카드뉴스 19크레딧/5장 기준 5,510원과 장당 1,102원입니다. 사용량 화면에 차감 전후 예시와 모든 크레딧 단위를 명시합니다.

묶음 전체 크레딧으로 기능별 새 작업을 몇 회 할 수 있는지 표시합니다. 회사 비용을 추정하는 소진율은 고객 사용 권한에 적용하지 않습니다. 최종 차감량뿐 아니라 작업 시작 시 확보해야 하는 잔액도 반영합니다.

캐릭터 신규 생성은 정면 후보 1장 + 추가 각도 방식으로 계산합니다. `lib/characters.ts`의 `clampCandidates(0)`가 1이 되므로 추가 각도 예약에도 후보 1장분이 포함됩니다. 각도 생성 직전 후보 1크레딧이 이미 차감되었다는 점도 고려합니다. 이 구조에서는 기본 100크레딧으로 4장 캐릭터 21개를 완료한 후 16크레딧이 남습니다. 리디자인 OpenAI 부분 수정은 시작 잔액 4개, 완료 차감 1개라 97회 후 3개가 남습니다. 시작 조건은 선택 단가·작업 장수에 따른 시뮬레이션이며 실제 서비스 동시 실행/일시 오류까지 보장하지 않습니다.

혼합 사용 계획은 시작 잔액과 차감량의 차이가 큰 작업부터 실행하는 순서로 필요한 크레딧을 계산합니다. 작업 순서를 바꾸면 마지막에 실행 가능 여부가 달라질 수 있습니다. 사용 계획은 현재 화면에만 유지하고 저장한 시나리오·조건 링크에 추가하지 않습니다.

## 자동 가격 계산 검증

80개 계산 검사를 통과했습니다. 브라우저 연결에서도 사이드바 20개 입력 변경에 따른 결과 갱신을 확인했습니다. 사용자가 입력한 목표 마진 50%를 보존하여 판매가 15,968원, 월 예상 이익 약 432,570원으로 갱신하고 확인 후 원래 입력 조건으로 복원했습니다. 자동 모드는 고정비와 무료 체험을 제외한 기존 목표 마진의 정의를 유지하며, 이 비용들은 전체 월 이익에 반영합니다.

전체 기능의 이미지 생성 배수는 기능별 추가 생성률을 덮어씁니다. 1.5배는 각 row.auto=50이며 기존 PDP 20%와 중복하지 않습니다. 기획/글 비용에 일괄 배수를 곱하지 않고 이미지 비용에만 반영하며 최종 실패 부담은 별도입니다. 고객의 결과 이미지 장수/차감 크레딧은 그대로 두고 서비스 비용과 자동 판매가를 갱신합니다. 이 설정은 각 기능의 auto 값으로 시나리오와 공유 링크에 저장됩니다.

## 판매가 고정 후 사용 가능량 배정

기본 모드는 allocate/protected입니다. 입력한 판매가와 제공 크레딧을 유지하고 각 작업의 원가를 감당하도록 차감량을 역산합니다. 고객수×구매묶음×크레딧 전체에 고정비·무료 비용·지원비·별도 분석비를 배분합니다. 부가세 제외 목표 이익과 결제 수수료, 운영비 배분을 제외한 크레딧당 AI 예산으로 작업 원가를 나누고 올림합니다. 최종 실패·재생성은 원가에 이미 포함되어 있습니다. 보호 계산은 크레딧 사용률 100%를 전제로 하며 월 추정 이익에는 실제 입력 사용률을 적용합니다.

무료 원가는 유료 차감량과 독립적으로 unified 기준 크레딧 환산을 사용하며 허용 기능 전체 중 가장 비싼 크레딧당 원가로 예산을 잡습니다. 따라서 무료 차감량의 순환 계산이 없고, 기능 비중이 바뀌더라도 각 유료 기능의 전량 사용 시 목표를 충족하도록 설계합니다. 생성 호출 비용 자체가 가정이므로 실측 오차를 보장하는 보험은 아닙니다. 매출 부족으로 AI 예산이 0 이하이면 제공 불가를 표시합니다.

이 결과는 실제 서비스에 아직 구현되지 않은 제안 차감 정책입니다. 기존 current/unified 방식의 비교 기능도 유지합니다. 모든 비용 차감 후 목표 이익률이라는 새 정의는 allocate 모드에만 적용하며 다른 모드는 기존 유료 매출 마진 정의를 유지합니다.

## 제공량을 정한 판매가 역산

고객 사용 계획에 작업 횟수 또는 총 이미지를 입력하면 단독 기능 상품과 전체 포함 상품의 필요 판매가를 계산합니다. 이미지 수는 작업당 이미지 수의 배수로 올림합니다. 사업 조건과 현재 판매가는 변경하지 않습니다. 가격은 AI 예상 비용+한 묶음 배분 운영비를 목표 순이익과 부가세/결제 수수료로 역산한 뒤, 정수 크레딧 배정 결과가 100크레딧 안에 들어오는 최소 원 단위까지 이진 탐색합니다. 전체 묶음 운영비는 한 번만 반영합니다. 작업 수가 크레딧보다 많으면 최소 1크레딧/작업 제한을 설명합니다.

## 계산 방식별 탭 분리

첫 탭은 크레딧·월 비용 기준(판매가/크레딧→허용량/월 손익), 두 번째 production 탭은 생산 수량 기준(횟수/이미지→비용/필요판매가)입니다. 운영비·모델·이익률은 공유하지만 수량 역산 결과는 첫 탭 값을 변경하지 않습니다. 현재 상품에 들어오는지 여부는 생산 수량 탭 하단 참고 항목으로 분리했습니다. 탭 이동과 재구성에서 공통 입력, 생산 계획, 견적 결과가 모두 보존되는 것을 브라우저 도구로 확인했습니다.

## 생산 수량 상품의 별도 이익률

생산 수량 탭에는 독립 목표 이익률을 두었습니다. 처음 열 때 첫 탭 목표를 복사하되 이후에는 별도로 변경합니다. 생산 수량의 단독 기능 견적과 전체 견적이 모두 이 값을 사용하며 첫 탭 값은 변경하지 않습니다. 최종 고객 결제액, AI+운영비, 모든 비용 차감 후 이익을 주요 지표로 표시하고 부가세/결제수수료/AI원가/배분운영비의 차감 내역을 같은 페이지에서 보여줍니다.

## 자동 제공 장수와 추가 재생성 장수

생산 수량 탭은 작업 횟수만 입력받아 기본 이미지를 자동 계산하고, 추가 재생성 제공 이미지를 별도 정수로 받습니다. 총 이미지=기본+재생성입니다. 생산 견적의 이미지 원가는 이 총량에 실패 비용을 적용하며, 기존 row.auto 생성 배수는 추가 적용하지 않습니다. 공통 무료 체험 예산은 기존 가정을 유지합니다. 추가 재생성에는 별도 기획 호출을 가정하지 않습니다. 기존 첫 탭 설정은 유지됩니다.
