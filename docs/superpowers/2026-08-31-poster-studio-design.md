# 포스터 스튜디오 — 레퍼런스 기반 포스터·광고 이미지 생성

작성일: 2026-08-31
개정: 2026-08-31 (외부 리뷰 반영 — 비용 정산 경로·키 권한 경계·배치 결과 계약·A4 해상도·원형 보존 표현)
상태: 설계 확정 대기 (구현 미착수)

## 무엇을 만드나

카드 스튜디오와 **독립된 새 섹션**. 긴 글을 여러 장으로 나누는 카드뉴스가 아니라,
**한 장짜리 포스터·광고 이미지**를 만든다.

사용자는 비율을 고르고 한 줄만 적는다. 나머지는 AI가 초안으로 채우고, 사람은 틀린 칸만 고친다.
**레퍼런스 이미지가 필수**이고, 결과가 그 레퍼런스를 닮아야 한다. 제품 이미지를 넣으면 원형이 보존돼야 한다.

## 왜 카드 스튜디오로는 안 되나

카드 스튜디오의 이미지 생성 엔진과 레퍼런스 반영은 그대로 쓸 수 있다. 막히는 것은 **앞단**이다.

| | 카드 스튜디오 | 포스터에 필요한 것 |
|---|---|---|
| 글 칸 | headline 60 + body 200 + accent 30 + footnote 40 = **330자 고정 4칸** | 헤드라인·받침문구·곁텍스트 여러 개 |
| 기획 | 자료를 주장 단위로 쪼개 **이야기 순서**를 짠다 | 순서가 아니라 **크기 위계** |
| 목적 프리셋 | 전부 서사 규칙("결론 먼저 → 근거 → 정리") | 포스터에 그대로 쓸 말이 아니다 |
| 결과 | 한 번 돌리면 끝, 한 장만 저장 | **여러 변형 + 고치는 루프가 본체** |
| 비율 | 4:5 · 1:1 · 9:16 | 포스터 비율·인쇄 규격 |

`MIN_CARDS = 1`이라 한 장 생성 자체는 이미 되지만, 뽑히는 내용이 카드뉴스의 것이다.

### 기본 모델을 GPT Image 2 로 두는 근거

한국어를 포함한 텍스트 렌더링과 레퍼런스 16장 때문이다. 다만 **근거의 강도를 구분해 적는다.**

| 주장 | 출처 | 강도 |
|---|---|---|
| CJK(중·일·한) 스크립트에서 글자를 자연스럽게 렌더한다 | fal 모델 페이지 자체 서술 | 1차 자료, 수치 없음 |
| 텍스트 정확도 "reported over 99%" | fal 해설 문서 — 일반 텍스트 기준이며 CJK 별도 수치가 아니다 | 2차, 조건부 |
| 이미지 생성 아레나 1위(485점) | llm-stats.com 리더보드(2026-08 기준) — **fal 자료가 아니다** | 3차, 참고용 |

**"한국어 정확도 99%"라고 단정하지 않는다.** 포스터는 작은 라벨이 많아 밀도가 다르므로
**실물 1장으로 확인하기 전까지는 미검증으로 둔다**(열린 질문 참고).

### 지금 코드에서 드러난 것

1. **`maxReferenceImages`가 7로 낡았다.** 실제는 nano 계열 둘 다 14장.
   다만 **카드 스튜디오에서 지금 병목은 아니다** — `selectReferences`가 역할별 스타일 1장 +
   보존 1장 + 앵커만 보내므로 7에 닿지 않는다. 포스터는 레퍼런스 여러 장 + 제품 + 직전 이미지를
   함께 넣으므로 **포스터에서 비로소 의미가 생긴다**
2. **GPT Image 2 단가가 `$0.25` 단일 추정치.** 실제는 크기·품질별 표
3. **비율이 3종뿐.** 모델은 11~15종 지원 — 포스터에 중요한 `2:3`·`3:4`가 빠져 있다
4. **`fal.subscribe`의 `requestId`를 버린다.** `src/studio/fal-client.ts`가 `data.images[0]`만
   꺼내고 나머지를 버린다. 이것이 비용 정산의 열쇠다(D10)
5. **배치 결과를 버린다.** 같은 파일이 `images[0]`만 돌려주고,
   `pipeline.ts`도 이미지 한 장·사용 기록 한 건만 저장한다. **지금 상태로 `num_images`를 올리면
   돈을 내고 결과를 버린다**(D9)

### 규격

인스타 기준 `1080×1350(4:5)` · `1080×1080(1:1)` · `1080×1920(9:16)`.
**지금 있는 세 비율이 SNS 광고 규격과 그대로 일치**한다.

### 레퍼런스 프롬프트 분석 (사용자 제공 2건)

사용자가 실제로 쓴 포스터 프롬프트 두 개를 겹쳐 보면 **뼈대가 같다.**

```
SAY IT :  SCENE  PEOPLE  ACTION  ARCHITECTURE │ TITLE  SUBTITLE │ ACCENT │ FORMAT
SNAP   :  SUBJECT        ACTION  BRAND        │ SHORT WORD      │ COLOR  │ RATIO
                                              │ TYPE INTERACTION
```

두 포스터가 공유하는 문법:

1. **거대 타이포가 배경이 아니라 구조** — 인물·건물이 글자를 가리고 통과한다
2. **지배색 1 + 흑백 + 강조색 소량**
3. **작은 편집 디테일** — 상단바·하단바·스펙 라벨·크로스헤어·얇은 선
4. **사실적인 인물/제품 사진** — 포즈 티가 안 나야 한다

그리고 두 프롬프트 모두 **슬롯 채우기 틀**이다. 자유 문장이 아니다.

## 결정

### D1. 독립 섹션 + 얇은 공용 층

`src/poster/` · `app/poster/` · `app/api/poster/`를 새로 만든다.

**빌려 쓰는 것** (도메인이 없는 공용 인프라): fal 클라이언트 · 모델 레지스트리 · 파일 업로드·경로 검증 ·
사용 기록 · 팀 격리
**새로 만드는 것**: 슬롯 기획 · 레퍼런스 문법 추출 · 프롬프트 조립 · 갤러리 · 수정 루프 · **비전 검수**

"참조하지 않는다"의 범위는 **카드뉴스의 도메인 코드**다 — 파이프라인·기획·원고·카드 스키마.
비전 검수기(`src/studio/vision-review.ts`)는 공용처럼 보이지만 프롬프트가 카드뉴스 전용이다
("한국어 인스타그램 카드뉴스 N/M장의 독립 품질 검수자", 앵커 비교, 카드 역할).
**포스터는 같은 방식(OpenAI Structured Outputs + data URL)으로 자기 검수기를 따로 만든다.**

카드 스튜디오를 **445개 테스트(56 파일)**가 지키고 있다. 거기에 `kind` 분기를 박는 대안은 그 코드를
위험에 빠뜨린다. fal 클라이언트까지 새로 만드는 대안은 이미 값을 치르고 배운 것(2분 타임아웃·
중복 과금 방지·해상도 배수 과금)을 버린다.

### D2. 흐름 — 초안형, 그리고 고치는 루프가 본체

```
① 입력   비율 · 한 줄 지시 · 레퍼런스(필수) · 제품 이미지(선택) · 모델 · 장수(1~3)
② 기획   fable 이 슬롯을 전부 채운 초안을 만든다
③ 확인   사람이 채워진 슬롯을 보고 틀린 칸만 고친다
④ 생성   슬롯 → 프롬프트 조립 → fal → **변형 N장 전부 저장**
⑤ 선택   사람이 변형 하나를 고른다                      ← 여기를 지나야 ⑥ 이 열린다
⑥ 반복   ├─ 수정 명령("글자를 더 크게") → 그 이미지를 /edit 로 고침
         └─ 다른 비율 → 선택된 이미지를 기준으로 재생성
```

대화형(채팅)이 아니라 **초안형**이다. AI가 빈칸을 다 채워 내놓고 사람은 고친다.
확신이 없는 칸은 가설을 명시하고 물어본다.

**⑤를 별도 단계로 둔 것이 중요하다.** 변형이 여러 장인데 어느 것을 고칠지 정하지 않으면
수정·리사이즈의 대상이 모호해진다.

### D3. 슬롯 고정

포스터 유형(영화·장소 홍보·공익·제품 광고)은 **슬롯 구조를 바꾸지 않는다. 같은 칸에 다른 값이 들어갈 뿐이다.**

| 묶음 | 슬롯 | 형태 |
|---|---|---|
| **무엇을 말하나** | 유형 | 열거 + 자유 입력 |
| | 헤드라인 | 짧은 문자열. 가장 크게 들어갈 말 |
| | 받침 문구 | 짧은 문자열 |
| | 곁텍스트 | 문자열 배열 (상단바·하단바·스펙 라벨) |
| **무엇이 보이나** | 장면 | 장소·사물·상황 |
| | 피사체 | 사람/제품/둘 다 + 나이·관계·외형 |
| | 동작 | 지금 이 순간 무슨 일이 일어나나 |
| **어떻게 보이나** | 타이포 관계 | 통과 / 뒤로 / 가림 / 감쌈 |
| | 지배색 · 강조색 | |
| | 금지 | 넣지 말 것 |

**타이포 관계를 독립 슬롯으로 뺀 것이 핵심이다.** 두 레퍼런스가 공유하는 가장 강한 특징인데,
문장 속에 묻어 두면 AI가 자주 놓친다.

곁텍스트가 배열인 이유는 SNAP 포스터의 렌즈 스펙(`28MM EQ. F2.0`, `ISO 400`)처럼
개수가 정해지지 않기 때문이다.

### D4. 비율과 모델은 백엔드가 자동으로 맞춘다

```
사용자가 고르는 것 :  비율(의도)  +  모델
백엔드가 정하는 것 :  그 모델에 실제로 보낼 값
```

- **픽셀 모드** (GPT Image 2) — 폭·높이를 계산한다. 제약: 양 변 16의 배수 · 총 픽셀 655,360~8,294,400 ·
  최대 변 3840 · 최대 비 3:1
- **열거 모드** (nano 둘) — 그 모델의 `supportedRatios` 에서 **가장 가까운 것**을 고른다

| 이름 | 비율 | GPT 픽셀 | dpi (A4 출력 시) | nano |
|---|---|---|---|---|
| 인스타 피드 | 4:5 | 1088×1360 | — | `4:5` |
| 정사각형 | 1:1 | 1088×1088 | — | `1:1` |
| 스토리·릴스 | 9:16 | 1152×2048 | — | `9:16` |
| 포스터 세로 | 2:3 | 1024×1536 | — | `2:3` |
| 포스터 세로(넓은) | 3:4 | 1152×1536 | — | `3:4` |
| 가로 배너 | 16:9 | 2048×1152 | — | `16:9` |
| **A4 비율 시안** | 1:1.414 | 1088×1536 | **약 131dpi** | ⚠ `3:4` |
| **A4 인쇄용** | 1:1.414 | **2400×3392** | **약 290dpi** | ⚠ 불가 — GPT 전용 |

**A4 를 두 줄로 나눈 이유:** 1088×1536 은 A4 *비율*은 맞지만 실제 A4 용지에 인쇄하면 약 131dpi 다.
화면 시안에는 충분하나 인쇄물이라고 부르면 오해를 만든다.
인쇄가 목적이면 **2400×3392**(약 290dpi, 8,140,800px, 양 변 16 배수, 비율 오차 0.062%)를 쓴다.
GPT Image 2 제약을 모두 만족한다. nano 계열은 픽셀 지정이 안 되므로 A4 인쇄용을 제공하지 않는다.

> **A4 비율 시안의 nano 대체는 사실상 동률이다.** 목표 1.4142 에 대해 `3:4`(1.3333)는 거리 0.081,
> `2:3`(1.5)은 0.086 — 6% 차이뿐이다. **A4 → `3:4` 를 규칙으로 못 박는다**(더 짧은 쪽이라
> 인쇄 시 여백으로 처리하기 쉽다). 최근접 계산에 맡기지 않는다.

**대체·불가가 발생하면 반드시 알린다.**

> Nano Banana 2 는 A4 비율을 지원하지 않아 3:4 로 만듭니다. 정확한 A4 가 필요하면 GPT Image 2 를 고르세요.

조용히 바꾸면 사용자는 왜 인쇄가 안 맞는지 영원히 모른다.
순수 함수 `resolveSize(ratio, model)` 하나로 만들고, 대체·거부 사실을 반환값에 담는다.

**모델이 지원하는 비율**과 **섹션이 보여주는 비율**을 분리한다.

```
모델 스펙   supportedRatios   ← 모델이 실제로 되는 것 (NB2 15 / Pro 11 / GPT 픽셀)
섹션        exposedRatios     ← 카드는 3종, 포스터는 위 표의 8종
```

**GPT Image 2 `/edit` 의 `image_size` 기본값은 `auto`**(입력 이미지에서 추론)다.
명시하지 않으면 **레퍼런스 포스터 크기가 그대로 나온다.** 항상 못 박는다.

**`quality` 는 `high` 로 고정한다.** 사용자에게 노출하지 않는다 — 품질을 낮춰 아끼는 것보다
모델을 바꾸는 편이 이해하기 쉽고, 파라미터가 하나 늘면 비용 계산 경우의 수가 세 배가 된다.

### D5. 레퍼런스 — 분석은 얹는 것이지 대체하는 것이 아니다

| 종류 | 필수 | 역할 |
|---|---|---|
| 스타일 레퍼런스 | ✅ | 포스터 문법을 여기서 뽑는다. 갤러리에서 불러오기 가능 |
| 원형 보존 이미지 | 선택 | 제품·인물·로고 |
| 직전 생성 이미지 | 자동 | 수정 루프에서만 |

**문법 추출** — 비전 1회로 *"어떻게 보이나"* 슬롯의 초기값을 뽑는다
(타이포 관계·지배색·강조색·곁텍스트 종류·질감).

> ⚠ **이 프로젝트는 "레퍼런스 분석" 길에서 한 번 실패했다.**
> 기존 CardForge 경로는 참조 이미지를 비전으로 **분석해 HTML/CSS 템플릿을 재구성**했고,
> 분석이 성공해도 결과물이 원본과 닮지 않았다. 카드 스튜디오가 성공한 이유는 **분석을 안 하고
> 원본을 그대로 넘겼기** 때문이다.

안전장치 둘:

1. **원본 레퍼런스는 항상 fal 에 함께 넘어간다.** 분석 결과가 원본을 대체하지 않는다
2. **추출이 실패하거나 이상하면 슬롯을 비워 두고 원본만 넘긴다.** 막지 않는다

#### 원형 보존은 "보장"이 아니다

카드 스튜디오의 `usage: style | preserve` 축을 그대로 쓰되, **무엇을 약속하는지 정확히 적는다.**

| 층 | 내용 |
|---|---|
| **목표** | 제품·인물·로고가 원형 그대로 들어간다 |
| **모델 계약** | 프롬프트 지시(`card-prompt.ts` 의 PRESERVED CONTENT ASSET 블록) — *"identity, shape, colors, proportions, labels, and logo 을 정확히 유지하고 다시 그리지 마라"* |
| **합격 조건** | 비전 검수 통과 + **사람 눈 확인** |
| **보장하지 않는 것** | **픽셀 단위 보존이 아니다.** 생성 모델이 다시 그린 결과이고, 사후 비교로 걸러낼 뿐이다 |

실측 근거는 **N=1**이다(2026-08-26, 제품 사진 1장으로 로고·제품명·성분 문구 유지 확인).
구조적 보장이 아니라 한 번의 성공 사례다.

**로고·법정 표기·가격처럼 정확성이 필수인 요소는 생성 결과를 그대로 신뢰하지 않는다.**
그것이 제품 요구사항이 되면 마스크 인페인팅(GPT Image 2 의 `mask_image_url`)이나
생성 후 결정적 합성 경로를 **별도로** 설계해야 한다. 이번 범위 밖이다.

### D6. 데이터 — 갤러리·생성 요청·결과 계보

네 테이블을 새로 만든다. **과금은 이미지가 아니라 fal 요청 한 건에 붙으므로 생성 요청을 별도 행으로 둔다.**

```
poster_references           갤러리. 카드용 reference_images 와 별도
poster_projects             한 건의 포스터 작업 (슬롯·비율·모델·상태)
poster_generation_requests  fal 호출 한 건 (배치·requestId·추정·정산이 여기에 한 번만 기록된다)
poster_images               생성 결과 한 장 (변형·수정 이력이 여기 쌓인다)
```

`poster_generation_requests` 는 호출·비용 계약을 담는다.

| 칸 | 뜻 |
|---|---|
| `project_id` | 어느 작업에서 나온 호출인가. 행 하나가 곧 fal 호출 한 건이라 별도 `batch_id` 를 두지 않는다 |
| `fal_request_id` | 정산 조회 키 (D10). 성공·타임아웃 모두 가능한 즉시 저장 |
| `parent_image_id` | 무엇을 고쳐 달라는 요청인가. 최초 생성은 비어 있다 |
| `edit_instruction` | 수정 루프에서 사람이 준 지시. 최초 생성은 비어 있다 |
| `model_id` · `ratio` · `size` | 실제로 요청한 모델과 출력 규격 |
| `requested_images` · `returned_images` | 요청 장수와 실제 결과 장수 |
| `estimated_cost_usd` | 생성 전에 계산한 보수적 추정액. 정산액과 섞지 않는다 |
| `cost_state` · `cost_usd` | `pending` / `reconciled` / `unknown` 과 요청 한 건의 실제 정산액 |
| `cost_reason` | `unknown` 사유: `admin_unavailable` / `deadline_exceeded` / `api_error` |

`poster_images` 는 결과 한 장과 계보만 담는다.

| 칸 | 뜻 |
|---|---|
| `project_id` | 어느 작업의 결과인가 |
| `generation_request_id` · `variant_index` | 어느 요청에서 함께 나온 N장 중 몇 번째인가 |
| `selected` | 사람이 고른 변형인가 |
| `asset_path` · `width` · `height` | 결과 파일 |

배치 3장이 같은 `fal_request_id` 의 정산액을 이미지마다 복제하면 합계가 3배가 된다.
그래서 `cost_usd` 는 `poster_generation_requests` 에 한 번만 기록하고, 프로젝트 비용도 이 테이블만 합산한다.

**같은 이유로 `parent_image_id` 와 `edit_instruction` 도 요청 쪽에 둔다.** 한 번의 수정 요청이
변형 3장을 낳으면 부모와 지시가 3번 복제되고, "같은 요청의 이미지들이 서로 다른 지시를 갖는"
불가능한 상태가 스키마상 표현 가능해진다. 계보는 `이미지 → 요청 → 부모 이미지` 로 따라간다 —
조인이 한 번 늘지만 어긋날 수 없다.

RLS 는 카드와 같은 패턴(`is_master() or team_id = my_team_id()`)이되,
**컬럼 권한은 회수가 아니라 허용 목록으로 쓴다.**

```sql
-- 틀림: 테이블에 주고 컬럼을 뺀다 (컬럼 REVOKE 는 무시된다)
grant update on poster_projects to authenticated;
revoke update (team_id) on poster_projects from authenticated;

-- 맞음: 테이블에서 회수하고 컬럼만 준다
revoke update on poster_projects from authenticated;
grant update (title, status, data, updated_at) on poster_projects to authenticated;
```

지난 팀 권한 설계에서 외부 리뷰가 세 라운드 도는 동안 이 실수를 두 번 했다.

### D7. 기획은 fable 이 한다 — 코드 변경 없음

이미 Anthropic 제공자가 붙어 있고 OpenAI 폴백까지 걸려 있다.
`ANTHROPIC_MODEL` 환경변수를 `claude-fable-5` 로 두면 된다.

### D8. 한국어

레퍼런스 두 장은 글자가 영어다. "한국어 유지"는 **한국어를 넣었을 때 깨지지 않는 것**으로 읽는다 —
전부 한국어로 강제하는 것이 아니다. 슬롯 값은 사람이 쓴 그대로 렌더한다.

카드 스튜디오의 검증된 지시문을 그대로 쓴다.

> "이 한국어 텍스트를 글자 그대로 렌더하라. 번역·의역·축약하지 말고, 목록에 없는 글자를 더하지 마라"

### D9. 배치 결과 계약 — `num_images` 를 켜기 전에 반드시 먼저

세 모델 모두 한 요청에 1~4장을 돌려준다. **그런데 지금 코드는 첫 장만 꺼내고 버린다.**
이 상태로 `num_images` 를 올리면 **N장 값을 내고 1장만 쓴다.**

그래서 `num_images` 를 켜기 전에 아래 계약을 먼저 만든다.

1. **`FalRunner.run` 의 반환형을 `{ images: FalImage[], requestId }` 로 바꾼다.**
   지금은 `FalImageResult` 한 장이고 `requestId` 를 버린다
2. **호출 한 건을 `poster_generation_requests` 에 먼저 저장하고 모든 변형을 `poster_images` 에 저장한다.**
   하나도 버리지 않는다
3. **과금은 생성 요청 한 건에 한 번만 기록한다.** `requested_images` 와 `returned_images` 를 남기고,
   `imageCount: 1` 고정을 없애되 이미지 행마다 총액을 복제하지 않는다
4. **사람이 변형 하나를 고른 뒤에만** 수정·다른 비율 생성이 열린다(D2 ⑤)
5. **부모와 계보를 저장한다** — 요청 쪽에 `parent_image_id`·`edit_instruction`,
   이미지 쪽에 `generation_request_id`·`variant_index`
6. **비전 검수는 선택된 변형에만 돌린다.** 변형 3장을 모두 검수하면 검수 비용도 3배가 되는데,
   버릴 2장을 검수할 이유가 없다

**카드 스튜디오의 `FalRunner` 를 함께 바꾸게 된다.** 반환형이 바뀌므로 카드 쪽 호출부도 손댄다 —
`images[0]` 을 꺼내 쓰던 자리를 그대로 유지하는 최소 변경으로, 동작은 바뀌지 않는다.
445개 테스트가 회귀를 잡는다.

### D10. 비용 — 사전 추정과 사후 정산을 분리한다

**추정과 정산은 다른 값이다.** 문서와 화면에서 섞지 않는다.

#### 사후 정산이 진실이다 — fal Billing Events

fal 응답 스키마에는 `images` 뿐이고 금액이 없다. 대신 **`request_id` 로 개별 과금 이벤트를
조회하는 공식 API** 가 있다.

```
GET https://api.fal.ai/v1/models/billing-events?request_id=<id>
→ output_units, unit_price, percent_discount,
  cost_subtotal, cost_discount, cost_total, cost_estimate_nano_usd
```

> ⚠ **이 API 는 ADMIN scope API 키를 요구한다.** 문서에
> *"Admin API key must be prefixed with `Key `"* 라고 명시돼 있다.

**실측 (2026-08-31):** 현재 `FAL_KEY` 로 Billing Events 를 조회하면 **403** 이 온다.

```
GET api.fal.ai/v1/models/billing-events?limit=2
→ {"error":{"type":"authorization_error",
             "message":"This API key is not permitted to perform this action."}}
```

즉 현재 키는 **API scope 이고 ADMIN 이 아니다.** 이미지 생성에는 아무 문제가 없다 —
카드 스튜디오 전체가 이 키로 돌고 있다. 정산 조회만 별도 권한을 요구하는 다른 API 다.

따라서 지금 상태에 **권한 과다는 없다.** 분리 원칙이 뜻하는 것은 하나다 —
ADMIN 키를 발급하더라도 **`FAL_KEY` 를 그것으로 교체하지 말고 별도 변수로 추가한다.**
교체하면 그때부터 모델 호출 코드가 앱 관리·CLI·Platform API 권한까지 들고 다니게 된다.

| 환경변수 | scope | 쓰는 곳 |
|---|---|---|
| `FAL_KEY` | API | fal 모델 호출 전용 |
| `FAL_BILLING_ADMIN_KEY` | ADMIN | Billing Events 정산 조회 전용. 서버/정산 작업에서만 읽는다 |

두 키는 반드시 **같은 개인·팀 workspace** 에서 발급돼야 한다. 다른 workspace 의 Admin 키로는
`FAL_KEY` 가 만든 요청의 과금 이벤트를 조회할 수 없다. `FAL_BILLING_ADMIN_KEY` 는 브라우저 번들,
`NEXT_PUBLIC_*`, 로그, 오류 메시지에 절대 노출하지 않는다.

Admin 키를 확보하지 못하면 사후 정산은 불가능하고 사전 추정만 남는다. 그 경우 화면은 항상
"예상 금액"만 보여주고, 실제 금액은 fal 대시보드에서 확인해야 한다.

제약: 한 번에 request_id 1~50개, 날짜 범위 90일 이내, 페이지당 10000건.

#### 비용 상태 기계

```
pending      호출 직후부터 정상 재조회 기한까지. 이벤트가 아직 없으면 이 상태를 유지한다
reconciled   Billing Events 로 실제 금액을 받아 기록했다
unknown      재조회 기한 초과, Admin 키 미제공·권한 부족, 지속적인 API 오류로 정산할 수 없다
```

정상적인 반영 지연은 실패도 `unknown` 도 아니다. 재조회 기한 안에는 `pending` 으로 두고 **"정산 중"** 으로
표시한다. `unknown` 은 생성 실패가 아니라 **정산 불가가 확정된 종결 상태**다. 이때 `cost_reason` 을 함께
저장하고 화면에는 추정치를 유지하되 **"정산 불가 · 추정 금액"** 으로 표시한다.

#### 사전 추정 — fal 견적 API 를 1순위로 쓴다

**실측 (2026-08-31): `POST /v1/models/pricing/estimate` 는 지금 `FAL_KEY` 로 된다.**
문서가 요구하는 것도 *"**API key** must be prefixed with `Key `"* 로, Billing Events 와 달리
ADMIN 을 요구하지 않는다.

```
POST /v1/models/pricing/estimate
{"estimate_type":"historical_api_price","endpoints":{"<endpoint>":{"call_quantity":N}}}
→ {"estimate_type":"...","total_cost":0.12,"currency":"USD"}
```

실측값:

| 엔드포인트 | 견적 | 대조 |
|---|---|---|
| `fal-ai/nano-banana-2/edit` | **$0.12** | 우리가 아는 2K 단가 `$0.08 × 1.5` 와 **정확히 일치** |
| `openai/gpt-image-2/edit` | **$0.22** | 공식 표의 우리 크기 범위($0.151~$0.234) 안 |
| `fal-ai/nano-banana-pro/edit` | $0.30 | 알려진 2K 단가 $0.15 의 **2배 — 설명되지 않음** |
| `fal-ai/flux/dev` (쓴 적 없음) | $0.05 | **이력이 없어도 값을 준다** |

> ⚠ **이 값이 "우리 이력"이라고 단정할 수 없다.** 한 번도 부르지 않은 엔드포인트도 값을 돌려주고,
> nano-pro 는 알려진 단가의 2배가 나온다. fal 내부에서 목록가로 대체하는 경로가 있는 것으로 보인다.
> **참고값으로 쓰되 진실은 사후 정산이다.**

**`unit_price` 방식은 쓰지 않는다.** `openai/gpt-image-2/edit` 에 `unit_quantity: 3` 을 주면
**$3.00**(장당 $1)이 나온다. 실제 단가와 자릿수가 다르다.

#### 추정 우선순위

```
1순위  pricing/estimate (historical_api_price)   ← 지금 키로 됨
2순위  마지막으로 성공한 견적값 캐시              ← API 가 죽었을 때
3순위  모델 레지스트리의 공표 단가 + "정확도 낮음" 표시
```

nano 둘은 3순위(공표 단가 × 해상도 배수)만으로도 정확하다. **1순위가 꼭 필요한 것은 GPT Image 2 다.**

#### 공표 단가 표를 그대로 쓸 수 없는 이유

GPT Image 2 가격은 **픽셀에 비례하지 않는다.** 표를 픽셀 오름차순으로 세우면 가격이 오르내린다.

| 크기 | 픽셀 | 가로세로비 | high |
|---|---|---|---|
| 1024×768 | 786,432 | 1.33 | $0.151 |
| 1024×1024 | 1,048,576 | 1.00 | **$0.219** |
| 1024×1536 | 1,572,864 | 1.50 | $0.178 ← 픽셀 50% 많은데 더 싸다 |
| 1920×1080 | 2,073,600 | 1.78 | $0.158 ← 픽셀 2배인데 더 싸다 |
| 2560×1440 | 3,686,400 | 1.78 | $0.234 |
| 3840×2160 | 8,294,400 | 1.78 | $0.413 |

정사각형에 가까울수록 비싸다. 이미지를 타일로 쪼개 토큰을 세기 때문으로 보인다.
**따라서 "픽셀이 더 큰 규격의 값을 상한으로" 같은 규칙은 성립하지 않는다** —
1088×1088(정사각형)에 그 규칙을 적용하면 $0.178 이 나오는데 실제는 $0.219 쪽이라 과소 추정이다.

이것이 1순위를 견적 API 로 두는 이유다. 3순위로 떨어졌을 때는 **표의 값을 쓰되 화면에
"정확도 낮음"을 함께 표시**하고, 정확한 금액은 정산이나 fal 대시보드에서 확인하게 한다.

#### 화면 문구

```
생성 전   예상 $0.22 · 실제 금액은 생성 후 정산
정산 중   정산 중 · 예상 $0.22
정산 완료 $0.19
정산 불가 정산 불가 · 예상 $0.22
```

"최대"라고 쓰지 않는다. 공식 가격표로는 실제 최대 금액을 보장할 수 없다.

|---|---|
| 문법 추출 실패 | 원본만 넘기고 진행. 막지 않는다 |
| 비율 미지원 | 가장 가까운 것으로 대체 + **화면에 알린다**. A4 인쇄용은 nano 에서 **거부**하고 GPT 를 권한다 |
| 생성 실패 | 2분 타임아웃, **자동 재시도 없음** (중복 과금 방지). **requestId 는 저장한다** — 타임아웃돼도 과금됐을 수 있다 |
| 기획 실패 | 슬롯을 비운 채 사람이 직접 채우게 한다 |
| 정산 이벤트 미반영 | 정상 재조회 기한 안에는 `pending` 유지. requestId 로 다시 조회한다 |
| 정산 불가 | 기한 초과·Admin 키 없음·지속 API 오류일 때만 `unknown` + `cost_reason`. 추정치를 유지한다 |
| 비전 검수 | **포스터 전용 검수기**로 선택된 변형만 검수 — 글자 정확도·잘림·겹침·원형 보존 대조 |

## 검증

### 첫 작업 — 비용 정산 경로 확인

**사전 추정은 이미 확정됐다** — `pricing/estimate` 가 지금 키로 되는 것을 2026-08-31 에 실측했다.
남은 것은 **사후 정산**뿐이다. 합격 조건:

1. `onEnqueue` 시점부터 `requestId` 를 보존한다
2. **성공·타임아웃 모두** 해당 ID 를 저장한다
3. 모델 호출용 `FAL_KEY` 와 **같은 workspace** 의 `FAL_BILLING_ADMIN_KEY` 로 Billing Events 조회가
   되는지 확인한다 — 안 되면 키 확보 경로를 정하거나 추정만으로 간다는 결정을 문서에 남긴다
4. 실제 호출 1회로 `cost_total` 을 받아 기록한다
5. **과금 이벤트가 반영되기까지의 지연 시간을 잰다** — 즉시인지, 분 단위인지가 재조회 주기를 정한다
6. `pending → reconciled` 와 재조회 기한 초과 뒤의 `pending → unknown` 전이를 코드로 고정한다
7. Admin 키가 없거나 403 이면 `unknown + admin_unavailable`, 지속 API 오류면 `unknown + api_error`,
   기한 안에 이벤트가 없으면 `pending` 임을 고정한다

**"응답 전체를 찍어 본다"로는 확정되지 않는다.** 응답에 금액이 없기 때문이다.

### 순수 함수

- `resolveSize(ratio, model)` — 픽셀 제약 만족, 모델별 `supportedRatios` 최근접 선택,
  A4 → `3:4` 고정 규칙, 대체·거부 사실 반환
- 슬롯 → 프롬프트 조립 — 슬롯이 비어도 프롬프트가 깨지지 않는다
- 비용 추정 — 1순위(견적 API) → 2순위(캐시) → 3순위(공표 단가) 로 정확히 떨어지는지,
  `unit_price` 방식을 절대 부르지 않는지, 결과가 `최대`가 아닌 `예상`으로 표시되는지
- 문법 추출 — 응답이 이상하면 `undefined` 를 돌려주고 **던지지 않는다**
- 레퍼런스 구성 — 원본이 항상 포함된다, 원형 보존이 스타일로 대체되지 않는다

### 계약 회귀

- `FalRunner` 반환형 변경 뒤 **카드 스튜디오 445개 테스트가 그대로 통과**한다
- `num_images: 3` 일 때 **생성 요청 1행 + 이미지 3행**이 저장되고, 정산 총액은 생성 요청에 한 번만 기록된다
- 프로젝트 비용 합계는 `poster_images` 가 아니라 `poster_generation_requests` 만 더해 중복 과금이 없다
- 변형을 고르기 전에는 수정·리사이즈가 막힌다
- 모델 호출 코드는 `FAL_KEY` 만 읽고, 정산 코드는 `FAL_BILLING_ADMIN_KEY` 만 읽는다
- `FAL_BILLING_ADMIN_KEY` 가 브라우저 번들·클라이언트 응답·로그·오류 메시지에 포함되지 않는다

### 실물 검증 (사람이 한다)

참고 포스터 1장 + 제품 이미지 1장으로 한 장 만들어 **레퍼런스를 닮았는지 · 제품이 원형대로인지 ·
한국어가 깨지지 않았는지**를 눈으로 본다. A4 인쇄용(2400×3392)을 채택하면 **큰 해상도의
품질과 실제 비용도 함께 확인한다.**

## 하지 않는 것

- **카드 스튜디오에 `kind` 분기를 넣지 않는다.** 독립 섹션이다
- **채팅형 대화 UI 를 만들지 않는다.** 초안형이다
- **레시피 내장 세트를 만들지 않는다.** 문법은 레퍼런스에서만 뽑는다
- **여러 규격 동시 생성을 1단계에 넣지 않는다.** 한 비율로 만들고, 필요하면 리사이즈로 이어 간다
- **웹 검색·high thinking 을 켜지 않는다.** 추가 과금이 붙는다
- **`quality` 를 사용자에게 노출하지 않는다.** `high` 고정
- **마스크 인페인팅·결정적 합성을 이번에 만들지 않는다.** 로고·법정 표기의 정확한 보존이
  요구사항이 되면 그때 별도 설계한다

## 열린 질문

| 질문 | 검증 방법 | 기한 |
|---|---|---|
| ~~현재 `FAL_KEY` 로 **정산**이 조회되는가~~ → **아니다. 403 실측** | 완료 | — |
| ~~현재 `FAL_KEY` 로 **견적**이 조회되는가~~ → **된다. 200 실측** | 완료 | — |
| 견적값이 우리 이력인가 목록가인가 — nano-pro 가 2배로 나오는 이유 | 정산이 열리면 대조 | 정산 확보 후 |
| fal 계정에서 ADMIN scope 키를 **발급할 수 있는가** | 사용자가 대시보드에서 확인 | 구현 착수 전 |
| 과금 이벤트 반영 지연은 얼마인가 | 호출 후 재조회 간격을 재 본다 | 첫 작업과 함께 |
| 포스터 밀도의 한국어(작은 라벨 다수)가 깨지지 않는가 | 실물 1장 | 1단계 종료 시 |
| A4 인쇄용(2400×3392)이 실제로 필요하고 품질·비용이 감당되는가 | 실물 1장 + 정산 확인 | 수요 확인 후 |
| 원형 보존이 포스터에서도 유지되는가 (카드 실측은 N=1) | 제품 이미지로 실물 확인 | 1단계 종료 시 |
