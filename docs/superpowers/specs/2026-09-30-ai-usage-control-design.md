# AI 사용 통제와 비용 측정 — 설계

- 날짜: 2026-09-30
- 상태: 초안(사용자 승인 전)
- 가지: `feat/ai-usage-control` (`.worktrees/ai-control`)

## 1. 목적과 사용자 결정

회사 키로 부르는 AI(Anthropic·OpenAI·Google·fal·Apify·외부 STT)는 **쓴 만큼 회사가 낸다.** 유료 출시 전에
「누가 쓸 수 있는가」, 「관리자가 멈출 수 있는가」, 「얼마를 썼는지 정확히 보이는가」를 닫는다.

사용자가 정한 것(2026-09-30, 그대로 옮김):

| # | 결정 |
|---|---|
| D1 | 글 AI(LLM) 로 도는 기능은 **크레딧을 차감하지 않는다**(지금 그대로) |
| D2 | 관리자가 **시스템 전체 AI 사용을 멈출 수 있어야** 한다. **자동으로 멈추는 것은 없다** |
| D3 | 비회원은 **크레딧·비용이 드는 모든 것을 쓸 수 없다.** 사용설명서 말고는 접근이 안 되고, 접근하면 **회원가입 안내 모달**을 띄운다 |
| D4 | 가입 무료 크레딧은 **없다**(지금 그대로). 크레딧은 당분간 관리자가 손으로 준다 |
| D5 | 가입했지만 **크레딧이 없는 회원**도 비용이 드는 기능은 **전부 못 쓴다.** 화면 접근은 모두 된다 |
| D6 | **AI 도우미**(고객센터 봇)는 회원만. 크레딧이 없으면 **가입 후 통틀어 10회**까지 |
| D7 | 관리자 화면에서 **AI 전체 사용 비용을 정확히** 측정하고, 거기서 스위치로 결정한다 |
| D8 | **데모 페이지(`/demo`)는 쓰지 않는다 — 삭제**해 혼란을 없앤다 |

판매 채널에 맞춘 기능은 만들지 않는다. 구독은 관리자가 직접 배정한다(기존 기능).

## 2. 지금 사실 (2026-09-30, master `849b9cd0`)

- **회원 확인만 하고 예약 없이 유료 AI 를 부르는 라우트 4곳**: `POST /api/easy/generate` 의 판정 단계
  (`app/api/easy/generate/route.ts:148-162`, 입력 길이 무제한, 회원이 최상위 모델 선택 가능), `POST /api/sns/projects/[id]/plan`
  (웹검색 조사·Apify·STT·기획·원고), `POST /api/sns/projects/[id]/caption`, `POST /api/poster/projects/[id]/review`
- **포스터 기획**은 예약보다 비전 읽기가 먼저이고(`poster/projects/[id]/plan/route.ts:104-109` → `:126`),
  `referenceIds` 개수 상한·중복 제거가 없다
- **0크레딧 작업**(분석·기획·레이아웃·CS 등)은 `credit_reserve` 에서 `v_need=0` 이라 **잔액 0 인 계정도 통과**한다
  (`202609280001_cs_ask_operation.sql:264, :281`). 가입 즉시 active(`202609220005:40,50`)라 가입만 하면 쓸 수 있다
- CS 도우미의 시간당 한도가 **장부 경로에서 빠져 있다** — `credit_reserve` 의 검사 목록은
  `('pdp_analyze','reference_analyze','redesign_transcribe')` 뿐(`202609280001:270`)
- **AI 전체 정지 스위치가 없다.** 지금 급히 멈추려면 서버에서 키를 비우고 재시작해야 한다
- **비용 기록**: 요청 끝에 `generation_events.llm_usd` + `billable_images × model_prices` 로 적고 관리자 비용 화면이
  합산한다(`lib/cost.ts:89-142`, `admin_cost_summary`). **빠지는 비용**: 예약 없는 4곳, 계량기(`withLlmMeter`) 밖 호출은
  조용히 버려진다(`lib/llm/meter.ts:19-21, 40-41`) — 카드뉴스 상태 조회 중의 장면·검수 글 AI, 웹검색 조사, Apify, STT.
  「오늘」은 DB 시각(UTC) 기준(`202609100004_llm_cost.sql:26`)이라 한국 시각과 9시간 어긋난다
- 비회원: AI API 는 모두 로그인 확인을 한다(401). 화면은 공개 목록(`middleware.ts:18-44` — `/`, `/about`, `/guide`,
  `/demo`, 로그인·가입·비밀번호·인증) 밖이면 `/login` 으로 넘긴다

## 3. 설계

### 3.1 한 관문 — 모든 유료 AI 는 예약을 거친다

**모든 유료 AI 호출은 `reserveAiUsage`(→ `credit_reserve`) 를 먼저 통과한다.** 예외 없음.

- 예약 없는 4곳에 예약·정산을 붙인다(0크레딧, 작업 이름 새로: `easy_decide`, `sns_plan`, `sns_caption`, `poster_review`).
  이미지 주문으로 이어지는 쉬운 만들기는 판정 예약과 뒤 단계 예약이 따로다(판정은 판정대로 닫는다)
- 포스터 기획: 비전 읽기를 **예약 뒤로** 옮기고, `referenceIds` 를 중복 제거·**최대 10개**
- 입력 길이 상한: 쉬운 만들기 `prompt` 4,000자, 카드뉴스 원문 `text` 20,000자·`question` 1,000자, 포스터 `instruction` 2,000자
  (넘으면 400 과 「글이 너무 깁니다(최대 N자)」)
- 시간당 한도(계정별, 넉넉히 — 크레딧 가진 회원의 오작동·반복 클릭 방지용): 새 4곳과 레이아웃 분석·포스터 기획 각 60회/시간.
  환경변수로 바꿀 수 있게(기존 `ANALYZE_HOURLY_LIMIT` 방식). CS 는 60회/시간을 **SQL 검사 목록에 넣어** 실제로 걸리게 한다

### 3.2 크레딧이 없으면 막는다 (D5·D6)

`credit_reserve` 안(전역 잠금 아래, 인자·이름 그대로 — 42725 사고 방지)에 규칙 하나를 더한다:

- **사용 가능 크레딧이 0 이하이면 0크레딧 작업도 거절** — 사유 `credits_required`
- 단 `cs_ask` 는 예외: 그 회원의 `cs_ask` 기록이 **가입 후 통틀어 10건 미만**이면 허용. 셀 때는 성공했거나 진행 중인 것만
  (제공사 오류로 실패한 것은 세지 않는다). 크레딧이 1 이상이면 이 10회와 무관하게 시간당 한도만 본다
- 관리자(무제한 지급)는 잔액이 있으므로 그대로 통과
- 앱 문구: `credits_required` → 「크레딧이 없어 이 기능을 쓸 수 없습니다. 운영자에게 문의해 주세요(ai.dev@fixupworld.com).」,
  CS 10회를 다 쓰면 「무료 질문 10회를 모두 썼습니다. 크레딧을 받은 뒤 다시 이용해 주세요.」 — 화면은 서버 문구를 그대로 보인다
  (각 제품 화면이 오류 문구를 보이는지 계획에서 확인)

### 3.3 관리자 「AI 전체 멈춤」 스위치 (D2)

- 저장: 기존 `app_settings` 표, 키 `ai_paused`(`'1'`/`'0'`). 관리자 화면(시스템 설정)에 스위치 하나, 바꾼 사람·시각을
  `credit_admin_events` 처럼 감사 기록
- **두 겹으로 막는다**
  1. `credit_reserve` 첫머리: `ai_paused='1'` 이면 사유 `ai_paused` 로 거절 — 새 요청은 모두 여기서 멈춘다
  2. **공급자 호출 직전 한 곳**(§3.4 의 기록 도우미): 스위치를 몇 초 캐시해 확인하고, 켜져 있으면 호출하지 않고 `AiPausedError`.
     이미 예약을 잡고 여러 단계로 도는 작업(카드뉴스 상태 조회가 다음 장면을 제출하는 것 등)도 **다음 호출에서 멈춘다.**
     각 흐름은 이것을 제공사 실패처럼 다룬다 — 완성된 것만 정산하고 나머지는 차감하지 않는다(기존 실패 처리)
- 관리자 계정도 예외 없이 멈춘다(「시스템 전체」). 이미 fal 에 제출돼 도는 그림은 끝까지 돌 수 있다 — 화면에 그렇게 적는다
- 문구: 「운영자가 AI 사용을 잠시 멈췄습니다. 잠시 후 다시 시도해 주세요.」, 상태 코드 503
- 자동 멈춤은 만들지 않는다(D2)

### 3.4 비용을 정확히 — 호출마다 한 줄 (D7)

**공급자를 부를 때마다 비용 한 줄을 남긴다.** 요청 끝에 모아 적는 지금 방식은 계량기 밖 호출과 여러 단계 작업을 놓친다.

- 새 표 `ai_cost_events`(서비스 권한만): 시각, 회원, 요청 id(있으면), 작업 이름, 공급자, 모델, 입력·출력 토큰, 그림 수,
  **USD 금액**, 금액 근거(`tokens`/`image_unit`/`provider_reported`/`estimate`), 실패 여부
- 공급자 호출을 모두 **작은 기록 도우미 하나**로 감싼다: 스위치 확인(§3.3) → 호출 → 사용량에서 금액 계산 → 한 줄 쓰기.
  쓰기 실패는 호출을 막지 않는다(경고 로그). 대상: `lib/llm/structured.ts`, `lib/easy/chat-provider.ts`, `lib/cs/provider.ts`,
  `lib/poster/providers.ts`, `lib/sns/providers.ts`, `lib/pdp/providers.ts`·`lib/pdp/fal.ts`, `lib/layout/analyze-provider.ts`,
  `lib/redesign/image-generator.ts`, `lib/ad/background.ts`, `packages/redesign-core`(generate·edit-section·transcribe·rag),
  `packages/ingest-core`(웹검색 조사·Apify·STT). 패키지 쪽은 호출자가 넘기는 콜백으로 기록한다(패키지는 DB 를 모른다)
- 금액 계산: 글 AI 는 기존 단가표(`packages/shared/src/llm-price.ts`) × 토큰, 그림은 기존 `model_prices` × 장 수,
  Apify 는 응답의 사용 금액(없으면 실행 1회 추정), 웹검색은 도구 호출 단가 + 토큰, STT 는 단가를 운영 설정에 두고
  모르면 `estimate` 로 적는다
- 관리자 비용 화면: 이 표를 **한국 시각** 기준으로 합산 — 오늘·이번 달·최근 30일 일별, **공급자별·작업별·회원별** 나눔,
  「금액 근거가 추정인 비율」 표시. 화면 위에 §3.3 스위치를 같이 둔다(보고 바로 결정)
- 기존 `generation_events` 원가 칸(크레딧 정산·낭비 분석)은 그대로 둔다. 화면의 「총 비용」은 새 표가 기준이다
- 정확도의 한계를 화면에 적는다: **공급자 청구서와 1원 단위로 같지는 않다**(단가표가 맞아야 맞는다). 청구서 대조는 이번 범위 밖

### 3.5 비회원 (D3·D8)

- 공개 화면: `/`(첫 화면), `/about`, `/guide/**`, `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/auth/*`. **`/demo` 삭제**
  (페이지·공개 목록·첫 화면·머리 메뉴 링크·그 화면만 쓰던 이미지 `public/demo-sections/**`·관련 시험)
- 비회원이 그 밖의 화면을 열면 `/login` 대신 **첫 화면으로 보내고 회원가입 안내 모달**을 연다(`/?signup=required&next=…`).
  모달: 「회원가입이 필요합니다」 + [회원가입] [로그인] [닫기]. 로그인 뒤에는 `next` 로 돌아간다(기존 안전한 next 처리 재사용)
- API 는 지금처럼 401. 모달 컴포넌트는 `@fixup/ui` 의 Dialog 를 쓴다

## 4. 하지 않는 것

- 자동 멈춤, 하루 지출 상한(D2)
- 글 AI 에 크레딧 차감(D1), 가입 무료 크레딧(D4)
- 계정별 하루 횟수(CS 10회 말고는 없다) — 크레딧을 가진 회원만 쓰므로 시간당 한도로 충분
- 공급자 청구서 자동 대조, 결제(페이먼트) 연동

## 5. 시험으로 고정할 것

- SQL: `ai_paused` 면 모든 작업 거절 · 잔액 0 이면 0크레딧 작업 거절 · `cs_ask` 는 잔액 0 에서 10건까지 허용·11번째 거절·
  제공사 실패는 세지 않음 · 잔액 1 이상이면 `cs_ask` 10회 무관 · `cs_ask` 시간당 60 · 기존 거절 사유·인자 불변(함수 유일성 시험)
- 라우트: 예약 없이 공급자를 부르는 라우트가 없다는 **정적 시험**(공급자 모듈을 부르는 `app/api/**/route.ts` 는
  `reserveAiUsage` 도 불러야 한다) · 입력 길이 초과 400 · 포스터 참고 이미지 중복 제거·10개
- 기록 도우미: 호출마다 한 줄 · 쓰기 실패가 호출을 막지 않음 · 스위치가 켜지면 호출하지 않음 · 공급자 모듈이 도우미 밖에서
  SDK 를 부르지 않는다는 정적 시험
- 비용 화면: 한국 시각 경계(한국 0시 ~ 9시 사이 호출이 「오늘」로 잡힘)
- 비회원: 공개 목록 밖 화면 → 첫 화면 + 모달, `/demo` 404, 공개 화면은 그대로
- 문구: 새 사유 두 개가 사용자 문구로 보인다

## 6. 단계 (각 단계는 따로 계획·독립 리뷰·배포)

| 단계 | 내용 | 운영 반영 |
|---|---|---|
| C1 | SQL: `ai_paused`·`credits_required`·CS 10회·CS 시간당 — `credit_reserve` 교체(같은 인자) | 마이그레이션 먼저(칸·표 추가 없음, 함수 본문만) → 앱 |
| C2 | 라우트: 예약 없는 4곳 + 포스터 기획 순서·참고 이미지 상한 + 입력 길이 + 시간당 한도 + 문구 | 앱 |
| C3 | 비용 기록: `ai_cost_events` + 기록 도우미 + 모든 공급자 감싸기 + 스위치 두 번째 겹 | 마이그레이션(새 표) → 앱 |
| C4 | 관리자: 비용 화면(한국 시각·나눔) + AI 전체 멈춤 스위치 | 앱 |
| C5 | 비회원 모달 + `/demo` 삭제 | 앱 |

순서 이유: C1 이 가장 싸고 가장 크게 막는다(가입만 한 계정의 무료 AI 가 여기서 끝난다). C3 은 가장 넓게 손대므로 C1·C2 뒤.

## 7. 위험

| 위험 | 대응 |
|---|---|
| `credit_reserve` 교체가 기존 동작을 깬다 | 같은 인자·이름, 기존 DB 시험 전체 + 새 시험, 운영 적용 전 시험 서버 DB 에 먼저 |
| 크레딧 0 회원이 늘 쓰던 무료 기능이 갑자기 막혀 문의가 는다 | 문구에 연락처, 사용설명서·약관 문구 확인(「크레딧」 안내 절) |
| 기록 도우미 쓰기가 느려 생성이 느려진다 | 쓰기는 응답을 기다리지 않게(실패는 경고). 호출당 DB 쓰기 1회 |
| 스위치가 몇 초 늦게 먹는다 | 캐시 5초 이내. 새 요청은 SQL 에서 즉시 막힌다 |
| 공급자 모듈이 새로 생겨 도우미를 안 거친다 | 정적 시험(§5)으로 막는다 |
