# 채팅 스튜디오 설계

/ 2026-09-02

대화로 무엇을 만들지 정하고, 그 자리에서 결과물까지 받는 화면을 만든다.
`/studio` 로 새로 만들고 기존 단계 화면(`/sns/new`, `/poster/new`)은 남긴다.

---

## 1. 왜 만드나

지금은 다섯 단계를 오가며 칸을 채운다. 사용자는 무엇을 적어야 할지 모르고,
안 적은 것은 시스템이 조용히 추측한다. 그 추측이 어긋난 것은 04 원고나 05
결과에 가서야 드러난다.

특히 **첨부한 그림의 역할**이 그렇다. 라이브러리에서 그림을 고르면 말없이
「따라 만들기」가 된다(`attachment-picker.tsx:81`). 제품 사진을 넣어도
그렇다 — 지켜져야 할 제품이 다시 그려진다. 사용자가 원한 것과 정반대다.

**물어보면 이 실패가 사라진다.** 이 설계의 값어치는 대부분 여기서 나온다.
모델이 똑똑해져서가 아니라, 빈칸으로 넘어가는 길이 막혀서다.

---

## 2. 범위

**넣는다**

- 카드뉴스 · 포스터(광고 소재)
- 대화 · 작업판 · 결과 3분할 화면
- 대화 모델은 Claude (실패하면 OpenAI 로 넘어감 — 기존 `structured.ts`)
- 생성 결과물 전부 라이브러리 자동 저장

**안 넣는다**

- 상세페이지 · 리디자인 · 캐릭터 — 대화가 쓸 만한지 확인한 뒤에 얹는다
- 대화 서버 저장 — 브라우저에만 둔다. 이어서 하기가 필요해지면 그때 옮긴다
- 「이 역할에는 이 모델」 표 — 실측이 없다. 지금 만들면 근거 없는 규칙이 굳는다

---

## 3. 화면

```
┌──────┬─────────────────┬──────────────┬──────────┐
│ 메뉴 │ 대화             │ 작업판        │ 결과      │
│ 150  │ flex            │ 330          │ 250      │
└──────┴─────────────────┴──────────────┴──────────┘
```

**스텝바는 없다.** 스텝바가 하던 두 가지 — 「어디인지」와 「되돌아가기」 —
를 작업판이 대신한다. 작업판은 마법사가 아니라 **현재 상태를 비추는 거울**이고,
칸마다 고칠 수 있다.

> 지킬 것: 작업판에서 못 고치는 항목이 하나라도 남으면 스텝바를 지울 수 없다.
> 되돌아갈 길이 사라진다.

**좁은 화면**에서는 결과 칸을 접는다. 1440에서 4분할이면 각 320px 안팎이고,
거기에 6장을 넣으면 무엇이 나왔는지 알아볼 수 없다. 자세히 보는 것은 이미
있는 원본 크기 뷰어(`_components/image-viewer.tsx`)가 받는다.

**돈 쓰는 버튼은 작업판 맨 아래 고정.** 대화 메시지는 스크롤되어 사라진다.
대화가 "만들까요?"라고 물어도 실제로 누르는 곳은 늘 한 자리여야 한다.

그 자리에 오는 버튼은 **때에 따라 둘 중 하나**다. 기존 흐름이 두 단계이기
때문이다.

| 단계 | 무엇이 나오나 | 값 |
|---|---|---|
| ① 원고 만들기 | 기획과 카드별 원고 | LLM 호출. 몇 센트 |
| ② 이미지 만들기 | 실제 그림 | fal 호출. **여기가 비싸다** |

①은 가볍게 눌러도 된다. **확인이 필요한 것은 ②뿐이다.** 그래서 ②에만 장수와
값을 붙인다 — `6장 만들기 · $0.48`. ①은 그냥 「원고 만들기」다.

①과 ② 사이에 사용자가 원고를 고친다. 그 편집은 작업판에서 칸으로 한다.

---

## 4. 대화 — 틀과 대본의 차이

LLM 을 얹는 이유는 **모델의 지능을 쓰기 위해서**다. 그런데 규칙을 많이 걸면
서식 채우는 기계가 된다. 그래서 코드가 잡는 것을 두 가지로 못 박는다.

| 코드가 잡는다 | 왜 |
|---|---|
| 없으면 서버가 거부하는 것 | 포스터 레퍼런스 최소 1장, 장수, 모델 제약 |
| 재어 보니 LLM 이 빠뜨리는 것 | 색 쓰임새 · 복사 금지 문장 (2026-07-30 실측) |

나머지는 전부 모델 몫이다 — **순서, 말투, 무엇을 먼저 물을지, 무엇을 제안할지,
프롬프트를 어떻게 쓸지.**

두 번째 항목에 근거가 있다. 실측에서 `colour palette` 라고만 하면 모델이
**0/2** 로 색을 면에 안 썼고, 서술을 곁들이니 **2/2** 였다
(`pdp-core/src/pdp.reference-policy.ts`). 지능 문제가 아니라 지시가 없으면
안 하는 종류다.

### 안내자가 아는 것

범용 상담원이 아니라 **우리 스튜디오를 아는 사람**이어야 한다. 무엇이
가능한지 알아야 사용자가 막연할 때 먼저 제안할 수 있다.

- 카드뉴스와 포스터의 차이, 보통 몇 장인지
- 그림의 세 역할 — 따라 만들기 / 제품 지키기 / 인물 지키기
- 따라 만들기는 아이콘을 안 가져오고 내용에 맞게 새로 그린다는 것
- 라이브러리와 만든 결과물을 다시 쓸 수 있다는 것
- 유튜브·기사 주소에서 자막·본문을 가져온다는 것
- 인물 사진이 없으면 캐릭터를 만들어 쓴다는 것(`/characters`)

### 첫 인사

도구를 먼저 고르게 하지 않는다. 사용자는 「카드뉴스인가 포스터인가」가 아니라
**「이걸 알리고 싶다」**를 들고 온다. 어울리는 쪽은 안내자가 제안한다.

### 자유 메모

정해진 칸에 안 들어가는 말 — "톤은 유머러스하게", "마지막 장에 QR",
"경쟁사 이름은 빼고" — 은 `notes` 에 쌓는다. 담을 곳이 없으면 그 말은
사라지고, 사용자는 말했는데 반영이 안 됐다고 느낀다. **덮어쓰지 않고 쌓는다.**

## 5. 언제 만들 수 있는가 — 이미 있음

`lib/studio/intake.ts` 가 판단한다. LLM 에게 맡기면 절반만 듣고 "이제 만들
수 있습니다"라고 한다.

| 필요한 것 | 카드뉴스 | 포스터 |
|---|---|---|
| 무엇을 만들지 | ✓ | ✓ |
| 주제 | ✓ | ✓ |
| 내용(글·유튜브·주소) | ✓ | ✓ |
| 장수 | ✓ | — |
| 첨부할지 답했나 | ✓ | ✓ |
| 붙인 그림마다 역할 | ✓ | ✓ |
| 따라 만들 그림 1장 이상 | — | ✓ |

모자란 칸에는 **이름과 왜 필요한지**만 달아 넘긴다. 순서도 말투도 모델이 정한다.

---

## 6. 그림을 붙이면

**반드시 무엇으로 쓸지 묻는다.** 이 설계의 핵심이다.

```
사용자가 대화창에 그림을 끌어다 놓는다
  → 곧바로 라이브러리에 올라간다 (POST /api/reference-images)
  → 안내자가 그림을 보고 짐작해 먼저 제안한다
    "제품 사진 같은데, 이 제품을 그대로 지킬까요?"
  → 사용자가 답하거나, 작업판에서 버튼을 누른다
  → 역할이 정해지기 전에는 만들기가 열리지 않는다
```

**끌어다 놓은 그림은 그 자리에서 라이브러리로 들어간다.** 임시로 들고 있다가
나중에 올리지 않는다. 세 가지 이유가 있다.

- 기존 파이프라인이 `id` 와 `assetPath` 로 그림을 받는다. 올려야 그게 생긴다
- 대화가 사라져도 그림은 남는다 (대화는 브라우저에만 둔다)
- "생성·등록하는 모든 것이 라이브러리에" 라는 규칙과 어긋나지 않는다

역할 어휘는 세 도구가 공유한다(`@fixup/shared` 의 `AttachmentRole`).
라이브러리에서 불러온 그림이 도구를 옮겨도 역할을 잃지 않는다.

---

## 7. 프롬프트와 모델

### 프롬프트 — 새로 만들지 않는다

**이미 LLM 이 쓰고 있다.** `sns-core/image-prompt.ts` 의 `writeImagePrompt`
가 장면 본문을 LLM 으로 쓰고, `composePrompt` 가 뼈대를 씌운다
(2026-09-01 커밋 b63f434 — "LLM 이 쓰고 코드가 뼈대를 씌우는 이미지 프롬프트").
포스터도 `poster-core/prompt.ts` 가 같은 모양이다.

> 처음 설계에는 `compose.ts` 를 새로 만든다고 적었다. **뺀다.** 같은 일을
> 하는 기계가 둘이 되고, 오늘 고친 실측 문구(색 쓰임새·복사 금지)를 양쪽에
> 유지해야 한다. 하나가 곧 낡는다.

대화에서 모은 것이 그 기계에 닿게만 하면 된다.

| 대화에서 모은 것 | 어디로 |
|---|---|
| 주제 | `title` |
| 내용(글·유튜브·주소) | `source` |
| 메모(톤·금지·특별 요청) | `toneNote` — 스키마에 이미 있다 |
| 첨부와 역할 | `attachments` |
| 장수·비율·모델 | `spec` |

`notes` 가 `toneNote` 로 가면 "톤은 유머러스하게", "경쟁사 이름은 빼고" 가
원고와 이미지 프롬프트에 그대로 실린다.

### 모델 선정 — 이미 있음

`lib/studio/model-choice.ts` 가 **못 쓰는 것만 걸러낸다.**

```
참고 그림 상한   16 / 14 / 14 / 7장
지원 비율        4:1·8:1 은 nano-banana-2 만
한 번에 만들 장수  nano-banana 는 1장씩
픽셀 직접 지정    A4 인쇄용은 GPT Image 2 만
```

남은 것에 값과 성질을 붙여 넘기면 **LLM 이 고른다.** 왜 뺐는지도 남긴다 —
사용자가 "그 모델은 왜 안 되나요"라고 물으면 답해야 한다.

**고르는 시점은 프로젝트를 만들 때 한 번이다.** 장마다 다시 고르지 않는다 —
같은 작업의 카드가 서로 다른 모델로 나오면 결이 어긋난다. 사용자는 작업판에서
언제든 바꿀 수 있다.

## 8. 만들 것 — 파일 단위

| 파일 | 하는 일 | 상태 |
|---|---|---|
| `lib/studio/intake.ts` | 언제 만들 수 있는가 | **있음** |
| `lib/studio/turn.ts` | 한 턴 · 안내자 지시 | **있음** |
| `lib/studio/model-choice.ts` | 쓸 수 있는 모델 | **있음** |
| `lib/studio/session.ts` | 브라우저 저장(sessionStorage) | 만든다 |
| `app/api/studio/chat/route.ts` | 한 턴 API | 만든다 |
| `app/studio/page.tsx` | 3분할 화면 | 만든다 |
| `app/studio/_components/*` | 대화 · 작업판 · 결과 | 만든다 |
| `lib/studio/launch.ts` | intake → sns/poster 프로젝트 | 만든다 |

### 생성 연결

대화에서 모인 것을 기존 파이프라인으로 넘긴다. **새 생성 경로를 만들지 않는다.**

```
intake(tool: "sns")     → POST /api/sns/projects   → 기존 카드뉴스 흐름
intake(tool: "poster")  → POST /api/poster/projects → 기존 포스터 흐름
```

사용자는 어느 쪽으로 갔는지 모른다. 결과는 결과 칸에 그대로 뜬다.

### 결과물 자동 저장

만들어진 이미지는 **전부** 참고 이미지 창고로 들어간다. 지금은 「참고 이미지로
보관」을 눌러야 들어간다(`_components/save-to-library.tsx`). 자동으로 바꾼다.

**서버에서 건다.** 그림이 저장되는 자리 바로 뒤다.

```
lib/sns/queued-flow.ts:155, :250   card.assetPath = saved.assetPath  ← 이 뒤
```

브라우저에서 걸면 창을 닫거나 새로고침한 사이에 끝난 장이 빠진다. 서버에서
걸면 빠질 일이 없다.

- 카드뉴스 6장이면 6장 전부
- 제목은 작업 단위로 묶어 붙인다 — `수분 세럼 카드뉴스 · 3` 처럼
- 실패해도 결과는 살린다. 보관은 곁다리다 (캐릭터에서 쓰는 방식과 같다)

## 9. 위험과 대비

**대화가 길어지면 비용과 지연이 는다.**
되묻기 한 번마다 LLM 호출이 늘고 사용자는 더 기다린다. 그래서 되묻기는
**비어 있는 칸에 대해서만** 하고, 한 번에 다 적은 사용자는 곧장 만들기로 보낸다.

**LLM 이 역할을 잘못 읽을 수 있다.**
그래서 작업판의 버튼을 남긴다. LLM 이 제안하고, 화면에서 눈으로 확인하고,
틀렸으면 한 번 눌러 고친다. 대화만으로는 확정하지 않는다.

**모델이 이상한 값을 준다.**
장수에 "여섯"이 오거나 도구에 "영상"이 오면 대화가 통째로 어그러진다.
아는 모양만 받고 나머지는 흘려보낸 뒤 다음 턴에 다시 묻는다. 빈 값으로 이미
아는 것을 지우지도 않는다. (`turn.ts` 의 `sanitize`, 테스트로 잠가 둠)

**새로고침하면 대화가 사라진다.**
의도한 것이다. 다만 **만들기를 누른 뒤**에는 프로젝트가 서버에 생기므로
결과는 남는다. 사라지는 것은 대화뿐이다.

**작업판이 불완전한 채로 스텝바를 지우면 되돌아갈 길이 없다.**
작업판에서 모든 항목을 고칠 수 있는지 확인한 뒤에 지운다. 확인 전에는
기존 화면(`/sns/new`)이 남아 있으므로 물러날 곳이 있다.
