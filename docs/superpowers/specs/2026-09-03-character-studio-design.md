# 캐릭터 만들기 개편 설계

작성 2026-09-03 · 상태: 확정, 구현 진행

---

## 지금 무엇이 문제인가

코드와 운영 DB 를 다 확인한 결과다.

| 문제 | 근거 |
|------|------|
| **사람 전용이다** | 프롬프트가 `anatomically correct body proportions`, `both eyes visible`, `rear hairstyle`, `visible fine pores` 를 강제한다. 고양이를 넣으면 사람 해부학을 요구받는다 |
| **컨셉·테마를 못 고른다** | 옵션이 `photoreal` 체크박스 하나뿐 |
| **첨부할 자리가 없다** | `generateCandidates` 가 `references: []` 를 넘긴다. 화면에도 입구가 없다 |
| **다시 만들기가 없다** | 후보가 다 별로면 처음부터. 각도 한 장만 다시도 안 된다 |
| **고를 수가 없다** | 캐릭터 카드에 삭제와 크게 보기뿐. 「이 캐릭터 쓰기」가 없다 |
| **라이브러리에 안 보인다** | `library_items` 에 넣는데 MCS 라이브러리 화면은 그 표를 안 읽는다 |
| **참고 이미지 저장이 안 돌아 봤다** | 운영의 유일한 캐릭터는 2026-07-28 것이고 `reference_images` 에 0장 |
| **로컬 모드에서 안 된다** | `characters.ts` 가 `createSupabaseAdminClient()` 를 바로 부른다. 분기가 없다 |

운영 DB 사실: 캐릭터 1개, 각도 3장(우측 없음), 좌측 파일 이름이 `three_quarter.png`
— 6각도 시절 이름이다. **지금 코드로 만든 캐릭터는 하나도 없다.**

## 확정된 결정

| 질문 | 결정 |
|------|------|
| 대상 고르기 | **종류 + 결을 따로 고른다.** 조합이 자유롭다 |
| 다른 도구에서 부르기 | **라이브러리 불러오기 창에 「캐릭터」 칸**을 둔다 |
| 다시 만들기 | **후보 다시 + 각도 한 장씩 다시** |

## 종류와 결

```ts
export type CharacterKind = "person" | "animal" | "character" | "object";
export type CharacterLook = "photoreal" | "anime" | "3d" | "illustration";
```

**종류가 몸을 정하고, 결이 질감을 정한다.** 둘을 나눈 이유는 「애니풍 사람」과
「실사 동물」이 둘 다 자연스러운 요구이기 때문이다. 하나로 묶으면 목록에 없는
조합은 못 만든다.

### 종류가 바꾸는 것

| | 구도 | 각도 지시의 기준 | 피부 지시 |
|---|---|---|---|
| person | 머리부터 발끝 | 얼굴·두 눈·뒷머리 | 결이 실사일 때만 |
| animal | 몸 전체, 꼬리·발 포함 | 얼굴·주둥이·털 무늬 | 없음 (털 지시로 대체) |
| character | 머리부터 발끝, **등신 비율을 강제하지 않는다** | 얼굴·두 눈·머리 모양 | 없음 |
| object | 물건 전체 | 앞면·옆면·뒷면의 생김새 | 없음 |

`character` 에서 사람 등신을 강제하지 않는 것이 중요하다. 2등신 캐릭터에
`anatomically correct human proportions` 를 요구하면 캐릭터가 사람이 된다.

`object` 는 얼굴 지시를 전부 뺀다. 뒷모습 지시의 「뒤통수에 얼굴을 그리지
말라」는 물건에는 뜻이 없다.

### 결이 바꾸는 것

| | 질감 지시 | 기본 모델 |
|---|---|---|
| photoreal | 모공·솜털·자연광 (person 일 때만) | nano-banana-pro |
| anime | 셀 셰이딩, 굵은 윤곽선, 평평한 색면 | gpt-image-2 |
| 3d | 부드러운 3D 렌더, 물리 기반 재질 | gpt-image-2 |
| illustration | 손그림 질감, 붓·펜 자국 | gpt-image-2 |

**모델은 기본값일 뿐 바꿀 수 있다.** 이미지 만들기에는 모델 선택이 있는데
캐릭터만 없어서 화면마다 다르게 보였다. 같은 목록(`IMAGE_MODELS`)을 쓴다.

## 첨부 이미지

두 가지 쓸모가 있고, **둘은 정반대다.** 나누지 않으면 모델이 절충한다.

```ts
export type CharacterReferenceRole =
  | "style"     // 이 그림의 결을 따라 새 캐릭터를 만든다. 그 캐릭터를 베끼지 않는다
  | "extract";  // 이 그림 속 캐릭터를 그대로 뽑아낸다. 배경과 다른 것은 버린다
```

「이미지 만들기」의 역할 드롭다운과 같은 모양을 쓴다. 화면 어휘도 같게 한다.

- **결만 따라 만들기** — 화풍·색·질감만 가져오고 캐릭터는 새로 만든다
- **이 캐릭터 뽑아내기** — 그림 속 그 캐릭터를 그대로 살려 각도를 만든다

fal 로는 이렇게 간다.

```
style   → ReferenceImage { kind: "style" }
extract → ReferenceImage { kind: "person" }   (정체성 유지 경로)
```

`extract` 가 있으면 **후보 단계를 건너뛸 수도 있다.** 뽑아낼 캐릭터가 이미
정해져 있으니 후보를 두 장 보여 줄 이유가 없다. 다만 배경 제거와 정면화가
필요하므로 한 장은 만든다 — 그것을 정면으로 쓴다.

첨부는 두 경로로 들어온다. 파일 올리기와 라이브러리 불러오기 — 「이미지
만들기」와 같다. 올린 그림은 라이브러리에도 들어간다.

## 다시 만들기

### 후보

「다른 후보 보기」를 누르면 같은 조건으로 2장을 더 만든다. **앞의 후보를
지우지 않는다** — 먼저 것이 나았던 일이 생긴다. 목록에 이어 붙인다.

### 각도 한 장

만든 캐릭터의 각도마다 「다시 만들기」를 둔다. 그 각도만 다시 만들어 갈아
끼운다. **정면을 참조로 넣는다** — 참조 없이 만들면 다른 사람이 된다.

없는 각도(지금 운영의 그 캐릭터는 우측이 없다)는 빈 칸으로 보이고 같은
버튼으로 채운다.

```
POST /api/characters/views
  { characterId, angle }
→ 그 각도만 새로 만들어 storage 와 character_views 를 덮어쓴다
→ reference_images 의 그 각도 줄도 갈아 끼운다
```

## 라이브러리

### 「캐릭터」 칸

라이브러리 불러오기 창은 지금 낱장과 묶음 세트를 보여 준다. 여기에 캐릭터
칸을 더한다. **캐릭터 하나를 고르면 각도 4장이 통째로 들어오고 역할이
「인물 그대로 지키기」로 정해진다.**

낱장으로 섞어 두면 장이 늘수록 못 찾는다. 지금도 캐릭터 하나가 4장이다.

### 어디에 저장하나

바꾸지 않는다. 지금 코드가 옳다.

- `characters` / `character_views` — 원본
- `reference_images` — 각도 4장, 제목은 「이름 (캐릭터) · 정면」

`library_items` 저장은 **뺀다.** MCS 라이브러리 화면이 그 표를 안 읽어서
아무도 못 본다. 안 보이는 곳에 쓰는 것은 쓰지 않는 것보다 나쁘다 — 저장된
줄 알게 된다.

캐릭터를 지우면 `reference_images` 의 그 4장도 같이 지운다. 지금은 안 지워서
캐릭터를 지워도 라이브러리에 남는다.

## 로컬 모드

`characters.ts` 에 `isLocalStoreEnabled()` 분기를 넣는다. 다른 기능은 다
로컬·운영이 같게 도는데 캐릭터만 다르다.

```
로컬: data/local/.../characters/{characterId}/{angle}.png + store.json
운영: characters 버킷 + Supabase 표
```

읽는 쪽(`listCharacters`, `loadCharacterView`)도 같이 갈라야 한다.

## 실패했을 때

| 무엇이 | 어떻게 |
|--------|--------|
| 각도 하나가 실패 | 그 각도를 빈 칸으로 두고 캐릭터는 저장한다. 나중에 채운다 |
| 참고 이미지 저장 실패 | 캐릭터는 살린다. 화면에 알린다 (지금은 조용히 넘어간다) |
| 후보가 0장 | 크레딧을 차감하지 않고 알린다 (지금도 그렇다) |
| `extract` 인데 그림에 캐릭터가 없음 | 모델이 만든 것을 그대로 쓴다. 막을 방법이 없다 |

원칙 — **캐릭터는 저장된다.** 각도 하나 때문에 처음부터 다시 하게 하지 않는다.

## 테스트

프롬프트 조립은 전부 순수 함수다. 여기에 붙인다.

| 무엇 | 어디 |
|------|------|
| 종류마다 다른 구도·각도 지시가 나온다 | `pdp.character.test.ts` |
| `object` 에는 얼굴 지시가 없다 | 〃 |
| `character` 에는 사람 등신 강제가 없다 | 〃 |
| 결마다 다른 질감 지시가 나온다 | 〃 |
| 피부 지시는 person + photoreal 일 때만 | 〃 |
| 결 → 기본 모델 | 〃 |
| `style` 과 `extract` 가 다른 문장을 만든다 | 〃 |
| 옛 호출(`photoreal: boolean`)이 그대로 동작한다 | 〃 |

**옛 호출 유지가 중요하다.** 상세페이지(`/create`)가 같은 함수를 쓴다. 종류·결을
안 주면 `person` + (photoreal ? photoreal : illustration) 로 떨어진다.

## 작업 순서

1. `pdp-core/pdp.character.ts` — 종류·결·역할. 순수, 테스트 먼저
2. `apps/web/lib/characters.ts` — 첨부 받기, 각도 하나 다시 만들기, 로컬 모드
3. `apps/web/app/api/characters/` — 각도 다시 만들기 경로 추가
4. `CharacterStudio.tsx` — 종류·결·모델·첨부·다시 만들기
5. 라이브러리 불러오기 창에 「캐릭터」 칸
6. `library_items` 저장 제거, 캐릭터 삭제 시 참고 이미지도 삭제

1~3 이 끝나면 4 없이도 API 로 검증할 수 있다. 5 는 다른 도구를 건드리므로
마지막에 한다 — 레이아웃 작업과 겹치는 파일이 거기 있다.
