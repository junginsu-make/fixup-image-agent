# 라이브러리에서 작업의 단계별 과정으로 들어가기

작성 2026-09-16 · 사용자 승인분

## 무엇을 만드는가

라이브러리 「작업물」에서 완성된 작업을 눌러 **그 작업의 단계별 화면**으로 갈 수
있게 한다. 관리자(`9843ohs@gmail.com`)는 **남이 만든 작업도** 그렇게 볼 수 있고,
원하면 **자기 작업으로 복사해** 다시 만들 수 있다.

## 지금 상태 — 기능이 없어진 것이 아니라 가려져 있다

`apps/web/app/library/works-tab.tsx:423`

```tsx
onClick={() => (work.images.length ? openWork(work) : router.push(work.href))}
```

**그림이 있으면 뷰어를, 없으면 단계별 화면을 연다.** 완성된 작업은 그림이 있으니
언제나 뷰어가 열린다 — 넘어가는 길은 살아 있는데 뷰어에 가려져 있었다.

주소는 이미 만들어져 있다: `:135` 이 `/sns/{id}`, `:166` 이 `/poster/{id}`.
라이브러리 작업물 탭이 다루는 도구는 **이 둘뿐**이다(`TOOL_LABEL`).

## 관리자는 그것만으로 안 된다 — 지나는 문이 다르다

| | 지나는 문 | 결과 |
|---|---|---|
| 라이브러리 목록 | `/api/admin/works` → `listAllWorks()` 가 **서비스 키**(`createSupabaseAdminClient`)로 RLS 우회 | 전부 보인다 |
| 단계별 화면 | `/api/sns/projects/{id}/plan` → `snsFlowStoreForUser(userId).get(id)` → `getProject` 가 **세션 클라이언트**로 읽어 RLS 적용 | 남의 것은 404 |

읽기 정책은 `supabase/migrations/202609070003_team_rls.sql:68`

```sql
create policy "team reads sns projects"
  on public.sns_projects for select to authenticated
  using (public.same_team(team_id, user_id));
```

`same_team`(`:43`)에 **관리자 예외가 없다.** 내 것이거나 같은 팀일 때만 읽힌다.
포스터도 같다(`:72`).

## 확정된 결정 (2026-09-16, 사용자)

| 물음 | 답 |
|---|---|
| 관리자가 남의 작업에서 어디까지 | **보기 + 다시 만들기** |
| 그때 크레딧은 누가 | **관리자 자기 크레딧** |
| 결과물은 어디에 | **관리자 자기 것으로 복사** |

세 번째 답이 설계를 결정한다. **복사**이므로 남의 작업을 고칠 필요가 없고,
따라서 **쓰기 권한을 넓히지 않는다.**

이것이 중요한 이유는 그 방어선이 사고를 겪고 세워진 것이기 때문이다
(`apps/web/lib/sns-flow-store.ts:113` 주석) —

> 팀원의 카드뉴스에서 생성을 돌리면 크레딧이 예약·차감되고 fal 에 실제 요청이
> 나간 뒤, 결과만 어디에도 안 남았다.

그래서 쓰기는 지금처럼 `.eq("user_id", userId)` 로 소유자만(`:123`),
`SnsProjectNotWritable` 도 그대로 둔다.

## 단계

위험이 작은 것부터. 각 단계는 **혼자서도 뜻이 있고**, 앞 단계 없이는 못 나간다.

### 1단계 — 라이브러리에서 과정으로 가는 길

**하는 일.** 작업물 카드에 「과정 보기」 단추를 붙인다.

- 카드 본문 클릭은 **지금 그대로** — 그림 뷰어가 열린다. 쓰던 동작을 뺏지 않는다
- 단추는 `work.href` 로 이동한다. 주소는 이미 있다
- 남의 작업(`work.mine === false`)에는 2단계 전까지 **단추를 내지 않는다.**
  내면 눌러서 404 를 보게 된다

**닿는 파일.** `apps/web/app/library/works-tab.tsx`

**이것만으로 사용자가 처음 물은 것이 풀린다.**

### 2단계 — 관리자가 남의 작업을 본다 (읽기만)

**하는 일.**

1. 관리자 전용 **단건 읽기**를 더한다. 목록이 이미 쓰는 방식과 같은 방식
   (`createSupabaseAdminClient`), 같은 파일에 둔다 —
   `apps/web/app/api/admin/works/store.ts` 에 `listAllWorks`·`deleteAnyWork` 옆
   `readAnyWork(kind, id)`
2. 관문은 `hasFullScope(viewerFrom(auth.member), ...)`
   (`apps/web/lib/access/core.ts:98`). **관리자가 아니면 404** —
   403 은 「그 작업이 있긴 하다」를 흘린다
3. 상세 화면이 **「남의 작업을 보는 중」** 상태를 받으면 쓰는 단추를 전부 잠근다.
   화면 위에 누구 작업인지 띠를 띄운다
4. 1단계에서 감춰 둔 단추를 관리자에게만 낸다

**설계 원칙.** 회원용 길(`snsFlowStoreForUser`·`posterStoresForUser`)에
관리자 조건을 심지 않는다. `deleteAnyWork` 가 이미 그렇게 갈라져 있고, 그 이유가
주석에 적혀 있다 —

> 같은 함수에 조건을 심으면 언젠가 그 조건이 어긋나 회원이 남의 작업을 지운다.

### 3단계 — 내 것으로 복사해서 다시 만들기

**하는 일.** 「내 작업으로 복사」 단추. 누르면 관리자 소유의 새 작업이 생기고
그 화면으로 이동한다.

**복사되는 것 / 안 되는 것.**

| 도구 | 복사 | 복사 안 함 |
|---|---|---|
| 카드뉴스 | `title`·`ratio`·`language`·`model_id`·`card_count_mode`·`card_count`·`tone_note`·`data`(원고·첨부 참조·slotPlan) | 만들어 둔 카드 그림, `candidate_id`, 상태 |
| 포스터 | `title`·`ratio`·`model_id`·`data`(지시·레퍼런스 id) | 만들어 둔 변형 그림 |

**결과 그림을 복사하지 않는 이유** — 어차피 다시 만들 것이고, 복사하면 저장소가
같은 그림을 두 벌 들고 있게 된다.

**소유자는 세션에서 강제한다.** 기존 생성 경로가 이미 그 모양이다 —
`projectInsertRow(userId, input)`(`supabase-store-core.ts:110`) 과
`create({ userId: ... })`(`api/sns/projects/project-store.ts:62`). 본문에 남의
`userId` 를 섞어 보내도 무시된다.

**복사한 뒤로는 전부 기존 동작이다.** 자기 작업이므로 크레딧도 소유도 자동으로
관리자가 된다 — 크레딧에 관리자 분기를 만들지 않는다.

**복사할 수 있는 것은 읽을 수 있는 것뿐이다.** 2단계와 같은 관문을 지난다.

## 시험

단계마다 먼저 쓴다.

**1단계**
- 도구별로 맞는 주소를 낸다 (`sns` → `/sns/{id}`, `poster` → `/poster/{id}`)
- 남의 작업에는 단추가 안 나온다
- 카드 본문 클릭은 여전히 뷰어를 연다 (지금 동작을 안 뺏었는지)

**2단계**
- 관리자가 아닌 회원이 남의 작업 id 로 읽으면 **404**
- 관리자는 남의 작업을 읽는다
- 읽기 화면에서 쓰는 단추가 잠겨 있다
- 회원용 읽기·쓰기 경로가 안 바뀌었는지 (소스 대조)

**3단계**
- 본문에 남의 `userId` 를 섞어 보내도 **세션 사용자 소유**로 만들어진다
- 복사 뒤 **원본이 안 바뀐다** (수정 시각·상태·데이터)
- 결과 그림은 복사되지 않는다
- 관리자가 아닌 회원이 남의 작업을 복사하려 하면 **404**

**가드.** 이 저장소는 소스 문자열을 대조하는 시험이 **통과만 하고 아무것도 안
잡는** 사고를 두 번 겪었다(2026-09-08 카드뉴스 자리 번호, 2026-09-15 격자 사본
배선 — 둘 다 변이를 넣어 실증). 그래서 두 가지를 지킨다.

- **타입으로 막을 수 있으면 타입이 먼저다.** 공유 경계의 필드는 `optional` 이
  아니라 **required nullable** 로 둔다. 빠뜨리는 것이 컴파일 오류가 된다
- 소스로 지킬 수밖에 없는 자리(jsdom 이 없어 렌더로 못 재는 배선)는
  **찾지 말고 센다.** `toContain("함수이름")` 은 존재만 말한다 —
  여는 태그와 인자를 한 덩어리로 묶고 자리 수를 박는다
- 시험을 붙였으면 **되돌려 재 본다.** 통과하는 것만 보면 통과만 하는 시험이 쌓인다

## 하지 않는 것

- **회원용 쓰기 경로 수정.** 한 줄도 건드리지 않는다
- **RLS 정책 수정.** 관리자 읽기는 서비스 키로 가고, 정책은 그대로 둔다 —
  정책에 관리자 예외를 넣으면 그 예외가 모든 회원 질의에 얹힌다
- **크레딧 분기.** 복사본이 관리자 것이므로 기존 경로가 그대로 맞다
- **라이브러리 작업물 탭 밖의 도구.** 상세페이지·리디자인·캐릭터는 이 탭이
  다루지 않는다(`TOOL_LABEL` 이 `sns`·`poster` 뿐). 필요해지면 별건

## 열린 것

- **관리자가 남의 작업을 열었다는 기록을 남길지** 정하지 않았다. 지금은 안 남긴다.
  회원 자료를 보는 일이라 나중에 감사 기록이 필요해질 수 있다
- 복사본 제목을 그대로 쓸지 「(사본)」 을 붙일지 — 구현에서 정하고 보고한다
