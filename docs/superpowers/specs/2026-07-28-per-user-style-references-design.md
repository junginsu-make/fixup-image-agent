# 사용자별 스타일 레퍼런스 (프로젝트 J)

작성일: 2026-07-28

## 왜 바꾸는가

지금 스타일 레퍼런스는 **전역 공용**이다. `style_references` 에 `user_id` 가 없다.

그대로 사용자를 받으면 이렇게 된다.

- A 셀러가 자기 상세페이지를 레퍼런스로 등록하면 **B 셀러의 생성 결과에 그 디자인이 씌워진다**
- 출시 전 기획물이 경쟁사에게 새어나간다
- 아무나 올린 것이 섞여 "어울리는 레퍼런스를 고른다"는 전제가 무너진다

라이브러리는 애써 사용자별로 만들어 놓고 레퍼런스는 공용이라 앞뒤가 안 맞는다.

**공용 레퍼런스는 두지 않는다.** 모든 레퍼런스는 그것을 올린 사용자의 것이고,
그 사용자의 생성에만 쓰인다.

## 임베딩을 뺀다

지금 레퍼런스는 Neon 에 있다. pgvector 로 유사도 검색을 하려고 그렇게 뒀다.
그런데 실제로 재보니 **임베딩으로는 못 고른다** — 위스키를 포함해 모든 질의에서
"산뜻한 파스텔"이 1위였다. 질의는 상품 얘기인데 레퍼런스 서술은 디자인 얘기라
서로 다른 의미 공간에 있기 때문이다(프로젝트 H 측정).

그래서 지금도 **LLM 이 고른다.** 임베딩은 레퍼런스가 40장을 넘을 때 후보를
좁히는 용도로만 남겨뒀는데, 사용자별로 나누면 대부분 열 몇 장이라 그 경로를
탈 일이 없다.

**임베딩을 쓰지 않으면 pgvector 가 필요 없고, Neon 에 둘 이유도 없다.**
사용자 데이터는 Supabase 한 곳에 모은다 — 인증·RLS·Storage 가 이미 거기 있다.

나중에 한 사용자가 수백 장을 갖게 되면 그때 좁히는 방법을 넣는다. 지금 넣으면
쓰지도 않을 복잡도만 진다.

## 설계

### 1. 저장

메타데이터는 `public.style_references`(Supabase), 이미지는 Storage 버킷
`references` 에 `{user_id}/{reference_id}.{ext}` 로 둔다. 라이브러리와 같은 방식이다.

```sql
create table public.style_references (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references public.profiles(id) on delete cascade,
  name        text not null,
  source      text not null check (source in ('upload', 'generated', 'seed')),
  path        text not null,
  mime_type   text not null default 'image/png',
  description text not null,          -- Gemini 가 읽어낸 디자인 특성
  created_at  timestamptz not null default now()
);
```

RLS 와 Storage 정책은 라이브러리와 같은 패턴이다. 경로 첫 칸이 소유자다.

### 2. 등록은 회원 스스로

지금은 관리자만 등록할 수 있다. 자기 레퍼런스를 자기가 못 넣으면 이 기능은
쓸모가 없다. **회원 인증으로 낮춘다.** 자기 것만 만들고 지울 수 있으므로
권한을 낮춰도 남에게 영향이 없다.

세 갈래로 들어온다.

- **업로드** — 다른 곳에서 받은 이미지를 첨부한다. 이게 값어치가 가장 크다
- **라이브러리에서 지정** — 내가 만든 결과를 다음 작업의 기준으로 삼는다
- **생성 직후 저장** — 갤러리의 기존 버튼

### 3. 새 사용자는 레퍼런스가 없다

공용을 두지 않기로 했으므로 **가입 직후에는 후보가 0장**이고, 레퍼런스 기능이
아무 일도 하지 않는다. 이건 부작용이 아니라 요구사항의 당연한 귀결이다.

숨기지 않는다. 시나리오 화면에 "등록한 레퍼런스가 없습니다. 올리면 그 디자인을
따라 만듭니다"를 안내하고 올리는 곳으로 보낸다.

### 4. 기존 9장

지금 Neon 에 있는 8종 견본과 생성물 1장은 마스터 계정(`9843ohs@gmail.com`)의
것으로 옮긴다. 만든 목적이 그 계정의 시험이었다. `source: 'seed'` 로 표시해
직접 올린 것과 구분한다.

옮긴 뒤 Neon 의 `style_references` 는 더 쓰지 않는다. 테이블은 남겨두되
코드에서 참조하지 않는다 — 지우는 것은 옮긴 결과를 확인한 다음에 한다.

## 하지 않는 것

- **공용 레퍼런스** — 사용자가 명시적으로 원하지 않았다
- **임베딩·유사도 검색** — 못 고른다는 것을 이미 쟀다. 수백 장이 되면 그때
- **레퍼런스 공유** — 수요가 확인된 뒤에
- **장수 제한** — 지금 사용자가 한 명이다
