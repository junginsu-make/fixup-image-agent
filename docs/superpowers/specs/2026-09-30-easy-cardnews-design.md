## 1. 사용자 결정 (2026-09-30)

1. **옵션은 원고와 함께 보여 주고 단추로 바꾼다.** 말에 있으면 그것, 없으면
   기본값으로 원고를 먼저 쓴다. 원고 밑에 조건 줄(비율 · 장수 · 언어 · 모델 ·
   그림체)이 있고 누르면 바뀐다. 원고까지는 무료라 나중에 바꿔도 손해가 없다
2. **원고가 마음에 안 들면 말로 전체를 다시 쓴다.** 「더 짧게, 20대 말투로」를
   더해 원고 전체를 새로 쓴다. 한 장만 집어 고치기는 3단계
3. **카드뉴스인지 한 장인지 애매하면 두 단추로 묻는다** —
   「이미지 한 장 · 카드뉴스 여러 장」. 분명하면 묻지 않는다. 09-19 의 「애매하면 한
   장」을 뒤집는다: 한 장은 틀리면 곧바로 값이 나가고, 묻는 값은 0 이다
4. **A안** — 「쉽게」 서버가 기존 카드뉴스 라우트를 그대로 차례로 부른다(§3)
5. 1단계 §0 의 결정은 그대로다: 옵션 **전부** 채팅에서, 레퍼런스가 없으면 요청한다
   (`[라이브러리에서 고르기] [저장한 레퍼런스 세트]`), 사진 역할은 1단계를 넓힌다,
   원고를 보여 주고 「이대로 만들기 · 약 N크레딧」으로 확인받는다

## 3. 한 턴의 흐름

```
사용자가 보낸다 — 말 + 붙인 사진(+ [다시 보낼 때] 고른 갈래 · 고른 역할 · 지난 역할)
  │
  ├─ ⓪ 사진 확인 (1단계 그대로)
  ├─ ⓑ1 말 판단 — 원하는 것: talk · image · cardnews · either · revise · detail_page
  │     revise → 이 대화의 마지막 원고를 말대로 다시 쓴다 (§7)
  │     either → 「이미지 한 장 · 카드뉴스 여러 장」 두 단추로 묻고 끝 (§4)
  │     image  → 1단계 그대로
  └─ cardnews
        ├─ ⓒ 장수 확인 (1단계 그대로, 카드뉴스 모델 상한)
        ├─ ⓐ 사진 읽기 · ⓑ2 역할 판단 — 카드뉴스 역할로 넓힌다 (§5)
        ├─ 레퍼런스(분위기 참고)가 한 장도 없다 → 요청하고 끝 (§5-3)
        ├─ unclear · 인물 둘 → 1단계 물음 모양으로 묻고 끝
        ├─ ⓔ 내용 고르기 — 주소 · 긴 글 · 주제 (§6)
        ├─ 작업 만들기(`POST /api/sns/projects`) → 원고(`POST /[id]/plan`)
        ├─ 원고가 0장 → 까닭을 말하고 끝 (§9)
        └─ 원고를 대화에 남긴다 → 화면: 원고 + 조건 줄 + [이대로 만들기 · 약 N크레딧]

「이대로 만들기」 (따로 보내는 요청)
  ├─ 이 대화의 원고인지 · 아직 원고 단계인지 서버가 확인한다
  ├─ 그림(`POST /[id]/generate`, 요청 식별자를 단계마다 갈라 준다)
  └─ 화면이 진행을 이어 부른다(§8). 다른 화면으로 가면 셸이 이어 부른다
```

**새 생성 경로를 만들지 않는다.** 1단계가 포스터 라우트 셋을 함수로 부르듯, 카드뉴스
라우트를 함수로 부른다. 카드뉴스에서 다듬은 원고 · 문구 · 과금이 그대로 온다.

## 4. 카드뉴스인가 한 장인가

- ⓑ1 이 가른다. 원하는 것에 `cardnews` 와 `either` 를 더한다
- `cardnews`: 「카드뉴스」 · 「여러 장」 · 「슬라이드」 · 「캐러셀」처럼 여러 장을 말했다
- `image`: 「포스터 한 장」 · 「배너」 · 「썸네일」처럼 한 장을 말했다
- `either`: 어느 쪽인지 말하지 않았다 — 「신메뉴 홍보물 만들어줘」
- **either 는 두 단추로 묻는다.** 대화에 아무것도 안 남긴다(비율 물음과 같다). 누르면
  처음 말과 고른 갈래를 함께 다시 보낸다 — 서버는 고른 갈래를 ⓑ1 보다 앞세운다
- 사진이 없어도 묻는다. 사진이 있으면 역할 물음보다 먼저 묻는다 — 갈래에 따라 역할이
  다르다

## 5. 사진과 레퍼런스

### 5-1. 역할

1단계의 넷에 카드뉴스 둘을 더한다. ⓑ2 는 갈래가 카드뉴스일 때만 두 역할을 안다.

| 「쉽게」 역할 | 카드뉴스 첨부 | 언제 |
|---|---|---|
| style (분위기 참고) | `style_reference` + 자리(§5-2) | 디자인 참고물 · 「이 느낌으로」 |
| preserve_product | `keep_identity` object | 제품 · 로고 |
| preserve_person | `keep_identity` person | 인물 |
| preserve_person_restyled | `keep_identity` person + `restyle` | 인물 그대로 · 그림체만 |
| place_as_is (원본 그대로 한 장) | `place_as_is` | 「이 표는 그대로 넣어줘」 · 표 · 그래프 · 캡처 |
| ending (마지막 장) | `ending` | 「이걸 마지막 장으로」 |

- 우선순위 · 코드 가드 · 지난 역할 · 말 보내기 조건은 1단계 그대로다
- 물음 화면에 단추 둘(원본 그대로 · 마지막 장)을 더한다 — **카드뉴스일 때만**
- 인물은 한 명(카드뉴스 규칙과 같다)

### 5-2. 레퍼런스를 어느 자리에

카드는 자기 자리 레퍼런스만 본다(§2). 자리를 비우면 그 카드는 다른 모양으로 나온다.

| 레퍼런스 | 자리 |
|---|---|
| 한 장 | 표지 · 속지 · 끝 **세 자리 모두**에 그 한 장 |
| 여러 장 | 붙인 순서로 첫 장 = 표지, 마지막 장 = 끝, 나머지 = 속지 |
| 말로 정함 | 「2번이 표지」면 말대로 |
| 저장한 세트 | 세트에 적힌 자리 그대로 |

한 그림을 세 자리에 넣을 수 있는지(같은 id 를 자리만 달리해 세 번 넣기)는 **계획 첫
단계에서 기존 검사 함수로 확인한다.** 안 되면 그 그림을 속지에만 두고 표지 · 끝 경고를
화면에 옮긴다 — 계획에서 정한다.

### 5-3. 레퍼런스가 없으면

- 분위기 참고로 정해진 사진이 한 장도 없으면 원고를 쓰지 않는다. 비용 0
- 「따라 만들 카드뉴스를 붙여 주세요」 + `[라이브러리에서 고르기] [저장한 레퍼런스 세트]`
- 세트를 고르면 세트의 그림이 붙고, 세트의 자리가 고른 역할(분위기 참고 + 자리)로 간다
- 붙인 뒤 다시 보내면 처음 말을 이어서 보낸다(대화에 아무것도 안 남겼다)

### 5-4. 내 그림만

카드뉴스는 내 폴더의 그림만 받는다(§2). 일반 회원의 라이브러리에는 원래 내 그림만
보인다. 관리자가 남의 그림을 붙이면 ⓪ 뒤에 「카드뉴스는 내가 올린 그림만 쓸 수
있습니다」로 멈춘다(비용 0).

## 6. 내용 고르기

코드가 가른다(값으로 잰다). 말에서 찾는다.

| 말 | 내용 |
|---|---|
| 유튜브 주소가 있다 | `youtube` |
| 다른 주소가 있다 | `web` — 꺼져 있으면(`SNS_WEB_SOURCE`) 「기사 주소는 아직 못 읽습니다. 글을 붙여 넣어 주세요」로 멈춘다 |
| 주소가 없고 말이 길다 | `text` — 말 전체 |
| 짧다 | `question` — 인터넷 검색 |

「길다」의 기준은 실측(§12)으로 정한다(첫 값 300자). 원고 화면에 「인터넷에서 찾은
내용으로 썼어요」 · 「붙여 주신 글로 썼어요」처럼 무엇으로 썼는지 한 줄 적는다.

## 7. 원고 화면

```
도우미: 원고를 썼습니다 (6장) · 인터넷에서 찾은 내용으로 썼어요
  1 표지  건강기능식품, 제대로 고르는 법
  2 속지  인증 마크부터 확인하세요
  …
  6 끝    오늘부터 라벨을 확인하세요
  [4:5 ▾] [자동 6장 ▾] [한국어 ▾] [표준형 ▾] [그림체: 레퍼런스 ▾]
  [이대로 만들기 · 약 6크레딧]
  고치고 싶으면 말로 해 주세요. 예: 더 짧게, 20대 말투로
```

- **조건 줄**
  - 말에 있던 것 → 기본값 차례. 모델은 입력창의 이미지 모델 드롭다운
  - 바꾸면 **원고를 다시 쓴다**(작업 입력을 고치는 라우트가 없어 새 작업). 무료
- **말로 고치기**
  - 원고가 있는 대화에서 사진 이야기 없이 원고를 고치는 말(「더 짧게」)이 오면,
    ⓑ1 이 `revise` 로 가른다
  - 앞 원고의 조건 그대로, 말을 추가 지시에 더해 새로 쓴다
- **다시 쓴 원고**
  - 앞 원고 줄은 접히고 「이대로 만들기」는 마지막 원고에만 있다
  - **아무것도 지우지 않는다**(2026-09-30 사용자 결정 — 「삭제가 아니라 새로
    생성」). 앞 원고의 작업은 그대로 남는다. 카드뉴스 목록에 쓰지 않은 원고가 쌓일
    수 있다
- **만든 뒤에 고치기**(2026-09-30 사용자 결정)
  - 카드를 이미 만든 대화에서 「더 밝게」처럼 고쳐 달라고 하면, 앞 결과는 그대로
    두고 **새 작업**으로 원고를 다시 쓴다
  - 「이대로 만들기」를 누르면 새로 만들고 **그만큼 크레딧이 빠진다.** 누르기 전
    단추에 값을 적는다
- **값 표시**
  - `estimateCost` 를 원고의 카드로 센다(틀 · 원본 장 · 마지막 장 반영)
  - image-v2 는 크레딧, cost-v1 은 「장」(화면의 지금 표기를 따른다)

## 8. 만드는 중과 결과

- 「이대로 만들기」
  - `{action: "generate", projectId}` 로 보낸다
  - 서버가 확인하는 것: 이 대화에 그 작업의 줄이 있나 · 원고 단계(`copy_ready`)인가 ·
    원고가 1장 이상인가. 아니면 멈춘다(비용 0)
- 진행
  - 「쉽게」 화면이 `status` 를 10초 간격으로 이어 부른다(카드뉴스 화면과 같은 간격)
  - 셸의 `RunningJobsProvider` 에 **그 대화 주소**로 등록한다 — 대화 화면에 있을 때는
    셸이 안 부르고(`href === pathname`), 떠나면 셸이 부른다. 한 작업을 두 곳이 겹쳐
    부르지 않는다
- 입력창
  - 만드는 동안에도 말은 할 수 있다(원고 단계 뒤라 새 주문과 안 섞인다)
  - 같은 대화에서 두 번째 카드뉴스를 시작하는 것은 막는다
- 결과
  - 오른쪽 결과 칸에 카드 전부
  - 대화에는 「카드뉴스 6장」 한 줄과 [카드뉴스 화면에서 이어서 작업](`/sns/{id}`)
  - 한 장 다시 만들기 · 게시글 · 전부 받기는 그 화면에서(채팅 안은 3단계)
- 다시 열기
  - 대화의 줄이 가리키는 작업을 **포스터에서 먼저, 없으면 카드뉴스에서** 찾는다 —
    마이그레이션이 필요 없다
  - 카드뉴스면 상태로 그린다: 원고 단계 → 원고 화면, 만드는 중 → 진행, 끝 → 카드
  - 앞 원고 → 접힌 채 「원고를 다시 썼습니다」 한 줄

## 9. 실패

| 상황 | 할 일 | 값 |
|---|---|---|
| 레퍼런스 없음 · 남의 그림 · 장수 상한 · 기사 주소 꺼짐 | 까닭을 말하고 멈춘다 | 0 |
| 원고 0장(내용을 못 가져옴 등) | `planningIssues` 를 쉬운 말로 적는다. 빈 원고 작업도 지우지 않는다(§7) | 0 |
| 원고 라우트 실패 | 어느 단계인지 말한다(1단계 `EasyStepError` 그대로) | 0 |
| 크레딧 부족 · 권한 | `generate` 가 준 말 그대로, 다시 누르기 안내 없음 | 0 |
| 만드는 도중 실패 | 만든 장까지만 값(기존 규칙), 실패한 장을 적는다 | 만든 장만 |

## 10. 건드리지 않는 것

기존 카드뉴스 · 이미지 만들기 코드는 0줄이다. 1단계 목록에 카드뉴스 쪽을 더한다.

```
git diff --stat <시작점> -- packages apps/web/app/api/poster apps/web/app/poster \
  apps/web/app/sns apps/web/app/api/sns apps/web/lib/sns apps/web/lib/poster \
  apps/web/lib/reference-images.ts apps/web/lib/membership apps/web/lib/llm \
  apps/web/app/api/reference-sets supabase
→ 0줄
```

부르기만 한다: 카드뉴스 라우트들, `estimateCost`, `GET /api/reference-sets`,
`RunningJobsProvider` 의 등록 함수. **마이그레이션 없음**(§8 다시 열기).

## 11. 계획 첫 단계에서 확인할 것

추측으로 설계하지 않도록, 코드로 먼저 확인하고 계획에 적는다.

1. 같은 그림을 자리만 달리해 세 번 넣을 수 있나 — `validateAttachments` · 만들기 스키마 · 과금 셈(`estimateCost` 가 첨부를 세는지)
2. 참고 그림의 저장 경로가 `${userId}/` 로 시작하나(§5-4)
3. 원고(1~2분)를 「쉽게」 요청 안에서 기다려도 운영 서버(Caddy · Node)가 끊지 않나
4. image-v2 에서 원본 그대로 장 · 마지막 장이 차감되는지(값 표시와 맞아야 한다)
5. `RunningJobsProvider` 에 등록하는 공개 함수와 끝났을 때의 신호

## 12. 확인

**먼저 잰다**(1단계 §2-11 방식, 실제 모델).

| 재는 것 | 예 | 기대 |
|---|---|---|
| ⓑ1 갈래 | 「건강기능식품 카드뉴스」 · 「인스타 캐러셀로」 | cardnews |
| | 「카페 오픈 포스터 한 장」 · 「유튜브 썸네일」 | image |
| | 「신메뉴 홍보물 만들어줘」 · 「이걸로 만들어줘」(사진) | either |
| | 「카드뉴스 표지 한 장만」 | image |
| | 「카드뉴스는 어떻게 만들어요?」 | talk |
| | (원고가 있는 대화) 「더 짧게」 · 「20대 말투로」 | revise |
| ⓑ2 카드뉴스 역할 | 「이 표는 그대로 넣어줘」(표 캡처) | place_as_is |
| | 「이 사진으로 마지막 장」 | ending |
| | 「이 느낌으로 카드뉴스」(카드뉴스 3장) | 셋 다 style, 자리는 §5-2 |
| 내용 | 유튜브 주소 · 기사 주소 · 긴 글 · 짧은 주제 | §6 |

**통과 기준**

- 한 장을 원했는데 카드뉴스로 가거나 그 반대로 간 것 0건 — 애매하면 either
- 레퍼런스 없이 원고를 쓴 것 0건
- 원고 단계에서 회원 크레딧이 나간 것 0건
- 지킬 것을 분위기로 보낸 것 0건(1단계 기준 그대로)

**시험으로 잠근다**: 갈래 · 내용 고르기 · 자리 나누기 · 역할 → 카드뉴스 첨부 ·
조건 줄 · 다시 쓰기(새 작업 · 아무것도 안 지움) · 「이대로 만들기」 확인 ·
다시 열기(포스터 먼저, 카드뉴스 다음) · 셸 등록 주소. 뮤테이션 · 독립 리뷰 · 0줄.
