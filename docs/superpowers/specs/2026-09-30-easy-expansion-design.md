## 0. 사용자 결정 (2026-09-30)

1. **상세페이지는 안내로 끝낸다.** 「쉽게」에서 상세페이지를 달라고 하면 만들지 않고
   상세페이지 기능으로 보낸다.
2. **카드뉴스는 「쉽게」에서 끝까지 만든다.** 기존 카드뉴스의 옵션과 기능이
   **전부** 채팅에서 돌아야 한다 — 레퍼런스 디자인 따라가기, 긴 글, 주제만 주고
   정보 수집 맡기.
3. **붙인 사진은 무조건 분위기 참고가 아니다.** 사용자는 사진을 붙이고 그 사진을
   어떻게 해 달라고 말한다. **그 말을 따른다.** 제품을 가리키면 제품을 지킨다.
   여러 장이면 장마다 다를 수 있다(이건 분위기, 저건 유지). 정확한 말이 필요하면
   **AI 가 사용자에게 묻는다.** 사용자의 말은 이미지 모델까지 그대로 가고, LLM 은
   그 뜻을 정확히 읽어 반영한다.
4. **사진 없이 카드뉴스를 달라고 하면** 채팅이 따라 만들 카드뉴스를 요청한다.
   `[라이브러리에서 고르기] [저장한 레퍼런스 세트]` 단추를 함께 낸다.
5. **A안**(§2-2) — AI 가 말과 사진을 함께 보고 사진마다 역할을 정한다.
6. **새 가지에서 한다.** 다른 터미널이 크게 작업 중이라 `feat/easy-cardnews` 에서
   하고 나중에 합친다.

> **「되묻지 않는다」와의 관계.** 2026-09-17 설계는 되묻기를 버렸다. 3번은 그것을
> **사진 역할에 한해** 되살린다. 모르는 채로 만들면 값이 나가고 제품이 다시
> 그려진다 — 묻는 것은 값이 0 이다. 비율·그림체를 한 번 묻던 방식(2026-09-21)과
> 같은 원칙이다: **묻되 막지 않는다**가 아니라, 여기서는 **모르면 묻고, 알면 안
> 묻는다.**

## 2. 1단계 — 사진 역할과 상세페이지 안내

### 2-1. 지금 무엇이 틀렸나

| 무엇 | 어디 |
|---|---|
| 붙인 사진을 **전부 `referenceIds`(따라 만들기)**로 보낸다 | `app/easy/easy-client.tsx:300` |
| 번호 순서를 「따라 만들기 먼저, 지킬 것 나중」으로 다시 짠다. 사용자가 붙인 순서가 사라진다 | `app/api/easy/generate/route.ts:219` |
| 붙인 수에 `personIds` 를 한 번 더 더한다. 인물이 `preservedIds` 에도 있으면 두 번 센다 | `route.ts:136` |
| `restyledIds` · `attachmentIntent` 를 안 넘긴다 | `route.ts:210-220` |

**이미지 만들기 쪽은 이미 다 받을 줄 안다.** 역할 네 가지(`@fixup/shared` 의
`AttachmentRole`), 역할마다 다듬어진 문구(`poster-core/src/prompt.ts` 의
`attachmentLines`), 사용자 말이 고정 문구를 이기는 규칙(같은 파일, `hasAttachmentIntent`),
사진마다 무엇이 찍혔는지 읽는 기계(`readAttachments`)가 있다.
**빠진 것은 하나다 — 말과 사진을 보고 역할을 정하는 자리.**

### 2-2. 방법 — A안

| | 방법 | 버린 까닭 |
|---|---|---|
| **A** | 사진마다 무엇이 찍혔는지 읽고, 그 설명과 사용자 말로 역할을 정한다 | — |
| B | 말만 보고 정한다 | 「제품은 살려」라고만 하면 어느 사진이 제품인지 모른다. 거의 매번 되묻게 된다 |
| C | 역할 없이 말만 넘긴다 | 역할이 없으면 전부 「따라 만들기」가 되고, 그 문구가 「사람·제품은 베끼지 마라」를 붙인다. **지금 문제가 그대로다** |

### 2-3. 한 턴의 흐름

```
사용자가 보낸다 (말 + 붙인 사진, 붙인 순서대로)
  │
  ├─ ⓐ 사진 읽기 — 붙인 것이 있을 때만. 한 장씩(`readAttachments`)
  │     「무엇이 찍혔나 · 사람이 몇인가 · 글자가 있나」
  │
  ├─ ⓑ 판단 — 글 모델 한 번. 지금 쓰는 「말인가 주문인가」를 넓힌다
  │     원하는 것   talk · image · detail_page
  │     사진마다    style · preserve_product · preserve_person ·
  │                preserve_person_restyled · unclear
  │     사진 지시   사용자 말 중 사진에 관한 부분(원문 그대로)
  │
  ├─ detail_page → 안내 줄을 남기고 끝 (§2-7)
  ├─ talk        → 답을 남기고 끝 (지금과 같다)
  ├─ image + unclear 가 있다 → 묻고 끝, 아무것도 안 남긴다 (§2-5)
  ├─ image + 지킬 인물이 둘 이상 → 묻고 끝 (§2-5)
  └─ image → 역할대로 칸을 채워 기존 세 라우트를 부른다 (§2-6)
```

**ⓐ를 판단 앞에 둔다.** 판단이 「제품 사진은 살려」의 「제품 사진」이 몇 번인지
알아야 하기 때문이다. 읽기는 **이미지 만들기 기획이 쓰는 그 기계**를 쓴다 —
새로 만들면 두 벌이 되고 하나는 곧 낡는다.

**사진을 판단 모델에 직접 넣지 않는다.** 한 번에 여러 장을 주면 모델이 사람과
연출을 뒤섞는다(`read-attachment.ts:168`, 옛 `readPeople` 이 같은 판단을 했다).
한 장씩 읽은 설명을 번호와 함께 준다.

### 2-4. 역할을 정하는 규칙

**사용자 말이 먼저다.** 말이 사진을 가리키고 쓰임을 말하면 그대로 따른다.

| 사용자 말 | 사진 | 역할 |
|---|---|---|
| 쓰임을 말했다 — 「1번 제품은 그대로」 · 「이 느낌으로」 · 「1번 사람들을 2번 그림체로」 | 무엇이든 | **말대로** |
| 가리키지만 쓰임이 모호하다 — 「이걸로」 · 「이거 참고해서」 | 한 갈래로만 읽힌다 (제품만 찍힌 사진, 글자와 디자인이 있는 포스터) | 그 갈래 — 제품 사진이면 **제품 유지**, 디자인이면 **분위기 참고** |
| 가리키지만 쓰임이 모호하다 | 두 갈래로 읽힌다 (인물 사진 — 사람을 살릴지 느낌만 볼지) | **unclear** |
| 사진 이야기가 없다 — 「카페 포스터 만들어줘」 | 디자인 참고물(포스터 · 광고 · 카드뉴스) | 분위기 참고 |
| 사진 이야기가 없다 | 제품 · 인물 사진 | **unclear** |

**애매하면 묻는 쪽으로 기운다.** 묻는 값은 0 이고, 틀리게 만들면 값이 나가고
제품이 다시 그려진다. 반대로 **말에 이미 있는 것을 또 묻지 않는다** — 안 들은
것이 된다.

**사진 지시는 원문에서 떼어 온다.** 판단이 돌려준 「사진 지시」가 사용자가 친
말 안에 **그대로 없으면** 버리고 친 말 전체를 쓴다. 모델이 요약하거나 지어낸
말이 「사용자 말」 자리에 들어가 고정 문구를 이기면, 사용자가 한 적 없는 말이
가장 센 말이 된다.

### 2-5. 묻는 모양

```
  ─────────────────────────────────────
  카페 오픈 포스터 만들어줘               ← 사용자 (사진 2장)
  ─────────────────────────────────────
  사진을 어떻게 쓸지 알려 주세요.

   [①사진]  [분위기만 참고] [제품 그대로] [인물 그대로]
   [②사진]  [분위기만 참고] [제품 그대로] [인물 그대로]

   말로 답하셔도 됩니다 — 「1번은 우리 원두 봉투야」
                                      [이걸로 만들기]
  ─────────────────────────────────────
```

- **물음은 코드가 짓는다.** 판단 모델은 어느 사진이 unclear 인지만 말한다.
  같은 상황에 같은 물음이 나와야 사용자가 배운다.
- 분명한 사진은 물음에 **이미 고른 채로** 보인다. 틀렸으면 거기서 바꾼다.
- 「인물은 그대로 두고 그림체만 바꾸기」는 단추로 내지 않는다. 말로만 받는다 —
  단추가 넷이면 읽고 고르는 데 오래 걸리고, 이 역할은 「애니풍으로」처럼 말에
  이미 들어 있을 때가 대부분이다.
- **말로 답하면** 처음 말과 답을 **함께** 다시 판단한다. 묻는 동안은 대화 표에
  아무것도 안 남기므로(지금 비율·그림체 물음과 같다), 답만 보내면 처음 말이 사라진다.
  이때 §2-4 의 「원문」은 처음 말과 답을 이은 것이다.
- **다시 보낼 때도 판단을 돌린다.** 단추로 고른 역할이 판단보다 세다 —
  `ask.ts` 의 「고른 것이 가장 세다」와 같다. **모든 사진을 단추로 골랐으면 사진
  읽기(ⓐ)를 건너뛴다.** 역할을 정할 일이 없는데 읽으면 값과 기다림만 는다.
- 단추로 고른 값은 **서버가 다시 확인한다** — 이번에 붙인 사진의 id 인지,
  아는 역할인지. 모르는 것이 오면 그 사진은 다시 unclear 다.
- **지킬 인물이 둘 이상이면** 한 명만 된다고 말하고 같은 물음 모양으로 다시
  묻는다. 둘이면 얼굴이 섞인다. `[인물 그대로]` 는 한 줄에서만 고를 수 있고,
  서버도 같은 규칙으로 다시 센다. 사람 수는 `@fixup/shared` 의
  `countPreservedPeople` 로 센다 — 같은 캐릭터의 여러 각도는 한 명이다.
- 비율·그림체 물음은 **사진이 없을 때만** 나온다(지금 그대로). 두 물음이 한 턴에
  겹치지 않는다.

### 2-6. 이미지 만들기로 넘기는 것

| 판단 | 칸 |
|---|---|
| style | `referenceIds` |
| preserve_product | `preservedIds` |
| preserve_person | `preservedIds` + `personIds` |
| preserve_person_restyled | `preservedIds` + `personIds` + `restyledIds` |
| 사진 지시 | `attachmentIntent` |
| 붙인 순서 | `attachmentOrder` — **사용자가 붙인 순서 그대로** |

- 인물은 **반드시 `preservedIds` 에도 넣는다.** 이미지 만들기가 인물 주소를
  `preservedIds` 에서만 찾는다(`api/poster/projects/[id]/generate/route.ts:236`) —
  빠지면 조용히 따라 만들기가 된다.
- 붙인 수는 **서로 다른 사진 수**로 센다. 값 셈(`easyCost`)이 같은 수를 쓴다.
- `attachmentIntent` 가 있으면 이미지 만들기가 「사용자 말이 부딪히는 규칙을
  이긴다. 안 부딪히는 규칙은 그대로 산다」를 붙인다(`prompt.ts` 의
  `hasAttachmentIntent`). 제품 유지 문구는 사용자가 반대로 말하지 않는 한 산다.

### 2-7. 상세페이지 안내

- 판단이 `detail_page` 면 **만들지 않는다.** 내 말과 안내 한 줄을 남긴다.
- 안내 문구는 **코드가 정한 한 문장**이다. 모델이 짓게 두면 매번 다른 길을 알려 준다.
- 안내 줄 밑에 `[상세페이지 만들기 열기]` 단추를 단다(`/create`). 다시 열어도
  단추가 보이게, 화면은 **그 문구와 똑같은 줄**에만 단추를 단다 — 표를 바꾸지 않는다.
- 값은 판단 한 번뿐이다. 회원 크레딧은 안 빠진다.

### 2-8. 판단 결과를 보여 준다

- 결과 밑 「만든 조건」에 `①제품 유지 · ②분위기 참고` 를 적는다.
- **다시 열어도 보인다.** 역할은 이미지 만들기 작업에 이미 저장된다(`referenceIds`
  · `preservedIds` · `personIds` · `restyledIds` · `attachmentOrder`). 거기서 읽는다 —
  대화 표에 베끼면 어긋난다(`_components/load.ts` 가 모델·비율을 읽는 방식과 같다).

### 2-9. 값

- 회원이 보는 값은 **그대로다.** 판단은 지금도 크레딧을 잡지 않는 자리이고, 사진
  읽기도 그 자리에 붙는다.
- 운영비는 는다 — 사진을 붙인 턴마다 사진을 한 번씩 더 읽는다(기획이 한 번 더
  읽는다). 한 장 읽기 값은 `llmCostUsd({ visionReads: 1 })` 이다.
- 사진을 붙인 채로 여러 턴을 보내면 턴마다 다시 읽는다. **첫 판에서는 담아 두지
  않는다** — 실측에서 기다림이 길다고 나오면 그때 붙인다.

### 2-10. 건드리지 않는 것

**이미지 만들기(다양하게)와 카드뉴스의 기존 화면·서버는 0줄이다.** 「쉽게」만 바꾼다.

```
git diff --stat <시작점> -- packages/poster-core packages/shared \
  apps/web/app/api/poster apps/web/app/poster apps/web/app/sns apps/web/app/api/sns
→ 0줄
```

**마이그레이션도 없다.** 대화 표의 갈래는 그대로 넷이다.

### 2-11. 확인

**먼저 잰다.** 구현 전에 판단만 떼어 실제 문장으로 돌린다.

| 문장 (사진) | 기대 |
|---|---|
| 「이 제품으로 광고 만들어줘」 (제품 1) | ① 제품 유지 |
| 「이거 참고해서 카페 포스터」 (디자인 포스터 1) | ① 분위기 참고 |
| 「카페 포스터 만들어줘」 (제품 1 · 디자인 1) | ① unclear · ② 분위기 참고 |
| 「1번 사람들을 2번 그림체로」 (인물 · 일러스트) | ① 인물 유지 · 그림체 바꾸기 · ② 분위기 참고 |
| 「제품은 살리고 배경만 바꿔」 (제품 1) | ① 제품 유지 |
| 「이 사람으로 프로필 만들어줘」 (인물 1) | ① 인물 유지 |
| 「이 느낌으로」 (인물 1) | ① 분위기 참고 |
| 「이거 참고해서」 (인물 1) | ① unclear |
| 「상세페이지 만들어줘」 | detail_page |
| 「이 제품 상세페이지 만들어줘」 (제품 1) | detail_page |
| 「상세페이지 문구 좀 봐줘」 | talk |
| 「안녕하세요」 (제품 1) | talk |
| 「두 사람 다 그대로 넣어줘」 (인물 · 인물) | 인물 유지 둘 → 한 명만 묻기 |

**통과 기준**

- **지켜야 할 것을 분위기 참고로 보낸 것 0건.** 가장 비싼 실수다 — 값이 나가고
  제품이 다시 그려진다
- 말에 쓰임이 있는데 되묻는 것 0건
- 나머지는 표와 맞는다. 어긋나면 프롬프트를 고치고 다시 잰다

**시험으로 잠근다**

- 역할 → 칸 나누기, 순서, 인물이 `preservedIds` 에도 들어가는지, 사진 지시가
  원문에 있는지, 사람 수 세기 — 순수 함수로 빼서 값으로 잰다
- 판단 응답 읽기 — 모르는 역할·모르는 id 는 버리고 unclear 로
- 라우트 — 역할이 이미지 만들기 칸까지 가는지, 물을 때 아무것도 안 남기는지,
  `detail_page` 에서 값이 안 나가는지
- 뮤테이션 — 규칙 하나씩 무력화해 시험이 잡는지 본다
- 독립 리뷰 — 다른 에이전트가 따로 본다

## 3. 2단계 — 「쉽게」 카드뉴스 (정한 것과 사실만)

**새 생성 경로를 만들지 않는다.** 기존 카드뉴스 라우트를 그대로 부른다 — Easy
이미지가 포스터 라우트 셋을 함수로 부르는 방식과 같다.

**확인한 사실**

| 무엇 | 사실 | 어디 |
|---|---|---|
| 내용 — 주제만 | **실제로 인터넷을 검색한다** (OpenAI `web_search`, 반드시 한 번 이상) | `ingest-core/src/adapters/topic.ts:58-76` |
| 내용 — 긴 글 | 길이 상한이 없다. 통째로 기획·원고에 들어간다 | `api/sns/projects/schema.ts:46` |
| 내용 — 유튜브 | 자막을 가져온다 | `lib/sns/source-adapters.ts:17-20` |
| 내용 — 기사 주소 | **꺼져 있다** (`SNS_WEB_SOURCE=1` 일 때만) | `lib/sns/feature.ts` |
| 따라 만들 카드뉴스 | **최소 1장이 있어야 만든다** | `sns-core/src/attachments.ts:119` |
| 따라 만들기의 자리 | 표지 · 속지 · 엔딩마다 따로 간다. 자리가 없으면 어디에도 안 간다 | `sns-core/src/attachments.ts:59-63` |
| 사진 역할 | 따라 만들기 · 사람/제품 그대로 · 원본 그대로 한 장 · 마지막 장. 화면에서 손으로 고른다 | `sns/_components/attachment-picker.tsx` |
| 원고에서 멈춘다 | `plan` 이 원고를 쓰고 `copy_ready` 로 멈춘다. `generate` 가 그림값을 잡는다 | `api/sns/projects/[id]/plan`, `generate` |
| 진행 | `status` 를 부를 때마다 다음 장을 보낸다. 안 부르면 멈춘다 | `lib/sns/queued-flow.ts` |
| 원고가 빈 채로 성공 | 내용을 못 가져오면 `ok` 인데 카드가 0장이다 | `lib/sns/actual-flow.ts:40-43` |

**정한 것**

- 사진 없이 요청하면 따라 만들 카드뉴스를 요청한다(§0-4)
- 사진 역할은 1단계의 판단을 넓혀 쓴다 — 카드뉴스 쪽 갈래(원본 그대로 한 장 ·
  마지막 장 · 표지/속지/엔딩 자리)를 더한다
- 원고를 보여 주고 「이대로 만들기 · 약 N크레딧」으로 확인받은 뒤 그림을 만든다
- 기사 주소는 카드뉴스가 켜질 때 같이 켜진다. 「쉽게」가 따로 켜지 않는다

**2단계 설계에서 정할 것**: 카드뉴스와 이미지 한 장을 어떻게 가르나(09-19 §12 의
실측) · 옵션을 어느 때 버튼으로 내나 · 결과 칸이 여러 장을 어떻게 받나 · 대화 표에
원고 줄을 어떻게 남기나(마이그레이션) · 화면을 떠나도 계속 만들어지게(셸의
`RunningJobsProvider`).
