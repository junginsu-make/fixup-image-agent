## 2. 고치는 것

### A. 엉뚱한 답 되풀이 (보고 2)
- **A1 선택지를 지금 쓸 수 있는 갈래로만.** `chat.ts` 에 「지금 쓸 수 있는 갈래」를 정하는 함수 하나를 두고, 프롬프트와 선택지 목록이 **같은 함수**를 쓴다. 고칠 이미지·원고가 없으면 고치기 갈래가 아예 없다
- **A1-2 규칙 한 줄.** 이 대화에서 아직 만든 것이 없을 때 「붙인 사진 속 ○○을 바꿔줘」는 그 사진으로 **새 이미지를 만들라는 것**(`image`)
- **A2 고른 갈래가 늘 이긴다.** 「이미지 한 장 · 카드뉴스」 단추로 고른 것은 판단 결과와 상관없이 그대로 간다
- **A3 빈 답이면 한 번 더 묻는다.** `talk` 인데 답이 비면 모델에게 한 번 더 묻고, 그래도 비면 그때만 기본 문장
- **A4 하는 일·안 하는 일을 사실대로.** 프롬프트에 적는다 — 하는 일: 이미지 한 장, 카드뉴스, 만든 이미지 이어서 고치기, 카드뉴스 손보기. 안 하는 일: 상세페이지(→ 상세페이지 만들기), 포털 광고 규격 여러 장(→ 아래 A5). 안 되는 것을 물으면 모델이 **그 사실과 갈 곳**을 말로 답한다
- **A5 「광고 소재」라는 말이 나오면 먼저 묻는다** (2026-10-06 사용자 결정 두 번)
  - **묻는 때**: 이번 말에 「광고 소재」·「광고소재」가 있고, **규격 낱말이 없을 때**. 묻는 말(고정): 「광고 이미지를 만들고 싶으세요, 아니면 네이버·구글·카카오 규격별로 이미지를 베리에이션하고 싶으세요?」 + 두 단추 「광고 이미지 만들기」 / 「규격별로 베리에이션」. 단추 대신 말로 답해도 된다
  - **안 묻는 때**: 같은 말에 규격 낱말이 있으면 — 「규격별」·「사이즈별」·「리사이징·리사이즈」·「베리에이션」·「네이버」·「구글」·「카카오」 — 묻지 않고 바로 규격 안내로 간다(사용자: 「이런 정확한 키워드를 말할 경우에는 굳이 안 물어도 됩니다」). 「광고 소재」라는 말 없이 여러 규격을 분명히 말해도(「구글 배너 사이즈별로 다」) 판단 모델이 규격 안내를 고를 수 있다
  - 낱말 찾기는 **코드**가 한다(규칙이 매번 지켜지게). 「광고 소재 **말고** 그냥 이미지」처럼 부정하는 말은 낱말이 있어도 판단 모델이 그 뒤 요청을 따른다 — 실제 모델 표본으로 확인하고, 흔들리면 코드 규칙을 더한다
  - **광고 이미지** → 이미지 길. 만들 때 쓰는 지시는 **물음 앞의 처음 말 + 답**이다(단추만 누른 경우 처음 말 그대로) — 「광고 이미지로요」 한마디로 그리면 내용이 사라진다
  - **베리에이션·리사이징·규격별** → 이미지를 만들지 않는다. LLM 이 우리 기능의 실제 순서를 받아 안내하고, 그 줄에 「광고소재 열기」(`/ad`) 단추를 단다. 안내할 사실(코드가 넣는다): `/ad` 의 세 단계 — 이름은 화면의 것(`app/ad/steps.ts` 의 `AD_STEPS`)을 그대로 읽는다: 「01 그림 고르기」(이미 만든 이미지 한 장) → 「02 어디에 올릴까요」(포털 · 규격, 네이버·구글·카카오) → 「03 확인하고 내려받기」(눈으로 확인하고 ZIP 한 묶음). 새로 그리지 않고 고른 이미지에서 뽑는다. **대부분의 규격은 자르고 줄이기만 해서 크레딧이 들지 않고, 투명 배경 규격(카카오 비즈보드 · 네이버 스마트채널 — `lib/ad/specs.ts` 의 `png-alpha`)을 고르면 배경 제거가 한 번 들어가 내려받기 한 번에 1크레딧이 든다**(`lib/ad/cost.ts`, `api/ad/export/route.ts:176-183`). 원본이 작으면 1.2배까지만 늘려 못 뽑는 규격이 생긴다. 이 대화에서 만든 이미지가 있으면 그것을 골라 가면 된다고, 없으면 여기서 광고 이미지를 먼저 만들어 가져가도 된다고 말한다
  - **물음과 안내도 대화에 남는다.** 물음 줄·안내 줄 모두 도우미 줄로 저장한다(단추는 상세페이지 안내처럼 그 문장이 달린 줄에 단다). 그래서 말로 답해도(「사이즈별로요」), 새로고침 뒤에 답해도 앞 물음을 알고 판단한다
  - **대화는 끊기지 않는다.** 광고 물음·안내는 「모드」로 붙잡지 않는다 — 다음 말은 늘 처음부터 판단한다. 「규격별로」라고 해서 안내를 받은 뒤 「아니야, 이미지 더 만들 거야. ○○ 만들어줘」라고 하면 그대로 이미지를 만든다. 물음에 답하지 않고 다른 말을 해도 그 말을 따른다(사용자: 「여기서 또 끊기면 안 됩니다. 대화는 계속 이어져야 합니다」)
- 고정 문장(`NOTHING_TO_EDIT` 등)은 안전망으로만 남는다 — A1 뒤에는 닿지 않는다

### B. 대화가 끊김 (보고 1)
- **B1 「이대로 만들기」는 기본값으로 만든다.** 아무것도 안 골랐으면 기본 비율을 「고른 값」으로 실어 보낸다(화면 한 줄)
- **B2 물음에 답할 때 앞서 고른 것을 함께 싣는다.** 갈래·비율·그림체를 한 묶음으로 들고 다녀, 같은 말에 두 번 묻지 않는다
- **B3 다시 열면 이어 받는다.** 대화를 열 때 그림이 아직 없는 이미지 줄이 있으면 상태를 물어 받아 온다(만든 직후와 같은 길). 떠났다 돌아와도, 새로고침해도 이미지가 들어온다
- **B4 실패도 대화에 남긴다.** 사용자 말을 남긴 뒤 실패하면 그 안내를 도우미 줄로 남긴다
- **B5 0장이면 실패로 알린다**

### C. 과정 보기 (보고 3)
- 쉽게 작업 목록이 「작업 → 대화」를 함께 준다. 라이브러리에서 **내** 쉽게 작업(이미지·카드뉴스 모두)의 「과정 보기」와 그림 없는 카드 클릭은 `/easy/{대화}` 로 간다
- 대화를 지웠거나, 관리자가 남의 작업을 볼 때는 지금처럼 도구 화면으로 간다(남의 대화는 열 수 없다)

### D. LLM 처럼 이어지는 대화 (사용자 핵심 원칙)

> 「[쉽게] 모드는 LLM 이 탑재되어 있어서 사용자가 GPT·Gemini·Claude 쓰는 것처럼 작동되어야 한다. 우리는 거기에 우리 시스템 데이터를 제공한다.」(2026-10-06)

A·B·C 를 고친 뒤 되는 것: 이미지 만들기 → **방금 것** 이어서 고치기 → 다른 것 새로 만들기 → 그것 이어서 고치기 → 질문하면 우리 기능 사실을 바탕으로 답하기.
그래도 GPT 처럼 쓰기에는 아직 모자란 것이 셋 있어, 함께 고친다.

- **D1 물음과 답을 대화에 남긴다.** 지금은 「한 장? 카드뉴스?」·「모양?」·「사진을 어떻게 쓸까요?」·「광고 이미지? 규격별?」 같은 물음이 대화에 안 남는다. 그래서 새로고침하면 내 말이 사라지고, 단추 대신 말로 답하면(「규격별로요」) 모델이 앞의 물음을 모른 채 판단한다. 물음도 사용자 말 + 도우미 물음 줄로 남기고, 답은 그 맥락 위에서 판단한다. 다시 열면 물음 문장이 보이고 말로 답하면 이어진다(단추는 그 자리에서만)
- **D2 이 대화의 어느 이미지든 골라 고친다.** 지금은 **마지막 결과 하나만** 고칠 수 있다. 「아까 첫 번째 거 배경만 바꿔줘」를 못 한다. 지난 대화에 이미지마다 번호를 붙여 모델에게 보여 주고, 모델이 고칠 번호를 고른다. 번호가 애매하면 묻는다
- **D3 붙인 사진은 쓴 뒤 비운다.** ChatGPT 처럼 — 이미지를 만들거나 고치는 데 쓴 사진은 입력창에서 내린다. 지금은 남아서 이후 모든 말에 「사진 2장 붙임」이 붙고, 모델이 그 사진을 또 쓰려 한다. 다시 쓰려면 다시 붙이면 된다(라이브러리에 남아 있다)

**나누어 낸다**: 1차 = A·B·C(보고 3건 바로 해결), 2차 = D(대화 구조가 바뀌는 것이라 1차가 운영에서 확인된 뒤). 각 차수 끝에 독립 리뷰.

## 3. 이번에 하지 않는 것 (점검에서 나왔지만 범위 밖 · 이유)
- 모델이 이미지 **내용을 보고** 답하기(「방금 거 어때?」) — 지금 모델은 이미지 자리를 「(이미지 한 장)」 글로만 본다. 이미지를 모델에 넣으면 턴마다 값이 크게 늘어 따로 정한다
- 지난 대화에 섞인 고정 문장 표시 바꾸기 — A1 뒤에는 고정 문장이 거의 안 나온다
- 개발 서버 전용 문제(StrictMode 에서 받기 멈춤), 카드뉴스 손보기 일부 답 미저장, 판정 대기 최대 3분, 실패 뒤 말풍선 중복 — 작다. 기록만 한다
- 광고 물음 뒤 말로 「카드뉴스로요」라고 답하면 카드뉴스 원고가 물음 앞의 처음 말을 못 잇는다(이미지 길만 잇는다) — 물음과 답을 대화 맥락 위에서 판단하는 **2차 D1** 이 다룬다(2026-10-06 최종 리뷰)

## 4. 사용자 결정 (2026-10-06)

2. 「광고 소재」 + 규격 낱말(규격별·사이즈별·리사이징·베리에이션·네이버·구글·카카오)이면 묻지 않는다. 어떤 경우에도 대화는 이어진다

## 5. 확인 방법
- 단위 시험: 쓸 수 있는 갈래 함수, 선택지 목록 = 프롬프트 안내, 고른 갈래 우선, 빈 답 재질문, 「이대로 만들기」 값, 물음 묶음, 다시 열기 이어 받기 조건, 실패 줄 남기기, 작업→대화 주소
- 실제 모델(값 몇 원): 캡처 두 말 → 새 이미지 · 「광고 소재 만들어줘」 → 먼저 묻기 · 말로 「사이즈별로요」 → `/ad` 안내 · 「광고 소재 네이버 카카오 규격별로」 → 묻지 않고 안내 · 안내 뒤 「아니야, 이미지 더 만들 거야. 겨울 화장품 이미지 만들어줘」 → 이미지 · 물음 뒤 말로 「광고 이미지로요」 → 처음 말 내용으로 이미지 · 「광고 소재 말고 그냥 이미지」 → 이미지 · 이미 만든 이미지 고치기 / 카드뉴스 고치기 / 질문 답하기가 그대로인지
- 로컬 화면: 「이대로 만들기」 한 번에 진행, 라이브러리 과정 보기 → 쉽게 대화
- 배포 뒤 사용자 손 확인: 캡처와 같은 요청, 만드는 중 새로고침
- **처음 만들기 경로**(포스터·카드뉴스 생성 라우트·`packages/*`)는 0줄 변경
