# 사내 사용 설명서 (앱 안 `/guide`) 설계

작성 2026-09-04 · 상태: 확정, 구현 진행

---

## 한 줄

**처음 온 사람이 도구마다 "이게 뭘 하는 것이고, 이 칸은 왜 있고, 나는 뭘
골라야 하나"를 화면을 보며 알 수 있는 페이지.**

## 왜 필요한가

지금 안내는 `_components/guide-dialog.tsx` 모달 하나다. 문제가 셋이다.

1. **빠진 도구가 있다.** 탭이 개요·새로 만들기·리디자인·보관·캐릭터·공통
   지식 여섯인데, 카드뉴스와 이미지 만들기와 수집이 없다. 지금 도구는
   다섯이고 카드뉴스에는 길이 둘이다
2. **설정 항목을 설명하지 않는다.** 카드뉴스 03 규격에만 비율·장수·언어·
   모델 네 가지가 있고 자리 계산이 따라 붙는다. 모달의 문단으로는 어느
   칸을 말하는지 짚어 줄 수 없다
3. **모달이라 좁다.** 화면을 보여 줄 자리가 없다

## 확정된 결정

| 질문 | 결정 |
|---|---|
| 기존 모달 | **설명서로 흡수.** 모달 자리는 `/guide` 로 보내는 링크가 된다 |
| 화면을 무엇으로 보여주나 | **코드로 그린 목업.** 스크린샷은 안 쓴다 |
| 사이드바 | 「설명서」 그룹에 항목 하나(`/guide`). 안에서 목차로 나눈다 |
| 로그인 | 필요하다. 스튜디오 셸 안에 산다 |

### 스크린샷을 쓰지 않는 이유

- 이 저장소는 UI 가 자주 바뀐다. 오늘만 해도 카드뉴스에 길이 하나 늘었다.
  스크린샷은 바뀐 화면을 따라가지 못하고, 낡은 안내는 없는 것만 못하다
- `public/landing/` 이 이미 21MB 다. 도구마다 몇 장씩 더하면 배포 꾸러미가
  커진다
- 다크모드에서 라이트 스크린샷은 이질적이다. 이 앱에는 다크모드가 있다
- 초보자에게는 **정보가 적은 그림이 더 잘 읽힌다.** 실제 화면에는 지금
  설명하지 않을 것까지 다 들어 있다

목업은 실제 화면을 그대로 베끼지 않는다. **그 화면에서 지금 설명할 것만**
남긴 단순화된 그림이다.

## 라우트

```
/guide                  처음 오셨다면 — 전체 지도 · 한 바퀴 · 용어
/guide/cardnews         카드뉴스 만들기 (두 갈래)
/guide/image            이미지 만들기 (포스터 · 광고 소재)
/guide/detail-page      상세페이지 만들기 (사진 / 글)
/guide/redesign         상세페이지 리디자인
/guide/character        캐릭터 만들기
/guide/library          라이브러리 · 수집
/guide/credits          크레딧과 모델 고르기
```

사이드바에는 「설명서」 그룹 아래 **「사용 설명서」 하나만** 둔다. 여덟 개를
사이드바에 늘어놓으면 도구 목록보다 안내가 길어진다. 설명서 안에서 자체
목차로 옮겨 다닌다.

`isActive` 는 `pathname.startsWith(href)` 라 `/guide/cardnews` 에서도
사이드바의 「사용 설명서」가 켜진 채로 남는다. 따로 손댈 것이 없다.

## 각 도구 페이지의 뼈대

여섯 조각을 같은 순서로 둔다. 순서가 같아야 두 번째 도구부터는 어디를 볼지
찾지 않는다.

1. **한 줄** — 이게 뭘 하는 도구인가
2. **흐름** — 단계 다이어그램. 실제 `StepBar` 의 단계와 같은 말을 쓴다
3. **무엇이 다른가** — 시중 도구와의 차이. 근거 있는 것만 적는다
4. **화면 읽기** — 목업 + 번호 콜아웃. 설정 항목마다 "무엇을 정하는 칸인지 ·
   비우면 어떻게 되는지 · 언제 바꾸는지"
5. **무엇을 고르나** — 상황 → 선택 표
6. **자주 막히는 곳** — 실제 검증 메시지와 제약에서 가져온다

## 목업을 그리는 법

재사용 프리미티브를 `_components/mockup.tsx` 에 둔다. 도구마다 새로 그리지
않는다.

| 조각 | 쓰임 |
|---|---|
| `<Mock>` | 창틀. 제목바 + 본문 |
| `<MockStepBar>` | 단계 막대 |
| `<MockField>` | 라벨 + 입력 칸 |
| `<MockTabs>` | 탭 줄 |
| `<MockChoices>` | 고르는 카드/버튼 묶음 |
| `<MockButton>` | 버튼 |
| `<MockNote>` | 회색 도움말 줄 |
| `<Marker n>` | ① 번호 뱃지. 목업 안과 설명 목록에서 같은 번호를 쓴다 |

색과 크기는 공용 토큰만 쓴다. 랜딩(`_landing/landing.css`)처럼 자체 팔레트를
두지 않는다 — 설명서는 앱 안에 있고, 다크모드에서 앱과 같이 뒤집혀야 한다.

## 다이어그램

흐름은 인라인 SVG 로 그린다. 라이브러리를 더하지 않는다.

- 상자와 화살표만. 좌표는 손으로 잡는다
- 색은 `currentColor` 와 CSS 변수로 — 다크모드에서 따라 뒤집힌다
- `viewBox` 로 폭에 맞춰 줄어들되, 좁으면 가로 스크롤 컨테이너 안에서 민다
- 글자는 SVG `<text>` 대신 `<foreignObject>` 를 쓰지 않는다. 폰트 문제로
  줄바꿈이 어긋난다. 상자 안 글자는 짧게 유지한다

## 하지 않는 것

- 스크린샷 캡처·주석
- 설명서 안에서 실제로 만들어 보게 하는 인터랙티브 튜토리얼. 도구가 바로
  옆에 있다
- 검색. 페이지가 여덟이다
- 다국어. 이 화면은 승인 회원용이고 회원은 한국어를 쓴다

## 시험

목업과 문구는 화면이라 단위 시험의 대상이 아니다. 대신 **설명서가 실제와
어긋나지 않는지**를 잡는 시험을 둔다.

- 설명서가 인용한 상수가 실제 상수와 같은지 — 비율 목록, 모델 목록, 역할
  4어휘, 캐릭터 각도 여섯을 코드에서 가져와 쓰고, 하드코딩하지 않는다
- 목차의 모든 항목이 실제 라우트를 가리키는지
