## 2. 코드로 확인한 사실

| 무엇 | 사실 | 근거 |
|---|---|---|
| 한 장 글 저장 | `PATCH /api/sns/projects/{id}/cards/{n}` — 제목 · 본문 · 강조 · 작은 글씨. **저장하면 작업 상태를 `copy_ready` 로 되돌린다** | `app/api/sns/projects/[id]/cards/[index]/route.ts:45-58` |
| 한 장 다시 만들기 | `POST …/cards/{n}` 본문 `{ note? }`(500자). 그 장만큼 크레딧을 잡고(`creditImagePlan(1, …)`), 상태를 `generating` 으로 바꾼다. 다른 장이 만드는 중이면 409 | 같은 파일 `POST`, `result-rules.ts:34` |
| 한 장 그림 자리 | `{userId}/sns/{projectId}/{n}.png` 에 **덮어쓴다**(`upsert: true`). 앞 그림은 남지 않는다 | `lib/sns/runtime.ts:100-102` |
| 전체 만들기 | `POST …/generate` 는 **원고의 모든 장**을 잡는다(`creditImagePlan(cards.length)`) | `app/api/sns/projects/[id]/generate/route.ts:72` |
| 게시글 | `POST …/caption` — 크레딧을 안 잡는다. `flow.caption = { hook, body, hashtags(≤15), firstComment }`, 상태는 그대로 | `app/api/sns/projects/[id]/caption/route.ts`, `sns-core/caption.ts:19-43` |
| 전부 받기 | 카드뉴스 화면이 브라우저에서 `jszip` 으로 묶는다. 파일 이름은 `snsCardFilename(title, n, assetPath)` | `app/sns/[id]/result-board.tsx:213-230`, `app/sns/download-filename.ts` |
| 참고 이미지 저장 | `saveReferenceImage({ userId, id, title, purpose, bytes, mimeType })` — 운영 저장소 · 로컬 둘 다 | `lib/reference-images.ts:356` |
| 진행 받기 | 2단계 진행 표시가 `generating` 작업을 이어 부른다 | `app/easy/use-cardnews.ts` |

**위험(그대로 두면 생기는 일):** 다 만든 카드뉴스에서 한 장 글만 고쳐도 상태가 `copy_ready` 가 되어, 「쉽게」 원고 카드가 「이대로 만들기 · 약 N」을 다시 띄운다. 누르면 **전 장을 다시 만들고 전 장 값이 나간다.** §6-1 이 막는다.

## 3. 대상

- 이 대화의 **마지막 카드뉴스 작업**(2단계 `latestCardnewsRow` 와 같은 줄).
- **만든 작업** = 만든 뒤 상태(`done` · `review_required` · `failed`)인 장이 있거나, **AI 가 그린 장**에 그림이 있는 작업. 작업 상태(`status`)로 가르지 않는다(§2 위험). 원본 그대로 · 마지막 장 사진 칸은 기획이 원고 단계부터 사진 경로를 넣어 두므로(`lib/sns/actual-flow.ts:101-105`) 세지 않는다(독립 리뷰 Critical, 2026-10-01).
- **만드는 중**(작업이나 어느 장이 `generating`)에는 글 고치기 · 다시 만들기를 받지 않는다 — 글 저장이 상태를 원고로 되돌려 진행이 끊기고, 다시 만들기는 어차피 거절되는데 앞 그림만 또 보관된다.
- 만든 작업: 네 가지 모두. 만들기 전 원고: **글 고치기만**(무료, 2단계 원고 카드에서).

## 4. 단추 (다 만든 카드뉴스 줄)

```
카드뉴스 6장을 만들었습니다
 1 표지  …제목…            [글 고치기] [다시 만들기]
 2 속지  …제목…            [글 고치기] [다시 만들기]
 …
 [게시글 쓰기] [전부 받기]   [카드뉴스 화면에서 이어서 작업]
```

- **다시 만들기** → 그 장 밑에 확인 줄: 「바라는 점(선택)」 칸 + 「앞 그림은 라이브러리에 보관합니다 · 약 1크레딧」 + [다시 만들기] [그만두기]. 누를 때만 값이 나간다.
- **글 고치기** → 그 장 밑에 칸 넷(제목 · 본문 · 강조 · 작은 글씨) + [저장] [그만두기]. 무료. 그림이 있는 장이면 저장 뒤 「그림에도 반영할까요?」 확인 줄(위 다시 만들기와 같다)이 열린다.
- **게시글 쓰기** → 게시글 칸(첫 문장 · 본문 · 해시태그 · 첫 댓글) + [복사]. 다시 누르면 새로 쓴다. 크레딧 없음.
- **전부 받기** → 그림이 있는 장만 압축 파일 하나로 받는다(브라우저). 크레딧 없음.
- 만드는 중이면 이 단추들은 잠긴다(2단계 `busy`). 만들기 전 원고에는 장마다 [글 고치기]만 붙는다.

## 5. 말로 부탁

ⓑ1(말인가 주문인가)에 갈래를 더한다. **이 대화에 카드뉴스가 있을 때만** 알려 준다(2단계 `revise` 와 같은 방식).

| 갈래 | 예 | 받는 칸 | 하는 일 |
|---|---|---|---|
| `card_redo` | 「3번 다시 그려줘, 글자 크게」 | `card`(번호) · `note` | 다시 만들기 **확인 줄**을 띄운다(§4). `note` 가 「바라는 점」에 들어간다. **값은 안 나간다** |
| `card_text` | 「3번 제목을 '뒷면을 보세요'로」 · 「3번 더 짧게」 | `card` · `note` | 그 장 글을 고쳐 저장(§6-2). 그림이 있는 장이면 반영 확인 줄 |
| `caption` | 「올릴 글 써줘」 | — | 게시글을 쓴다 |
| `download` | 「다 받을게」 | — | 화면이 압축 파일을 받는다 |

- `card_redo` · `caption` · `download` 는 **만든 작업**이 있을 때만 받는다. 없으면 「먼저 카드를 만들어 주세요」로 답한다(값 없음).
- 번호가 없거나 원고에 없는 번호면 「몇 번 장인가요?」로 되묻는다(아무것도 안 남긴다).
- **번호 없는 고치기**(「더 짧게」)는 지금처럼 `revise` — 원고 전체를 새 작업으로 다시 쓴다(2단계 §7).
- 판단 틀(`EASY_CHAT_SPEC`)에 `card`(정수, 없으면 0) · `note`(글) 칸을 더한다. 틀에 없으면 안 온다(1단계 교훈).

## 6. 서버

`POST /api/easy/cardnews` (2단계 라우트)에 할 일을 더한다. 모두 **이 대화 줄이 가리키는 내 작업**만(2단계 검사 그대로).

### 6-1. `generate` 를 막는다 — 만든 작업이면 거절
- 만든 작업(§3)이면 409 「이미 만든 카드뉴스입니다. 장마다 [다시 만들기]를 써 주세요.」
- 화면도 만든 작업에는 「이대로 만들기」를 안 낸다(상태가 `copy_ready` 로 돌아와도).

### 6-2. `edit` — 한 장 글 고치기
- 본문 `{ index, copy?: { headline?, body?, accent?, footnote? }, words? }`
- `copy` 가 오면 그대로, `words` 가 오면 **고른 글 모델이 그 장 글을 고친다**(새 틀 `EASY_CARD_EDIT_SPEC`: 제목 · 본문 · 강조 · 작은 글씨, 원고 언어, 앞 글에 없는 사실 · 숫자 금지). 둘 다 비면 400.
- 저장은 `PATCH …/cards/{n}` 를 대신 부른다. 응답은 작업 + 그 장이 그림이 있는지(`needsRedraw`).

### 6-3. `redo` — 한 장 다시 만들기
- 본문 `{ index, note? }`(500자).
- 차례:
  1. 그 장에 그림이 있으면 **앞 그림을 참고 이미지로 보관**한다. 파일을 읽어(운영: 저장소, 로컬: 파일) `saveReferenceImage` 로 넣는다. 이름 「{작업 제목} · {n}번 장 이전 그림」, 용도 `cardnews`
  2. **보관이 실패하면 멈춘다**(값 안 나감) — 「앞 그림을 보관하지 못해 다시 만들지 않았습니다.」
  3. `POST …/cards/{n}` 를 대신 부른다(크레딧은 거기서). 응답 작업은 `generating` → 2단계 진행 표시가 이어 받는다
- 서버가 대화에 「3번 장을 다시 만들고 있습니다. 앞 그림은 라이브러리에 「{이름}」으로 보관했습니다.」 줄을 남긴다(다시 열어도 보인다). 그림이 없던 장(실패한 장)이면 보관 문장은 뺀다.

### 6-4. `caption` — 게시글
- `POST …/caption` 를 대신 부른다. 응답의 `flow.caption` 을 화면이 그린다. 실패하면 쉬운 말.

### 6-5. 채팅 턴(`/api/easy/generate`)
- `card_redo` → `{ ok, cardAsk: { rowId, index, note } }` — 확인 줄만(아무것도 안 남긴다, 비율 물음과 같다)
- `card_text` → `edit` 와 같은 일을 하고 `{ ok, cardEdited: { rowId, project, index, needsRedraw } }`. 사용자 말과 「3번 장 글을 고쳤습니다」 줄을 남긴다
- `caption` → `{ ok, caption: { rowId, project } }` · `download` → `{ ok, download: { rowId } }`
- 번호 문제 → `{ ok, talked }` 「몇 번 장인가요?」(남기지 않는다)

### 6-6. 오류
- 402 · 403 · 409 는 그 안내를 그대로, 500 번대는 쉬운 말 + 서버 기록(2단계와 같다).

## 7. 화면

- `cardnews-card.tsx`: 만든 작업이면 장마다 단추 · 아래 단추 줄 · 확인 줄 · 글 칸 · 게시글 칸. 파일이 800줄을 넘지 않게 장 한 줄과 게시글 칸을 새 부품으로 뺀다.
- `use-cardnews.ts`: `edit` · `redo` · `caption` · 전부 받기(브라우저, `jszip` · `snsCardFilename` 을 부르기만).
- 판단은 값으로 잰다: `isMade(view)`, 확인 줄 상태, 받기 목록 — `cardnews-state.ts` 에 둔다.
- `easy-client.tsx` 는 800줄 그대로 — 새 응답(`cardAsk` 등)은 훅의 `take` 가 받는다.

## 10. 검증

1. **실측:** 새 갈래 넷과 번호 읽기를 실제 판단 모델로. 혼동하면 안 되는 쌍 — `card_text` ↔ `revise`(번호 유무), `card_redo` ↔ `image`(한 장 새로), `caption` ↔ `talk`
2. **TDD:** 순수 판단(만든 작업 · 확인 줄 · 번호 검사 · 받기 목록) → 라우트(보관 실패 시 멈춤, 만든 작업 `generate` 거절, 남의 작업 거절) → 연결 시험
3. **뮤테이션 · 독립 리뷰 · 0줄**
4. **실제 화면:** 글 고치기 · 게시글 · 전부 받기는 바로. 크레딧이 드는 한 장 다시 만들기는 fal 충전 뒤 사용자에게 묻고

## 11. Review Focus (구현 전에 시험으로 묶을 것)

1. 다 만든 작업에서 글만 고친 뒤 「이대로 만들기」가 다시 나와 전 장 값이 나가는 길(§2 위험)
2. 앞 그림 보관이 실패했는데 다시 만들어 앞 그림을 잃는 길
3. 말 「3번 다시」가 확인 없이 값을 내는 길
4. 원고에 없는 번호(「9번」)나 만들기 전 원고에 「다시 그려줘」
5. 만드는 중에 또 다시 만들기(409)와 화면 잠금
