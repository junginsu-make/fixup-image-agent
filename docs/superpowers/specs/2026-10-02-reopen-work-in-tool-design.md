# 「과정 보기」로 상세페이지·캐릭터를 도구에서 다시 열기

작성 2026-10-02 · 사용자 승인분

## 무엇을 만드는가

라이브러리에서 상세페이지·캐릭터의 「과정 보기」를 누르면 **그 작업을 만든 도구가
그 작업의 값으로 채워진 채 열린다.** 단계마다 보고, 고치고, 그 상태로 다시 만들 수
있다. 카드뉴스(`/sns/[id]`)·다양하게(`/poster/[id]`)가 이미 그렇게 되어 있다
(`2026-09-16-library-open-work-steps-design.md`).

지금은 둘 다 **결과 그림만 보여 주는 읽기 전용 화면**으로 간다
(`app/library/works/[id]`, `app/characters/[id]`). 9월 16일 설계가 「상세페이지·
리디자인·캐릭터는 필요해지면 별건」으로 남겨 둔 자리다.

## 확정된 결정 (2026-10-02, 사용자)

| 물음 | 답 |
|---|---|
| 상세페이지를 어디까지 | **브라우저에 남은 초안 연결 + 서버에 복원 꾸러미 보관 둘 다** |
| 캐릭터 각도 한 장을 다시 만들면 | **항상 새 캐릭터로 저장**(원본은 그대로) |

두 번째 답에 붙인 기본값(사용자에게 알림): **각도 한 장만 다시 만들어도 새 캐릭터에는
원본의 나머지 각도를 옮겨 담는다.** 안 그러면 새 캐릭터에 그 한 장만 남는다.

## 지킬 것

- **처음 만들기 경로는 0줄 변경**(사용자 지시 2026-09-29). 캐릭터는
  `handleCandidates`·`handleCreate`·`startOver`·`POST /api/characters`·
  `createCharacter`·`generateCandidates`, 상세페이지는 분석·텍스트 완료·생성 경로.
  끝에 `git diff` 로 증거를 보인다
- **원본을 고치지 않는다.** 다시 만들면 언제나 새 작업이 생긴다 — 카드뉴스·
  다양하게와 같다(`poster/new-client.tsx:547-550`)
- **회원용 쓰기 경로를 넓히지 않는다.** 남의 작업은 지금처럼 보기 전용 + 관리자
  「내 것으로 복사」

## 단계

### 1단계 — 캐릭터

**지금 가진 것으로 거의 된다.** 저장된 것: 이름·설명(`source_prompt`)·종류·그림체·
정면과 각 각도. 저장 안 된 것: 참고로 붙인 그림과 역할, 고른 모델(비율은 늘 3:4).

**캐릭터 도구는 「고른 정면(`chosen`)」이 차 있으면 「각도 고르고 저장」 자리가
된다**(`CharacterStudio.tsx:197-199, 941-960`). 거기에는 이미 「다시 뽑기」(정면
다시)와 「설정 고치기」(입력 칸 다시 열기)가 있다. 그래서 저장된 값과 정면을 그
자리에 채우기만 하면 모든 단계가 기존 화면 그대로 열리고, 저장은 기존
`handleCreate` 가 **새 캐릭터로** 한다.

| 하는 일 | 어디서 |
|---|---|
| `/characters/[id]` 가 내 캐릭터면 도구를 그 값으로 연다. 남의 것이면 지금의 보기 전용 화면 | 새 `[id]/open-client.tsx` |
| 입력 칸·정면을 채운다. 참고 그림·모델이 비었다고 알린다 | 새 `use-opened-character.ts`·`opened-notice.tsx`, 스튜디오는 prop 하나와 훅 호출만 |
| 원래 정면 그대로 저장했으면 **새 캐릭터에 없는 각도를 원본에서 옮겨 담는다.** 정면을 다시 뽑았으면 다른 인물이라 안 옮긴다 | 새 `lib/character-carry.ts` + `POST /api/characters/[id]/carry` |
| 캐릭터 하나를 읽을 때 최근 100개 안에서만 찾던 것을 id 로 직접 찾는다 | `listCharacters` 에 `ids` 선택지 |

옮겨 담기는 **두 캐릭터가 모두 요청한 사람 것일 때만**, **새 캐릭터에 없는 각도만**
채운다. 원본은 읽기만 한다. 그림 생성이 없으므로 크레딧이 들지 않는다.

**라이브러리 등록.** 옮겨 담은 각도도 라이브러리 「참고 이미지」에 **새 캐릭터 이름으로
등록한다.** 다른 도구가 캐릭터 각도를 라이브러리 제목(「이름 (캐릭터) · 각도」)으로만
찾고, 캐릭터를 지울 때도 그 제목으로 지우기 때문이다. 그래서 새 캐릭터 이름에는
겹치지 않는 「(수정본)」/「(수정본 N)」 꼬리를 40자 안에서 붙이고, 저장한 뒤에도 이름 칸이
그대로면 다음 꼬리로 바꾼다 — 같은 이름이 둘이면 한쪽을 지울 때 다른 쪽 라이브러리
각도까지 지워진다. 옮겨 담기는 `{ carried, failed, referenceIssue? }` 를 돌려주고, 못 옮긴
각도와 라이브러리 등록 실패는 사용자에게 알린다.

> **2·3단계는 대체됐다(2026-10-02 사용자).** 상세페이지는 웹 서비스로 여러 브라우저에서
> 쓰므로 과정 전체를 서버에 저장한다. 설계·작업 지시는
> `2026-10-02-pdp-server-documents-codex-handoff.md`(Codex 가 구현). 아래 두 단계는 기록으로만 남긴다.

### 2단계 — 상세페이지, 이 브라우저에 남은 초안 연결

서버 변경 없음. 라이브러리 항목의 `source_id` 가 이 브라우저 IndexedDB 의 초안 id 와
같으면 `/create?draft=<source_id>` 로 연다(이 길은 이미 있다,
`PdpMakerClient.tsx:722-731`). 없으면 지금의 보기 전용 화면. 같은 컴퓨터·30일 안·
2026-09-28 이후 서버 동기화로 들어간 내 작업에서만 된다.

계획은 1단계를 마친 뒤 그때 코드로 다시 쓴다.

### 3단계 — 상세페이지, 서버에 복원 꾸러미 보관

앞으로 만드는 작업은 **도구를 되살리는 데 필요한 것 전부**(입력·상품 사진·섹션·
설정·편집 상태)를 서버에 함께 둔다. 다른 컴퓨터·관리자도 도구로 연다(관리자는
「내 초안으로 복사」). 옛 작업은 꾸러미가 없어 보기 전용으로 남는다.

설계 과제(3단계 계획에서 정한다): 처음 만들기·저장 경로를 건드리지 않고 **따로
덧붙여** 보내는 방법, 본문 10MB 제한(`library-save.ts:19-25`)과 사진 용량, 리디자인을
같이 할지. 계획은 2단계를 마친 뒤 쓴다.
