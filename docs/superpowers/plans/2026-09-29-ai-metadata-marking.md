# AI 생성 표시를 파일 안에 적는다

**요청**(2026-09-29): 사용자가 「이 시스템에서 생성한 모든 결과물에 메타데이터로
AI 생성 마크를 넣을 수 있나」를 물었다. 목적은 **「나중에 저작권이나 법적 논쟁을
피하기 위함」**이고, 보이는 워터마크를 의도적으로 지운 그림이 인터넷에 공개돼도
문제가 되지 않게 하려는 것이었다.

**범위**(사용자 지시): 「우선 1시간에 끝나는것만 진행하세요」 — EXIF 만. XMP 는
뒤로 미뤘다(§5).

## 0. 처음 권고를 뒤집었다

사용자가 목적을 「의도적 삭제 방어」로 설명했을 때 나는 **하지 말자고 했다.**
메타데이터는 지우기가 너무 쉽고(`exiftool -all=` 한 줄), 플랫폼이 업로드할 때
알아서 떼어 버리므로 그 목적에는 쓸모가 없다고 답했다. 대신 서버 기록과 약관
조항을 권했다.

그 뒤 사용자 지시로 법을 조사하고 **권고를 다시 뒤집었다.** 메타데이터는
필요하다 — 다만 **삭제 방어가 아니라 법 준수 수단으로서**다. 이유가 바뀌었다.

조사 결과는 `docs/ai-labeling-law.html` 에 있다(근거 5건).

### 0.1 법이 요구하는 것

인공지능기본법 **제31조**, 2026-01-22 시행 중.

| | |
|---|---|
| 누구에게 | 생성형 AI 서비스를 제공하는 사업자 |
| 무엇을 | 결과물이 AI 로 생성되었다는 사실의 표시 |
| 어떻게 | **사람이 인식할 수 있는 방법 또는 기계가 판독할 수 있는 방법** |
| 파일 단위 | 다운로드·공유로 서비스 밖에 나갈 수 있으면 **파일 자체에** |
| 안 보이는 방법만 쓸 때 | 별도 고지 1회 이상 |
| 안 지키면 | 3천만원 이하 과태료(제43조) |
| 매출·사용자 수 면제 | **없다** |

### 0.2 그래서 우리에게 구멍이 있었다

배지는 굽고 있었다(`lib/watermark.ts`). 그런데 **관리자가 그것을 끌 수 있다.**

    배지 켬 → 파일에 표시 있음 → 요건 충족
    배지 끔 → 파일에 표시 없음 → 요건 미충족

끈 상태로 내려받은 그림이 밖으로 나가면 요건을 못 채운다. 배지를 끌 수 있게
해 둔 것은 사용자가 요청한 사양이므로(「관리자가 끄고 키게 할 수 있게 해놓은
것도 맞습니다」), **껐을 때도 유효한 길**을 만들어야 했다.

## 1. 실측한 것 — 추측으로 정하지 않았다

sharp 0.35.4 / libvips 8.18.6.

| 시험 | 결과 | 그래서 |
|---|---|---|
| XMP 쓰기 | **불가** | IPTC `DigitalSourceType` 표준을 지금은 못 쓴다 |
| 무손실 WebP 컨테이너 | `VP8L` — 메타데이터 칸이 없다 | 넣으려면 `VP8X` 로 재조립해야 한다 |
| EXIF 값에 괄호 | **값이 잘린다** — `FormWith (AI)` → `FormWith` | 괄호를 안 쓴다 |
| EXIF 에 한글 | 뷰어마다 깨진다 | 설명은 ASCII 로 적는다 |
| APNG 의 `meta.pages` | **`undefined`** — libvips 가 APNG 를 못 읽는다 | 바이트에서 `acTL` 을 찾는다 |
| 움직이는 WebP 의 `meta.pages` | **`2`** — 제대로 온다 | `pages` 로도 가른다 |
| 움직이는 WebP 의 최상위 청크 | `VP8X,ANIM,ANMF,ANMF` — 화소가 `ANMF` 안에 있다 | 컨테이너 판정에 「손실」로 보여 그쪽이 먼저 막는다 |
| q80 JPEG 를 q95 로 다시 굽기 | **화소 90% 가 바뀌고 ×1.42** | JPEG 는 아예 손대지 않는다 |
| 손실 WebP 를 무손실로 다시 굽기 | **×3.07** | 컨테이너를 보고 손실이면 안 건드린다 |
| 16비트 PNG 를 다시 굽기 | `depth` 가 `ushort` → `uchar` | 깊이 가드를 둔다 |
| `withMetadata({ exif })` | **들어온 ICC 를 sRGB 로 갈아치운다.** 태그가 없던 그림에는 480B 를 끼워 넣는다 | `keepMetadata().withExif()` 를 쓴다 |
| 이미 sharp 가 구운 PNG 를 다시 굽기 | **×1.000** — 값이 없다 | 광고 경로에 표시를 늘 붙여도 용량이 안 늘어난다 |

**`acTL` 과 `pages` 는 서로가 놓치는 쪽을 잡는다** — `acTL` 은 PNG 청크라 WebP 에
안 걸리고, `pages` 는 APNG 에 안 온다. 다만 움직이는 WebP 는 **손실 판정이 먼저
막으므로** `pages` 줄은 지금 중복이다(§3.2).

### 1.1 내가 적어 둔 값이 틀렸었다

처음에 `ai-metadata.ts` 주석에 「움직이는 WebP 도 `pages` 가 `undefined` 라
마찬가지였다」고 적었다. **틀렸다.** 그렇게 측정한 것은 raw 입력에 `pages` 옵션을
준 것이었는데, sharp 는 raw 입력에서 그 옵션을 무시한다 — 애초에 움직이는 WebP 가
만들어지지 않았고, 정지 WebP 를 재고 있었다.

변이 시험이 이것을 잡았다(「pages 방어를 뺀다」가 초록으로 남았다). 저장소의
2프레임 GIF 를 `{ animated: true }` 로 읽어 WebP 로 구워 다시 재니 `pages` 가 2 로
왔다. 주석을 고치고 시험을 붙였다.

**교훈은 측정 방법이다.** raw 입력에 옵션을 주고 「쟀다」고 적었다. 만든 표본이
정말 그 성질을 갖는지 **먼저 확인**해야 한다 — 그래서 새 시험들은 표본 자체를
먼저 단정한다(`expect(손실.toString("ascii",12,16)).toBe("VP8 ")` 처럼).

## 2. 무엇을 바꿨는가

### 2.1 새로 만든 것

`apps/web/lib/ai-metadata-values.ts` — 적는 값만. **`server-only` 를 안 붙인다**
(광고 규격 검사가 읽어야 하는데 그 파일은 서버 전용이 아니다. 처음에 값을
`ai-metadata.ts` 에서 가져갔더니 그 시험이 통째로 안 돌았다).

`apps/web/lib/ai-metadata.ts`

    AI_METADATA        파일에 적는 값. 못 박혀 있고 바뀌면 시험이 잡는다.
      software                 "FormWith AI"          윈도 파일 속성에 뜬다
      description              ASCII 한 줄            사람이 읽을 설명
      digitalSourceType        "trainedAlgorithmicMedia"   IPTC 표준값

    stampAiMetadata    EXIF 에 적는다. IFD0 의 Software·ImageDescription,
                       IFD2 의 UserComment 에 DigitalSourceType.
    hasAiMetadata      들어 있나. 시험과 확인용.

**EXIF 로 요건이 충족된다** — 조문은 형식을 지정하지 않는다. `digitalSourceType`
에 IPTC 표준값을 그대로 넣어 둔 것은, XMP 로 옮길 때 값을 다시 정하지 않기
위해서다. 지금 한 일을 버리지 않는다.

### 2.2 `markAsAi` 가 배지 설정을 보기 **전에** 찍는다

```
markAsAi(bytes)
  stamped = stampAiMetadata(bytes)     ← 늘 지나간다
  배지 꺼져 있으면 → stamped 를 준다
  배지 켜져 있으면 → stamped 위에 배지를 굽고 keepMetadata() 로 표시를 지킨다
  배지를 굽다 실패하면 → stamped 를 준다 (원본이 아니다)
```

부르는 자리를 `markAsAi` 하나로 둔 것은 기존 판단을 그대로 따른 것이다 — 부르는
곳이 넷이라(라이브러리·광고·포스터·카드뉴스) 각자 넣게 하면 언젠가 한 곳이 빠진다.

### 2.3 이미 새고 있던 것을 찾았다

**배지 합성 단계에 `keepMetadata()` 가 없었다.** sharp 는 기본으로 메타데이터를
안 옮기므로, 이 표시와 무관하게 **그동안 원본 생성기가 붙여 온 메타데이터도 배지를
구울 때마다 사라지고 있었다.** 이 작업의 곁가지로 고쳤다.


### 2.4 그림을 해치면서까지 적지는 않는다

표시를 넣는 단계는 그림을 **다시 굽는다.** 그래서 다시 구우면 잃는 것이 있는
입력은 **표시를 포기하고 원본을 준다.**

| 입력 | 표시 | 까닭 |
|---|---|---|
| PNG (8비트) | **넣는다** | 무손실이라 잃는 것이 없다 |
| 무손실 WebP (`VP8L`) | **넣는다** | 같다 |
| JPEG | 안 넣는다 | 2세대 손실 — 화소 90% 가 바뀐다 |
| 손실 WebP (`VP8` 규격) | 안 넣는다 | 무손실로 다시 구우면 3배가 된다 |
| 16비트 PNG | 안 넣는다 | 8비트로 떨어져 밴딩이 생긴다 |
| 움직이는 것 (APNG·WebP·GIF) | 안 넣는다 | 첫 장만 남는다 |

**제품이 실제로 만드는 것은 PNG 다**(`packages/pdp-core` 가 `"png"` 로 못 박았다).
그래서 요건은 그 길에서 채워진다. 손실 형식까지 덮으려면 **다시 굽지 않고**
컨테이너에 조각만 끼워야 한다 — PNG 는 `eXIf` 청크, JPEG 는 `APP1` 세그먼트.
그것이 XMP 와 함께 갈 다음 차례다(§6).

### 2.5 광고 소재도 표시를 받는다

광고 내보내기는 배지가 **꺼져 있으면 마무리를 아예 안 불렀다.** 그래서 소재가
표시 하나 없이 ZIP 으로 나갔다 — 사용자가 그것을 네이버·카카오에 올린다.

**배지를 끄는 것은 보이는 표기를 끄는 결정이지, 표시를 안 하겠다는 결정이 아니다.**
껐으면 배지 없이 파일 안 표시만 찍는다.

그 한 줄을 `lib/ad/finish.ts` 의 `finishForAd` 로 꺼냈다. 라우트 안에 두면
시험할 길이 없기 때문이다 — 그 핸들러는 인증·장부·라이브러리·`exportBatch` 를
다 거친다. 저장소가 같은 이유로 같은 일을 이미 했다(`image-encoding.ts` 의
`encode` 를 밖에서 넣게 둔 것).

**용량은 안 늘어난다.** 광고 경로가 먹이는 것은 이미 sharp 가 구운 파생본이라
다시 굽는 값이 ×1.000 이다(§1). 표시 자체는 660바이트, 200KB 예산의 0.3% 다.

## 3. 독립 검토가 찾은 것 — 내가 깨뜨린 것 하나를 포함한다

검토는 **REQUEST CHANGES** 를 냈다. 지적 전부를 내 손으로 다시 재서 확인했고,
추측이 아니라 측정으로 사실을 확인한 뒤 고쳤다.

### 3.1 가장 심한 것 — 내 변경이 광고 내보내기를 깨뜨렸다

`lib/ad/check.ts` 가 **「ICC 또는 EXIF 가 있으면 규격 위반」**으로 보고 있었다
(200KB 예산에서 메타데이터는 사치라는 판단). 그래서 표시를 넣기 시작한 날부터
**배지를 켠 광고 내보내기가 전부 규격 실패로 떨어졌다.**

**5152개 시험이 전부 초록인 채로 그랬다.** 광고 시험은 모두 가짜 `finish` 를
넣고, 내보내기 라우트 시험은 `exportBatch` 를 통째로 대신한다 — **진짜
`markAsAi` 가 진짜 `checkAgainstSpec` 을 만나는 자리가 저장소에 없었다.**

고친 것: 검사가 **남의** 메타데이터만 본다. 제31조가 요구하는 표시는 사치가
아니라 의무다. 그리고 그 둘이 실제로 만나는 시험을 만들었다.

### 3.2 나머지 지적과 조치

| 지적 | 확인 | 조치 |
|---|---|---|
| `withMetadata` 가 ICC 를 sRGB 로 갈아치운다 | 사실 (P3 → sRGB) | `keepMetadata().withExif()` 로 바꿨다. ICC 가 바이트 단위로 남는지 시험 |
| 손실 WebP 가 3배로 부푼다 | 사실 ×3.07 | 컨테이너를 보고 손실이면 안 건드린다 |
| JPEG q95 재압축이 손실을 쌓는다 | 사실 (화소 90%) | JPEG 를 형식 목록에서 뺐다 |
| 16비트가 8비트로 떨어져 저장 경로 가드를 무력화한다 | 사실 | 깊이 가드를 여기에도 뒀다 |
| 배지를 끄면 광고 소재가 표시 없이 나간다 | 사실 | §2.5 |
| 로컬 저장이 표시를 지운다 | 사실 | `keepMetadata()` 한 단어 |
| 한 장짜리 GIF 시험이 애니메이션 가드를 안 밟는다 | 사실 — 형식 가드에서 먼저 빠진다 | 시험 이름을 사실에 맞췄다 |
| 상세페이지 도구의 내려받기가 표시를 못 받는다 | 사실 | **안 고쳤다** — §6 |

**PNG 재인코딩이 광고 용량 예산을 넘긴다**는 지적은 **확인되지 않았다.** 검토는
+65% 를 쟀는데, 광고 경로가 먹이는 것은 이미 sharp 가 구운 파생본이라 ×1.000 이다
(§1). 다르게 인코딩된 PNG 를 넣었을 때의 값으로 보인다.

### 4.1 변이 시험이 잡은 내 시험의 결함 넷

**하나. 소스에서 `keepMetadata()` 를 찾는 시험은 아무것도 재지 않았다.**
`image-encoding.ts` 안에 그 호출이 **세 자리**(저장 인코더·썸네일·PNG 되돌리기)라,
한 자리를 지워도 나머지 둘이 시험을 통과시켰다. 자리 수를 세는 것으로 바꿔도
자리 수만 맞추면 통과한다. **실제로 구워서 읽는 시험 세 개로 바꿨다.**

**둘. `catch` 갈래를 밟는 입력을 진짜 그림으로는 만들 수 없었다.**
`badgePlacement` 가 자리 값을 전부 1 이상으로 가두어 1×1 도 2000×3 도 정상으로
지나가고, 깨진 바이트를 넣으면 표시 찍기가 **먼저** 실패해 원본과 구별이 안 된다.
실패를 실제 이음매에서 만들었다 — `badgeImage()` 가 그림이 아닌 바이트를 주게
했다. 운영기에서 이 `catch` 가 뜰 실제 사정과 같다.

**셋. APNG·움직이는 WebP 표본이 없어 애니메이션 방어가 검증되지 않았다.**
sharp 로는 움직이는 PNG 를 만들 수 없다. 저장소에 이미 있던 표본(ffmpeg 로 만든
5프레임 APNG, 손으로 짠 2프레임 GIF)을 `__tests__/fixtures/` 로 꺼내 두 시험이
한 벌을 같이 쓰게 했다.

**넷. 한 장짜리 GIF 로 「움직이는 그림」을 잰다고 적어 두었다.** 그것은 형식
가드에서 먼저 빠져서 **애니메이션 가드를 둘 다 지워도 초록이었다.** 이름이
거짓말을 하고 있었다(독립 검토가 찾았다). 이름을 사실에 맞췄다.

### 4.2 살아남은 둘은 시험의 결함이 아니다

**`if (!meta.width || !meta.height) return stamped;`** — sharp 가 `width` 를
`number | undefined` 로 주어 **타입을 좁히는 줄**이다. metadata 를 읽어낸 그림에는
늘 값이 있고, 못 읽으면 위에서 던져 `catch` 로 간다. **밟을 입력이 없다.**
그래도 `bytes` 가 아니라 `stamped` 를 준다 — 나중에 이 줄이 닿게 되는 날 그
갈래만 표시 없는 그림이 나간다.

**`if ((meta.pages ?? 1) > 1) return bytes;`** — 움직이는 WebP 는 최상위 청크가
`VP8X,ANIM,ANMF,ANMF` 라 화소가 `ANMF` 안에 있고, 그래서 컨테이너 판정이 그것을
「손실」로 보아 **아래 가드가 먼저 막는다.** 즉 이 줄을 빼도 결과가 같다.
**그래도 남긴다** — 컨테이너 판정이 언젠가 `ANMF` 안을 보게 되면 움직이는 무손실
WebP 를 막는 것은 이 줄 하나가 된다.

### 4.3 하나는 정말로 시험이 없다

**`lib/sns/runtime.ts` 의 로컬 저장 갈래.** `isLocalStoreEnabled()` 일 때만 타는
개발용 길이고, 시험하려면 임시 디렉터리와 저장 경로 설비가 필요하다. 고치기는
했지만(`keepMetadata()` 한 단어) **시험으로 못 박지 않았다.** 소스에서 글자를
찾는 시험은 §4.1 이 바로 그 함정이라 안 썼다.

운영 경로는 안전하다 — 거기는 바이트를 그대로 올리고 미리보기는 이미
`keepMetadata()` 를 쓴다. 이것을 확인하고 나서야 이 갈래를 개발용으로 한정할
수 있었다.

### 5.1 사용자가 받는 파일에서 실제로 읽힌다

저장 경로를 통째로 지나게 하고 단계마다 EXIF 를 꺼내 봤다.

| 단계 | 형식 | 읽히는 값 |
|---|---|---|
| 원본 PNG | png | 없음 |
| 표시 찍은 직후 | png | `FormWith AI` · 설명 · `DigitalSourceType=…` |
| 저장된 것 | webp | 셋 다 |
| 내보낸 PNG | png | 셋 다 |
| 썸네일 | webp | 셋 다 |

표시가 붙는 값은 120KB PNG 에 663바이트(0.55%)다.

## 6. 안 한 것 — 남은 일

| | 왜 미뤘나 |
|---|---|
| **상세페이지 도구의 내려받기** | 가장 큰 구멍이다. 겹칠 것이 없으면 제공사 바이트를 그대로 내려받고(`PdpEditor.tsx`), 겹칠 것이 있으면 html2canvas 가 JPEG 로 다시 굽는다 — **캔버스 출력에는 EXIF 가 구조적으로 없다.** 서버를 한 번 거치게 하거나 내려받기 자리를 서버로 옮겨야 한다. 서버 쪽 표시로는 닿지 않는다. |
| 손실 형식(JPEG·손실 WebP)의 표시 | 다시 굽지 않고 컨테이너에 조각만 끼워야 한다(PNG `eXIf`, JPEG `APP1`). XMP 작업과 같은 성질이라 함께 한다. |
| XMP / IPTC `DigitalSourceType` | sharp 가 XMP 를 못 쓴다(§1). 구글·메타의 AI 라벨이 읽는 값이 이것이라, 그 라벨이 필요해지면 그때 얹는다. |
| 배지를 끈 상태의 별도 고지 | 제31조는 **안 보이는 방법만 쓸 때 별도 고지 1회 이상**을 요구한다. 배지를 끄면 우리가 그 상태가 된다. 내려받는 자리에 고지를 붙여야 한다. |
| 약관에 「AI 표시를 지우지 않는다」 조항 | 사용자가 「약관 관련해서는 지금 다른곳에서 검토중」이라 했다. 그 검토가 끝난 뒤 넣는다. |
| jpg 광고 규격에 배지 | **이 작업 전부터 깨져 있다.** `markAsAi` 가 늘 PNG 로 끝나므로 배지를 켜면 jpg 규격이 「형식이 다릅니다」로 떨어진다. 배지 기본값이 꺼짐이라 아무도 안 밟았다. 배지 작업의 몫으로 남긴다. |

**배지 크기는 줄이지 않았다.** 사용자가 「정말 살짝 보일듯 말듯」을 요구해 재
보았는데, 1024² 에서 배지는 54×12px 로 **그림 면적의 0.05~0.06%**, 글자 높이 약
6px, 불투명도 0.15 다. 더 줄이면 제31조의 「사람이 인식할 수 있는 방법」에서
벗어난다 — 이미 그 한계 근처다.
