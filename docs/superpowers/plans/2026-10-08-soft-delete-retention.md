# 회원이 지워도 보관하기 (2026-10-08 계획)

## 사용자 결정 (원문 요지)

- 회원 화면에서는 지운 것이 사라진다. **데이터베이스와 파일에는 결과물·참고 이미지·캐릭터 등 전부 남긴다**
  — 「혹시 모를 법률적 대응, 증거 자료로 필요시 사용하기 위함」
- 보관 기간 **6개월**, 지나면 자동 삭제
- 관리자(9843ohs·ai.dev)는 **보기 + 완전 삭제**
- **탈퇴는 지금 구조 그대로**(탈퇴하면 함께 삭제) — 「기술적으로 많은 변경이 필요하면 기존 구조에 맞게」

## 지금 상태 (조사, 2026-10-08)

- 회원이 지우면 **전부 즉시 하드 삭제**(행 + 저장소 파일). 상세페이지만 `deleted_at` 을 찍지만 같은 요청에서 내용·파일을
  비운다(`lib/pdp/documents/http.ts` completeDelete → purge)
- 처리방침이 **정면으로 어긋난다** — §1 「이용자가 해당 자료를 삭제하거나 탈퇴할 때까지」, §4 「자료를 삭제하거나
  탈퇴하면 회사가 보관하는 자료를 파기합니다」 → **같은 배포에 방침 수정 필수**
- 운영 워커는 masked(꺼짐) → 6개월 자동 삭제는 워커에 못 붙인다
- 탈퇴(`lib/membership/withdraw-account.ts`): 상세페이지 문서 정리 → 라이브러리 버킷 폴더 삭제 → 계정 삭제(행 연쇄 삭제)
  또는 돈 기록이 있으면 `member_withdraw`(개인 칸 비움) — 이번에 바꾸지 않는다

## 공통 설계

- 표마다 `deleted_at timestamptz`, `deleted_by uuid` 칸. 회원 삭제 = 이 칸만 채운다, **파일은 지우지 않는다**
- **회원에게 다시 보이는 길을 막는 것이 핵심 위험**이다. 두 겹으로 막는다
  1. DB 접근 규칙(RLS): 회원이 읽는 정책에 `deleted_at is null` (세션 클라이언트로 읽는 길 전부)
  2. 서비스 키로 읽는 길(라이브러리·캐릭터·참고 이미지 목록, 단건, 파일, 고르기 창, 광고 원본, 첫 화면 갤러리 등)은
     각 질의에 `.is("deleted_at", null)` — 단계 시작 때 **읽는 길 전체 목록**을 만들고 길마다 시험을 둔다
- 관리자 「전체 회원 보기」: 지운 것도 보이고 **「회원이 삭제함 · 날짜」** 표시, 열어 보기·내려받기·**완전 삭제**
- 관리자가 지우는 것(살아 있는 것이든 회원이 지운 것이든)은 지금처럼 **완전 삭제**
- 크레딧·저장 상한 세기는 지운 것도 센다(지금과 같다 — 지웠다 만들기로 상한을 피하지 못하게)

## 1단계 — 만든 결과물 (카드뉴스·쉽게·다양하게·상세페이지·리디자인·광고소재)

- 표: `sns_projects`, `poster_projects`, `library_items`(+`library_images` 는 부모를 따른다), `pdp_documents`(칸 있음)
- 회원 삭제 4길을 「표시만」으로: `api/sns/projects/[id]`, `api/poster/projects/[id]`, `api/library` DELETE,
  `api/pdp/documents/[id]`(completeDelete·purge 를 회원 삭제에서 빼고, 관리자 목록에서 `deleted_at` 거르기를 뺀다)
- 처리방침·화면 안내 문구 수정(아래 초안) — **이 단계와 같은 배포**
- 시험: 읽는 길마다 「회원이 지운 것은 회원에게 안 보인다」, 관리자에게는 표시와 함께 보인다, 완전 삭제는 파일까지

## 2단계 — 재료 (참고 이미지·캐릭터·쉽게 대화 기록)

- 표: `reference_images`(+세트 항목), `characters`(+`character_views`), `easy_conversations`(+`easy_messages`)
- 캐릭터를 지우면 함께 지우던 각도 참고 이미지도 「표시만」
- 지운 캐릭터 이름은 다시 쓸 수 있게(이름 겹침 검사에서 지운 것 빼기)
- 관리자 화면 「회원이 삭제한 자료」 목록(보기·완전 삭제)

## 3단계 — 6개월 자동 삭제

- 서버 안 전용 주소(`/api/internal/purge-deleted`, 비밀 머리 `CRON_SECRET` — 운영 설정에 새 값 필요)를
  **systemd 타이머가 하루 한 번** 부른다(워커는 꺼져 있어 못 씀). 지운 지 6개월 지난 것을 행·파일 모두 완전 삭제
- 한 번에 지우는 양에 상한, 몇 건 지웠는지 서버 기록
- 타이머 설치는 서버 설정 변경이라 `docs/DEPLOY.md` 「서버 설정 바꾸기」에 절차를 적고 그대로 한다

## 처리방침 문구 초안 (변호사 확인 필요)

> 아래는 초안이다. **보관 근거·고지 방법·시행 시점(사전 공지 필요 여부)은 법률 판단이라 변호사 확인을 받는다.**

- **§1 표 「AI 콘텐츠 제작·보관」 보유기간**
  - 지금: 이용자가 해당 자료를 삭제하거나 탈퇴할 때까지
  - 초안: 이용자가 해당 자료를 삭제할 때까지. 삭제한 자료는 삭제일로부터 6개월간 별도 보관 후 파기(아래 2-1).
    회원 탈퇴 시에는 즉시 파기
- **§2 뒤에 「2-1. 이용자가 삭제한 자료의 보관」 신설**
  - 회사는 이용자가 삭제한 생성 결과물·업로드 자료·작업 기록을 권리침해 신고 처리, 분쟁 대응 및 부정 이용 확인을
    위하여 삭제일로부터 6개월간 보관합니다. 보관 중인 자료는 이용자 화면에 표시되지 않으며 다른 목적으로 이용하지
    않고, 회사가 지정한 관리자만 열람할 수 있습니다. 보관 기간이 지나면 지체 없이 파기합니다. 회원 탈퇴 시에는
    보관 기간과 관계없이 즉시 파기합니다.
- **§4 국외 이전 「보유·이용기간」**
  - 지금: …이용자가 자료를 삭제하거나 탈퇴하면 회사가 보관하는 자료를 파기합니다.
  - 초안: …이용자가 자료를 삭제하면 2-1에 따른 보관 기간(6개월)이 지난 뒤, 탈퇴하면 즉시 회사가 보관하는 자료를
    파기합니다.
- 시행일·변경 내용 줄 갱신, 화면 문구(지우기 확인 창 「되돌릴 수 없습니다」 등)는 「이 화면에서는 되돌릴 수 없습니다」
  처럼 사실에 맞게 — 단계 1 에서 목록을 만든다
- 정본은 `apps/web/app/_landing/legal/documents.ts`, 손으로 `frontend/법률문서/` 에 옮긴다(그 파일 머리말)

## 위험·비용

- 회원이 지운 것이 다시 보이는 길이 하나라도 남으면 사고 → 읽는 길 전체 목록 + 길마다 시험 + 독립·보안 리뷰
- 저장 용량이 6개월치만큼 늘어난다(파일을 안 지우므로)
- 처리방침은 법률 판단 → 변호사 확인 전에는 「초안」으로만 둔다. **방침 수정 없이 1단계를 배포하지 않는다**

- 단계마다: `pnpm -r typecheck`, 전체 시험, `test:readiness-fixes`, 마이그레이션은 로컬 Postgres 로 적용·되돌림 확인
