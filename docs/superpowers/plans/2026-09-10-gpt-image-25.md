# gpt-image-2.5 로 옮긴다

**승인**(2026-09-10): 사용자가 두 모델의 결과물을 직접 보고 「퀄리티 차이가 많이
난다」고 판단해 교체를 승인했다. 절감이 아니라 **화질이 이유다.**

## 0. 무엇을 재고 이 문서를 쓰는가

추측으로 정하지 않았다. fal 에 실제로 34번 호출해 값을 쟀다(약 $1.2).

### 0.1 규격 — 네 제약이 그대로다

| 시험 | 결과 |
|---|---|
| 우리가 쓰는 크기 8종 | **요청과 정확히 일치** |
| 비율 4:1 | **422 거부** — `aspect ratio 4.00:1 exceeds the maximum supported 3:1` |
| 16의 배수 아님 1023×1024 | 1008×1024 로 자동 보정 |
| 최소 픽셀 미만 640×640 | 816×816 으로 자동 보정 |
| 최대변 초과 4096×2048 | 3840×1920 으로 자동 보정 |
| 최대 픽셀 초과 3840×2400 | 3632×2272 로 자동 보정 |

**`pixelSizeLimits` 를 그대로 쓴다.** 2.5 는 거부 대신 조용히 보정하므로,
미리 맞춰 보내는 지금 방식이 오히려 더 안전하다 — 보정되면 사용자가 요청한
크기와 다른 그림을 받는데 아무도 모른다.

**3:1 상한이 안 풀렸다. 광고 조립 엔진은 그대로 필요하다.**

### 0.2 화질·속도 — 같은 프롬프트·같은 레퍼런스로 2회씩

실제 카드뉴스 프롬프트(3,690자)와 실제 레퍼런스 그림, 1088×1360.

| | 한글 | 크기 | 시간 | 장당 |
|---|---|---|---|---|
| 현재 `2/high` | 안 깨짐 | 정확 | 121·129초 | $0.178 |
| `2.5 flare/high` | 안 깨짐 | 정확 | **22·24초** | $0.041 |
| `2.5 flare/max` | 안 깨짐 | 정확 | **48·50초** | $0.165 |
| `2.5 sunburst/max` | 안 깨짐 | 정확 | 99·91초 | $0.165 |

**넷 다 한글이 하나도 안 깨졌다.** 「모델이 그린 한글은 자주 깨진다」는 기존
기록이 2.5 에서는 맞지 않는다. 다만 **표본은 모델당 2개다.**

**지시 준수는 sunburst 가 낫다.** 처음엔 「각자 하나씩 지켰다」로 읽었는데
프롬프트 원문이 그 둘을 같은 무게로 두지 않는다.

```
image-prompt.ts:227  "If the copy needs more room, use additional lines…"   허용
image-prompt.ts:352  "Give every non-empty copy field … explicit visible placement"  요구
```

**줄을 늘리는 것은 명시적으로 허용된 동작이고, 배치는 요구다.** 그러면 이렇게
읽힌다 — sunburst 는 어긴 것이 없고, flare 는 `:352` 를 어겼다(2회 모두).

**다만 표본이 모델당 2개다.** §0.1 의 크기·비율·거부는 결정적이라 2회로
단정되지만, 배치 준수는 확률적 성질이라 2회로 단정할 수 없다. 화질도 같다.

### 0.3 단가 구조

모든 크기에서 **`max` = `high` × 4.00 배**로 일정하다. `2.5/max` 는 현재보다
3~7% **싸다**(16:9 만 0.3% 비싸다).

### 1.1.1 미리보기는 fal 을 안 부른다 — 품질을 건드리면 안 된다

초판은 「버리는 그림에 본편 값을 쓴다」로 적고 `low` 로 낮추려 했다. **틀렸다.**

```
lib/layout/preview-service.ts:11  "fal 을 부르지 않는다. 그림 칸은 회색 상자로 두고…"
                            :33  composeCard({ …, preview: true })   로컬에서 PNG
                            :40  estimateSlots(…)                    값만 계산
```

두 라우트의 `modelId`(`layout/preview/route.ts:14`, `deck-preview/route.ts:21`)는
오직 **화면에 보여 줄 예상 비용**을 만드는 데 쓰인다.

**품질을 낮추면 그림은 하나도 안 싸지고 화면의 예상 비용만 1/33 로 표시된다.**
사용자는 $0.005 를 보고 누르는데 `generate/route.ts:53` 은 `project.modelId`
(= `max`)로 `creditUnits` 를 예약한다 — **화면과 장부가 갈린다.**
`generate/route.ts:46` 주석이 명시적으로 금지하는 상황이다.

→ 두 라우트의 `.default("gpt-image-2")` 는 **새 기본 id 로만** 바꾸고 품질은
안 건드린다.

### 1.2 안 건드리는 것

- **광고 배경 제거**(`birefnet/v2`) — gpt 계열이 아니다
- **리디자인** — fal 을 안 쓴다. OpenAI·Google 을 직접 부른다
- **캐릭터 photoreal** — `nano-banana-pro` 다
- **광고 조립 엔진** — 3:1 상한이 그대로라 여전히 필요하다

### 1.3 sunburst 는 선택지로만 넣는다

기본값으로 안 쓴다. 근거는 **둘**이다.

**① 표본이 모델당 2개다.** 배치 준수는 크기·비율과 달리 확률적 성질이라
2회로 단정할 수 없다.

**② 화질 등급이 같은데(둘 다 `max`) 속도가 2배 차이다.**
```
현재 2/high        121·129초
sunburst/max        99· 91초   →  21% 개선
flare/max           48· 50초   →  2.5배 개선
```
카드 8장이면 sunburst 약 13분, flare 약 6.5분이다.

**배치는 틀(레이아웃)이 구조적으로 푼다** — 틀이 붙은 카드는 헤드라인을 우리가
서버에서 그린다(`lib/layout/compose.ts:114` `drawText`, `layout-core/estimate.ts:8`
「칸 하나가 fal 요청 하나다」 — 모델에는 그림 칸만 시킨다).

**단 틀은 옵트인이다.** 사용자가 세트나 뼈대를 붙여야 하고
(`api/sns/layout/apply/route.ts:26-31`), 안 붙인 카드는
`app/sns/cost-estimate.ts:72-78` 의 fallback 으로 떨어져 모델이 글자를 그린다.
**그러니 이것은 배제 근거가 아니라 완화 수단이다.**

### 1.3.1 선택지는 카드뉴스·이미지 만들기에만 넣는다

**상세페이지·캐릭터에는 넣지 않는다.** 그 둘은 동기로 돈다.

```
api/pdp/images/batch/route.ts:28   maxDuration = 300   (images·characters/views 도 같음)
pdp-core/types.ts:176-181          "GPT 는 6장에 288초… 3장씩 나눈다"
→ sunburst 95초 × 3장 = 285초. 상한까지 15초
```

카드뉴스·이미지 만들기는 fal 큐를 쓴다(`lib/fal/queue.ts:21` `client.queue.submit`)
라 이 제약이 없다.

### 1.3.2 되돌릴 신호를 미리 정한다

틀 없는 카드에서 헤드라인 위치 불만이 나오면
```
1단계  그 작업에 틀을 붙이게 안내한다 (compose.ts 가 직접 그린다)
2단계  그래도 안 되면 sunburst 를 골라 쓰게 한다
3단계  반복되면 기본을 sunburst 로 옮긴다
```

## 2. 어떻게 바꾸는가

### 2.1 교체가 아니라 추가다 — 목록은 **늘리기만 한다**

`gpt-image-2` 를 남기고 새 둘을 더한 뒤 `isDefault` 만 옮긴다.

**옛 모델을 못 지우는 이유와 새 모델을 못 지우는 이유가 같다.** 저장된 작업이
그 시점의 id 를 들고 있고(`202608310002_sns.sql:13,30` `model_id text not null`,
check·FK 없음), `modelById`(`models.ts:99-103`)가 모르는 id 에 **던진다.**

```
카드뉴스 만들기·낱장 다시 만들기   cost-estimate.ts:44        → 500
카드 실제 생성                    lib/sns/queued-flow.ts:183 → throw
상세페이지                        pdp.image-provider.ts:50   → 런타임 오류
이미지 만들기                     poster-core/pricing.ts:75  → 거절 문구(500 아님)
```

### 2.1.1 되돌리기는 **세 줄**이다

```
1. packages/sns-core/src/models.ts              isDefault 를 gpt-image-2 로
2. apps/web/app/api/sns/projects/schema.ts:64   .default 만 — enum 목록은 그대로
3. apps/web/app/sns/new-client.tsx:44           손으로 박힌 초기값
```

**1번만 하면 카드뉴스는 안 되돌아간다**(3번이 하드코딩). **3번만 하고 2번을
빠뜨리면** 화면은 옛 모델을 보내는데 서버 `.default` 가 새 모델이라 모델
미지정 요청만 새 모델로 간다.

**이미지 만들기·광고·레이아웃 추정은 1번 하나로 따라온다** —
`poster/new-client.tsx:98`·`poster-core/schemas.ts:51`·`layout-client.tsx:64`
가 전부 `isDefault`·목록에서 파생된다.

상세페이지까지면 넷째 줄 `pdp-core/types.ts:144`.
캐릭터까지면 **두 곳** — `pdp.character.ts:537-539` 와
`CharacterStudio.tsx:404-408`. 같은 표가 서버·화면에 한 벌씩 있다
(화면 쪽 주석: 「서버의 selectCharacterModel 과 같은 표다」).

**`z.enum` 목록에서 새 id 를 빼지 않는다.** 빼면 새 모델로 만든 작업을 화면이
열어 저장된 `modelId` 를 되보내는 순간 400 이 난다 — 되돌리기가 **옛 작업을 못
여는 사고**로 바뀐다.

### 2.1.2 이미 만들어진 작업은 안 따라온다

되돌린 뒤에도 옛 작업의 「다시 만들기」는 **저장된 새 모델로 나간다**
(`queued-flow.ts:183` `modelById(project.modelId)`). 그 작업의 다른 카드와
결을 맞춰야 하니 맞는 동작이지만, 되돌린 사람에게는 「되돌렸는데 왜」로 보인다.

**일괄 전환 경로는 없다.** 운영자가 `model_id` 를 직접 UPDATE 해야 한다.

### 2.2 quality 가 지금은 상수다

```ts
// sns-core/generate.ts:96 — 지금
input.quality = "high";
```

모델·용도와 무관하게 박혀 있다. 이것을 **모델이 정하는 값**으로 옮긴다.
미리보기는 `low` 로 내려야 하는데, 지금 구조로는 그 자리만 다르게 줄 수 없다.

## 3. 위험

| 위험 | 대응 |
|---|---|
| DB `model_prices` 가 새 id 를 모른다 | **막히지는 않는다. 조용히 틀린다.** 아래 §3.1 |
| 표본 2개로 화질을 단정 | 옛 모델을 남긴다. 되돌리기 한 줄 |
| 미리보기 `low` 가 최종본과 너무 다름 | 상수 하나로 둔다. 바꾸려면 그 한 줄 |
| 3:1 상한을 잊고 광고를 손댐 | 광고 코드는 이 작업에서 **안 건드린다** |

### 3.1 단가표가 새 id 를 모르면 — 막히는 게 아니라 **$0 으로 잡힌다**

직접 확인했다.

```
generation_events.model      text · check 제약 없음 · FK 없음  → 쓰기는 안 막힌다
admin_cost_summary 외 4곳    left join model_prices
                             billable_images * coalesce(p.unit_cost_usd, 0)
```

즉 새 모델로 만든 그림은 **비용 0원으로 집계된다.** 2026-09-08 에 카드뉴스·
이미지 만들기가 장부에 한 줄도 안 남아 약 $8.96 이 밖에 있었던 일과 같은
종류다 — 그때는 행이 없었고 이번에는 단가가 0 이다. **화면에는 아무 오류도
안 뜬다.**

**그래서 마이그레이션을 코드 배포보다 먼저 적용한다.** 순서가 뒤바뀌면 그
사이에 만든 그림의 비용이 영영 0 으로 남는다(집계가 조회 시점에 조인하므로,
단가를 나중에 넣으면 과거 행도 함께 채워진다 — 이 점은 다행이다).

### 2.4 단가표는 여섯 행을 다 채운다

`pickRow`(`models.ts:120-129`)는 **비율이 가장 가까운 행**을 고른다. 실측은
1088×1360 하나뿐이다(→ `1024×1536` 행).

**상세페이지는 크기를 안 넘긴다** — `credit-cost.ts:45` 의
`DEFAULT_SIZE = 1024×1024` 를 쓴다(`:66`). 그 행이 틀리면 상세페이지 차감이
통째로 틀린다.

§0.3 의 「`max` = `high` × 4.00 배」로 여섯 행을 유도하고, **어디까지가
실측인지 표 주석에 남긴다.** 지금 `models.ts:33` 이 「fal 모델 페이지 공표값
(2026-08-31 확인)」으로 출처를 적어 두는 형식을 따른다.

### 2.5 배열 순서가 세 곳에서 의미를 갖는다

```
poster-core/pricing.ts:116        find(m => m.pixelSizeLimits)  ← 첫 픽셀 모델로 크기 계산
app/create/ModelPicker.tsx:55     IMAGE_MODELS[0]!.id           ← 「기본」 배지
layout-core/image-request.ts:145  planSlotImage — gap 동점 시 배열 순서
```

flare 와 gpt-image-2 는 한계가 같아 **항상 동점**이다. 그러니 **새 모델을 배열
맨 앞에 두고 gpt-image-2 를 뒤로** 옮긴다. 세 곳이 전부 새 기본과 맞는다.

### 2.6 광고가 기본 모델의 픽셀 한계 위에 올라탄다

`poster-service.ts:88` `adMasterFor` → `poster/…/generate/route.ts:138` →
`poster-core/generate.ts:141` `sizeFromSource(job.sourceSize, model)`.
`model` 은 사용자가 고른 것 = 기본값이다.

`lib/ad/specs.ts:41` 이 `ad-3x2` 를 1536×1024 로 정한 근거가 바로 이것이다 —
「`sizeFromSource` 가 이 값을 그대로 돌려준다」.

**새 모델의 `pixelSizeLimits` 가 한 글자라도 다르면 `AD_MASTERS` 여섯 개의
실제 크기가 조용히 바뀐다.** 지금 자물쇠는 gpt-image-2 의 한계만 고정해
못 잡는다(`ad-isolation-lock.test.ts:128-135`).

→ **「`pixelSizeLimits` 를 가진 모든 모델의 한계가 서로 같다」**는 단정을
그 자물쇠에 한 줄 더한다. §0.1 에서 실측으로 확인한 사실이다.

## 4. 어떻게 확인하는가

- 새 모델로 실제 생성 — 크기·한글·시간
