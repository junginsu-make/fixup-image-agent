# 라이브러리 정리 — 필터 한 줄·그림 없는 작업 숨기기·광고소재 저장 (2026-10-08)

## 사용자 요청 (원문 요지)

1. 위 탭 [작업물·참고 이미지·캐릭터] 과 아래 필터 [전체…리디자인] 을 **한 줄로 합친다**
2. 그림 없는 작업은 미리보기 카드로 보일 필요 없다. 크레딧이 안 나갔다면 보여 줄 필요도 없다
   → **라이브러리에서 안 보이게** 한다(별도 목록 없음)
3. **광고소재로 만든 이미지도 한 묶음으로 라이브러리에 저장**한다

## 조사로 확인한 사실 (운영, 2026-10-08)

- 그림 없는 카드 13건: 상세페이지 7(사진 올린 뒤 30초 자동 저장으로 문서가 생기고, 다시 시작하면
  앞 문서가 남음), 다양하게 4(기획만), 카드뉴스 2(원고만). 실패한 그림이 저장되는 것은 아니다
- **크레딧은 그림이 실제로 나올 때만 나간다.** 기획·분석·원고 = 0, 실패 = 0(돌려줌).
  그림 없는 13건은 모두 0크레딧(`credit_consumptions` 대조)
- 크레딧 사용은 작업과 무관하게 `generation_events` 에 남고, 설정 › 사용 기록이 보여 준다
- 광고 내보내기(`api/ad/export`)는 결과를 응답(base64)으로만 주고 어디에도 저장하지 않는다.
  `library_items.tool` 은 `create`·`redesign` 만 허용(DB check)

## 1단계 — 필터 한 줄 + 그림 없는 작업 숨기기 (화면만, DB 변경 없음)

**모양**

```
[전체 N] [쉽게 N] [다양하게 N] [카드뉴스 N] [광고소재 N] [상세페이지 N] [리디자인 N] [캐릭터] [참고 이미지]
```

- `page.tsx`: `Tabs` 3개를 없애고 한 줄 필터 하나가 무엇을 보일지 정한다
  - 캐릭터 → 지금 `CharactersTab` 그대로, 참고 이미지 → 지금 `ReferencesTab` 그대로
  - 나머지 → `WorksTab` 에 고른 필터를 넘긴다
- 작업물 안의 「캐릭터」 필터(캐릭터 만들기 결과)는 없앤다. 예전에 라이브러리에 저장된 캐릭터 결과
  (운영 1건, 원본 캐릭터는 이미 지워짐)는 빼면 어디서도 안 보이므로 「전체」에 「캐릭터」 이름표로 보인다
- 사용 설명서(라이브러리·광고)를 새 화면에 맞춘다(1단계 독립 리뷰 MEDIUM). 배포 뒤 도우미 색인을 다시 만든다
- 광고소재 단추: 1단계에서는 지금처럼 "아직 저장되지 않습니다" 안내, 2단계에서 켠다
- **그림 없는 작업은 라이브러리에 안 보인다**(사용자 결정 2026-10-08: 크레딧이 안 나갔으면 보여 줄
  필요 없다). 그림이 한 장도 없고 표지도 없는 작업을 목록에서 뺀다 — 별도 목록도 두지 않는다
  - 근거: 그림 없는 작업은 크레딧 0(위 사실). 크레딧 사용은 설정 › 사용 기록에 그대로 남는다
  - 이어서 하기 길은 각 기능 화면에 있다(상세페이지 불러오기, 카드뉴스·다양하게 목록)
  - 달라지는 점: 만드는 도중인 작업은 첫 그림이 나와야 보인다
- 개수는 버튼에 붙는다(지금과 같은 방식). 빠진 작업은 개수에도 안 든다

**바뀌는 파일**: `library/page.tsx`, `library/works-tab.tsx`, `library/work-filter.ts`,
테스트 `__tests__/work-filter.test.ts` 고침 + 새 테스트(그림 없는 작업 빼기)

**지키는 것**: 작업을 지우지 않는다(보이는 곳만 바뀜). 이어서 하기 길(상세페이지 불러오기,
카드뉴스·다양하게 목록)은 그대로.

## 2단계 — 광고소재 결과를 한 묶음으로 저장 (DB 변경 있음)

- 마이그레이션: `library_items.tool` 허용값에 `'ad'` 추가 (운영 SQL 은 배포 때 손으로 적용)
- `api/ad/export/route.ts`: 장부를 닫은 뒤, 규격대로 나온 그림(`status ok`)을 **한 번 실행 = 한
  작업물**로 `saveLibraryItem({ tool: "ad", origin: "ai", images })` 저장
  - 저장이 실패해도 내보내기 결과는 그대로 준다(응답에 "라이브러리에 저장하지 못했습니다" 안내만)
  - 제목: 원본 그림 제목 + "광고 규격 N개"
- 타입 넓힘: `server-library.ts`, `library-works.ts`, `work-filter.ts`, `admin/works/store.ts`,
  `lib/library.ts`(다른 화면의 불러오기 창에서 광고 결과가 "상세페이지"로 찍히지 않게)
- 광고소재 단추의 "아직 저장되지 않습니다" 를 지우고 실제 개수로 켠다
- 광고 화면에 "라이브러리에 저장했습니다" 한 줄

**확인할 위험**: 규격이 많으면 저장할 장수가 늘어 응답이 느려진다 → 실제 최대 규격 수로 시간을
재고, 느리면 응답 뒤 저장으로 바꾼다.

### 2단계 독립 리뷰·보안 리뷰 뒤 더한 것

- 회원당 한 시간 30번까지만 라이브러리에 저장(보안 MEDIUM — 자르기만 하는 내보내기는 0크레딧이라
  장부가 막지 않는다). 넘으면 결과는 주고 저장만 건너뛴다
- `asIs` 는 PNG·JPEG 만 받는다(보안 LOW)
- 광고 화면 01 원본 목록에서 광고 결과를 뺀다(리뷰 MEDIUM 1 — 원본이 아니다)
- 규격 이름·크기·형식을 과정(`data`)에 남겨 「과정 보기」가 어느 그림이 어느 규격인지 보인다,
  작업물 화면에서 받을 때 실제 확장자(.jpg/.png)로 이름 붙인다(리뷰 MEDIUM 2)
- 긴 제목은 꼬리(「· 광고 규격 N개」)가 들어가게 앞을 줄인다(리뷰 LOW 3)
- `lib/library.ts`(옛 불러오기 목록)는 넓히지 않았다 — 광고 작업이 `pdp` 로 찍히지만 그 목록을 그리는
  화면이 없다(리뷰 LOW 4)
- 시간(리뷰 MEDIUM 3): 뽑을 수 있는 규격 17개, 압축 안 되는 최악 그림 8.2MB 기준 로컬 작은 사본 340ms·
  base64 2ms. 업로드 시간은 운영에서 1회 내보내기로 잰다. 느리면 응답 뒤 저장으로 바꾼다
- 운영 적용 전 `select conname from pg_constraint where conrelid='public.library_items'::regclass;` 로
  제약 이름을 확인한다(리뷰 LOW 5)
