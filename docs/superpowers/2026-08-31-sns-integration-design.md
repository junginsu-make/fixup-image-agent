## 한 줄 요약

`detail-page-studio` 를 **새 저장소로 복제**하고, 거기에 **수집 미디어 · 수집함 · 카드뉴스 만들기**
세 시스템을 더한다. **로그인·회원가입·Supabase 는 상세페이지 스튜디오 것을 그대로 공유하고,
GitHub 저장소와 EC2 배포만 나눈다.**

## 왜 이렇게 하나

기존 CardForge(`instargram automation`)를 고치지 않고 옮기는 이유는 실측으로 확인된 것들 때문이다.

| 확인된 문제 | 근거 |
|---|---|
| 속지가 전부 표지처럼 나온다 | 저장된 프롬프트에 `Match its palette... exactly. Only the content differs.` |
| 참조 이미지를 안 닮는다 | 프롬프트 1,715자 중 참조 규칙 330자, 나머지가 그것을 덮음 |
| 그림 AI 가 나노바나나였다 | 사용 기록 65건 전부 `nano-banana-*`, `gpt-image-2` **0건** |
| 목적(goal) 을 이미지 모델에 보냄 | `Narrative rule: 결론을 먼저 말하고...` 전송 중 |
| 재생성할수록 멀어진다 | 검수 반려 지시 450자가 참조 규칙보다 길게 뒤에 붙음 |
| 손으로 쓴 CSS | shadcn/ui·Tailwind 없이 클래스를 직접 관리 |

**그리고 결정적으로 — 같은 문제를 옆 프로젝트가 한 달 전에 이미 풀었다.**

> **2026-07-30 상세페이지 참조 이미지 정책 (사용자 결정)**
> "첨부된 이미지 분석을 하지 마세요 … 이미지 생성 모델에 그냥 첨부해서 생성하게 하는 게 좋다"
>
> ```
> 그대로 지킨다      제품(anchor) · 인물(person)   형태·비율·색·라벨·얼굴
> 비슷하게 따라간다   디자인 레퍼런스(style)        레이아웃·분위기·서체
> 우선순위          제품 = 인물  >  스타일  >  장면 지시
> ```
>
> **fal API 는 이미지별 역할 라벨을 받지 않는다.** `image_urls` 배열로만 보낸다.
> 코드의 역할 구분은 우리 안에서만 유효하고, **모델에게는 프롬프트 문장이 유일한 전달 수단**이다.

이 규칙을 카드뉴스에 그대로 적용한다. 같은 실수를 두 번 하지 않는다.

# 1. 범위와 전제

## 이번에 만드는 것

```
① 수집 미디어    소스 등록 · 주기 수집 · 워커
② 수집함        수집한 후보 검토 · 제작으로 넘기기
③ 카드뉴스 만들기  ← 가장 크다
④ 포스터 만들기   설계·계획이 이미 있다
```

`/sns` 아래 두 탭으로 둔다.

```
SNS 만들기
  ├ 카드뉴스    여러 장. 글이 중심
  └ 포스터      한 장. 타이포와 구도가 중심
```

**둘은 만드는 방식이 다르다.** 카드뉴스는 글을 먼저 확정하고 그림을 그리고,
포스터는 슬롯을 채운 뒤 변형을 여러 장 뽑아 고르고 고친다. 화면을 억지로 합치지 않는다.

공유하는 것: fal 클라이언트 · 모델 레지스트리 · 라이브러리(참고 이미지) · 업로드 · 비용 기록
공유하지 않는 것: 기획 · 프롬프트 · 검수 · 화면

## 저장소와 배포 — 개인과 회사를 가른다

| | 개인 (`detail-page-studio`) | 회사 (`Fixup Image Agent`) |
|---|---|---|
| GitHub 저장소 | 기존 | **새로 판다** |
| EC2 배포 | 기존 인스턴스 | **새 인스턴스** |
| **Supabase** | | **같은 것을 쓴다** |
| **회원·로그인** | | **같다** — 계정이 그대로 통한다 |
| **라이브러리** | | **같다** |

**저장소와 서버만 나눈다. 데이터와 계정은 하나다.**
상세페이지에서 쓰던 계정으로 SNS 만들기에 그대로 들어간다.

회원가입은 상세페이지와 **완전히 동일**하다 — 가입 개방 + Turnstile + 이메일 인증 + 자동 활성화.
새로 만들지 않는다. 복사한 마이그레이션이 이미 그 구조를 담고 있다.

**새 저장소는 `detail-page-studio` 를 복사해 씨앗으로 삼되, 이후로는 별개다.**
원본을 참조하지 않고, 원본이 바뀌어도 따라가지 않는다.

**기존 CardForge 데이터(수집 후보 86건·카드 프로젝트·팀)는 가져오지 않는다.** 사용자 결정이다.

### 기존 스키마를 따른다 — 실제로 읽고 맞춘 것이다

```sql
-- 씨앗 저장소의 library_items (202607280001_server_library.sql)
user_id  uuid not null references public.profiles(id) on delete cascade
tool     text not null check (tool in ('create', 'redesign'))
```

**새 테이블도 이 규약을 따른다.**

| 항목 | 규약 |
|---|---|
| 소유자 칸 이름 | **`user_id`** (`owner_id` 가 아니다) |
| 참조 대상 | **`public.profiles(id)`** (`auth.users` 를 직접 보지 않는다) |
| RLS 표현 | **`(select auth.uid()) = user_id`** |
| 정책 이름 | `"members manage own <대상>"` |

### 이미지는 Supabase Storage 에 넣는다

CardForge 는 로컬 디스크(`out/studio/...`)에 썼다. **배포할 때마다 사라지고 두 서버에서
서로 안 보인다.** 씨앗 저장소는 이미 Storage 를 쓴다.

```
버킷        library   비공개. 조회는 짧은 수명의 서명 URL
경로 규약    {user_id}/...   첫 칸이 소유자여야 한다
```

Storage RLS 가 **경로 첫 칸으로 판정**한다. 그래서 **새 정책을 만들 필요가 없다.**
경로 규약만 지키면 기존 정책이 그대로 적용된다.

```
{user_id}/{item_id}/{position}.{ext}      기존 작업물 (건드리지 않는다)
{user_id}/references/{id}.{ext}           참고 이미지            신규
{user_id}/sns/{project_id}/{index}.png    카드뉴스 결과          신규
{user_id}/poster/{project_id}/{id}.png    포스터 결과            신규
```

**DB 에는 경로 문자열만 담는다.** 이미지를 행에 넣지 않는다 — 목록 조회가 느려진다.

### 같은 DB 를 두 저장소가 쓴다 — 지켜야 할 규칙

두 배포가 한 Supabase 를 본다. 스키마 변경이 서로에게 영향을 준다.

```
① 새 테이블만 추가한다
② 기존 테이블의 컬럼을 바꾸거나 지우지 않는다
③ 마이그레이션 파일명이 겹치지 않게 한다 — 우리는 202608 부터 쓴다
④ 기존 테이블에 컬럼을 꼭 더해야 하면 nullable 로만 더한다
```

**②를 어기면 개인 배포가 죽는다.** 상세페이지 앱은 우리 변경을 모른다.
새 테이블(`ingest_*`, `sns_*`, `reference_sets`)은 상세페이지 앱이 아예 모르므로 안전하다.

## 쉬운 화면을 위한 원칙 — 이번 재구축의 기준

`detail-page-studio` 를 그대로 베끼는 것이 목적이 아니다. **사용자가 헤매지 않는 것**이 목적이다.
아래 여섯은 새로 만드는 화면 전부에 적용한다.

1. **한 화면에 한 가지 결정.** 기존 CardForge 마법사는 다섯 단계를 한 페이지에 쌓아 두어
   어디까지 했는지 알 수 없었다
2. **모든 선택에 결과를 미리 보여 준다.** 비율을 고르면 그 비율의 틀이 그 자리에서 보인다.
   장수를 고르면 표지·속지·엔딩이 몇 장인지 그 자리에서 계산해 보여 준다
3. **돈이 드는 버튼은 금액을 옆에 쓴다.** 누르기 전에 안다
4. **AI 가 정한 것은 회색, 사람이 정한 것은 검정.** 무엇을 내가 정했는지 한눈에 보인다
5. **기다리는 화면에 무엇을 하는 중인지 문장으로 쓴다.** 진행 막대만 도는 화면을 만들지 않는다
6. **되돌리기가 항상 있다.** 잘못 눌러도 돈이 안 나가야 한다

packages/ui/src/components/step-bar.tsx     ← 셋이 같이 쓴다
```

`/create` 와 `/redesign` 을 새 컴포넌트로 갈아 끼운다. **동작이 바뀌는 것은 리디자인의 클릭 정책뿐이다.**

## 라이브러리에 참고 이미지를 합친다

`/library` 가 이미 "저장한 작업"이다. 여기에 탭을 더한다.

```
라이브러리                          화면 하나
  ├ 작업물        library_items      기존 테이블. 건드리지 않는다
  └ 참고 이미지    reference_images   새 테이블
       ├ 낱장
       └ 묶음 세트   표지 + 속지 여러 장 + 엔딩을 한 벌로
```

**합치는 것은 화면이지 테이블이 아니다.**

기존 `library_items` 는 `tool check (tool in ('create','redesign'))` 로 막혀 있고,
의미도 **완성된 작업물**이지 입력 재료가 아니다. 참고 이미지를 거기 넣으려면 제약을 고쳐야 하고,
그러면 개인 배포와 부딪힌다.

**`reference_images` 를 새로 만들고 화면에서만 탭으로 합친다.** 사용자에게는 한 곳이고,
기존 테이블은 손대지 않는다.

**묶음 세트를 고르면 딸린 이미지가 역할까지 함께 들어온다.** 매번 네 장을 고를 필요가 없다.

작업물을 참고 이미지로 쓰고 싶으면 **「참고 이미지로 복사」** 로 옮긴다. 두 테이블을 섞지 않는다.

```

- 켬/끔 토글
- 주기 선택 (1·3·6·12·24시간)
- 마지막 오류는 **여기 안 보여준다** — 일반 사용자가 고칠 수 없다. 관리자 화면에만 둔다

## 유튜브 자막은 apify 로 우회한다

**EC2 에서 유튜브 자막 API 는 IP 차단된다.** 실측으로 확인됐다.

```
EC2(AWS IP)  → LOGIN_REQUIRED "Sign in to confirm you're not a bot" · 자막 0개
로컬(집 IP)  → OK · 자막 31개
```

CardForge 에서 `직접 자막 → apify → STT` 3단계로 바꿔 **실패 14건 → 0건**이 됐다. 그 코드를 복사한다.

**실패 이유를 단계별로 전부 남긴다.** 마지막 단계 오류만 남기면 진짜 원인이 가려진다 —
실제로 STT 의 `fetch failed` 가 자막 차단을 가리고 있었다.

## 워커

`apps/worker` 를 새로 만들고 **systemd 서비스로 따로 돌린다.**

```
detail-page-studio.service      웹 (기존)
content-studio-worker.service   수집 워커 (신규)
```

- 리스(lease)로 중복 실행을 막는다
- 다음 확인 시각(`next_poll_at`)을 DB 에 둔다
- 실패해도 다음 주기에 다시 시도한다

# 6. 카드뉴스 만들기 (`/sns`)

## 6-1. 화면 흐름

```
[ 01 내용 ]  [ 02 이미지 ]  [ 03 규격 ]  [ 04 원고 확인 ]  [ 05 결과 ]
```

통일한 `StepBar` 를 쓴다. **지난 단계는 눌러서 돌아갈 수 있다.**

### 화면 다섯 단계와 안에서 도는 여덟 단계

사람이 보는 것은 다섯이고, 그 사이에 시스템이 하는 일이 셋 더 있다.

| 화면 | 사람이 하는 일 | 안에서 도는 것 |
|---|---|---|
| 01 내용 | 글을 넣거나 가져온다 | |
| 02 이미지 | 첨부하고 종류·역할·자리를 정한다 | |
| 03 규격 | 비율·장수·언어·모델을 고른다 | |
| | **기획 시작** 을 누른다 | **④ 구조 기획 → ⑤ 원고** |
| 04 원고 확인 | 글자를 고친다 | |
| | **그림 만들기** 를 누른다 | **⑥ 프롬프트 생성 → ⑦ 생성 → ⑧ 검수** |
| 05 결과 | 보고, 다시 만들고, 내려받는다 | |

**⑥ 프롬프트 생성은 사람에게 안 보인다.** 카드마다 LLM 이 프롬프트를 쓰고 바로 fal 을 부른다.
다만 **쓴 프롬프트는 저장한다** — 결과가 이상할 때 무엇을 보냈는지 볼 수 있어야 한다.

## 6-2. 01 내용 — 네 가지 길

| 항목명 | 넣는 것 | 안에서 |
|---|---|---|
| **직접 쓰기** | 글 붙여넣기 | 그대로 |
| **유튜브 주소** | 영상 URL | 자막 → apify → STT |
| **웹 주소** | 기사·블로그 URL | 본문 추출 |
| **질문해서 찾기** | 궁금한 것을 문장으로 | **웹 검색 + 출처 인용** |

### "질문해서 찾기" 는 새 기능이 아니다

CardForge 의 `주제 조사` 가 이미 웹 검색을 돌리고 출처를 붙인다. **이름이 기능을 가리고 있었다.**

```
OpenAI + web_search
"공식 기관·논문·기업 공식 발표·신뢰할 수 있는 언론 우선"
"최근 자료 우선, 날짜 명시"
"독립적인 출처 최대 6개, 숫자·통계에 인라인 출처"
→ 한국어 1000자 이상 + 출처 목록
```

**이름과 안내만 바꾼다.**

```
주제 조사 · "조사할 주제를 적어 주세요"
  →  질문해서 찾기 · "궁금한 걸 물어보세요. 웹에서 근거를 찾아옵니다"
```

### 말투 메모 (선택)

목적(goal) 프리셋과 「목적 관리」 화면은 **만들지 않는다.** 대신 한 줄 입력을 둔다.

```
말투나 분위기 (선택)     예) 친구에게 말하듯 가볍게
```

비우면 AI 가 내용을 보고 정한다. **규칙을 만들지 않으면서 글투는 조절된다.**

## 6-3. 02 이미지 — 네 종류

07-30 참조 정책을 카드뉴스에 옮긴 것이다.

### ① 그대로 넣을 것 (identity)

> 제품 · 인물 · 로고 · 아이콘

AI 가 카드 안에 **그려 넣는다.** 각도·조명은 바뀌어도 되지만 **정체성은 유지**한다 —
모양 · 비율 · 색 · 재질 · 라벨 문구.

**스타일 레퍼런스와 충돌하면 이긴다.** 실제 파는 물건이 달라지면 의미가 없다.

인물은 **하나만** 쓴다. 얼굴이 둘이면 모델이 절충해 제3의 인물을 만든다.

### ② 원본 그대로 쓸 장

> 표 · 도표 · 포스터 · 캡처

**AI 를 거치지 않는다.** 올린 픽셀이 그대로 그 장이 된다.

```
원본 비율 ≠ 카드 비율  →  잘라내지 않는다. 여백을 둔다
여백 색                가장자리 평균색
```

표는 글자가 조금만 틀어져도 못 쓴다. 생성 모델에 넣으면 반드시 틀어진다.
**이 항목은 생성 대상이 아니라 배치 대상이다.**

### ③ 따라 만들 카드뉴스 (design language)

> 마음에 든 카드뉴스 이미지

이미지 모델에 **그대로 주고 내용만 갈아 끼운다.**

```
기존 CardForge   "색·배치만 가져오고 글자·삽화는 가져오지 마라"  → 느낌만 흉내
새로            "이 카드뉴스를 그대로 두고 내용만 바꿔라"       → 그림체·구조까지
```

**그림 종류(실사·일러스트·3D·콜라주)도 따라간다.** 기존 프롬프트의
`Do NOT take: specific illustrations` 가 이것을 막고 있었다.

역할을 지정한다 — **표지 / 속지 / 엔딩.**

### ④ 마지막 장

> 브랜드 마무리 이미지

맨 뒤 고정. **없으면 AI 가 내용 요약 마무리 페이지를 만든다.**

### 역할 지정 정리

| 항목 | 역할 | 위치를 누가 정하나 |
|---|---|---|
| 따라 만들 카드뉴스 | 표지 / 속지 / 엔딩 | 사람이 역할을 지정 |
| 그대로 넣을 것 | 없음 | **AI** — 내용에 맞는 카드에 그려 넣는다 |
| 원본 그대로 쓸 장 | 속지 자리 하나를 차지 | **사람** — 아래 참고 |
| 마지막 장 | 항상 마지막 | 고정 |

### 「원본 그대로 쓸 장」의 위치는 사람이 정한다

AI 에게 맡기지 않는다. **같은 입력에 같은 결과가 나와야 하고, 표가 몇 번째에 오는지는
내용 판단이 아니라 사용자의 편집 의도다.**

```
1번          표지
2 ~ N-1번     속지 구간
              원본 장을 지정한 자리에 놓고, 남은 자리를 AI 속지가 채운다
N번          마지막 장
```

02 이미지 화면에서 원본 장마다 **「몇 번째 속지」** 를 고른다. 비우면 앞에서부터 채운다.

예) 6장 · 원본 2장 · 자리 미지정 → `표지 / 원본1 / 원본2 / AI속지 / AI속지 / 마지막`
예) 6장 · 원본 2장 · 각각 2·4번째 지정 → `표지 / AI속지 / 원본1 / AI속지 / 원본2 / 마지막`

지정한 자리가 겹치거나 속지 구간을 벗어나면 **02 화면에서 그 자리에 알린다.**

**라이브러리 묶음 세트를 고르면 ③이 역할까지 함께 채워진다.**

## 6-4. 03 규격

| | 값 |
|---|---|
| 비율 | 4:5 · 1:1 · 9:16 · 16:9 |
| 전체 장수 | **AI 추천** · 4 · 5 · 6 · 7 · 8 |
| 언어 (다국어) | 한국어(기본) · 영어 · 일본어 · 중국어 |
| 모델 | **GPT Image 2 (기본)** · Nano Banana Pro · Nano Banana 2 |
| 첨부 이미지 | 최대 8장 |

**해상도 선택은 없앤다.** 고를 근거가 없고 비용만 달라진다. 코드가 고정한다.

| 비율 | GPT Image 2 | nano |
|---|---|---|
| 4:5 | 1088 × 1360 | `4:5` · 2K |
| 1:1 | 1088 × 1088 | `1:1` · 2K |
| 9:16 | 1152 × 2048 | `9:16` · 2K |
| 16:9 | 2048 × 1152 | `16:9` · 2K |

넷 다 GPT Image 2 제약(양 변 16의 배수 · 총 픽셀 655,360~8,294,400 · 최대 변 3840 ·
최대 비 3:1)을 만족한다.

### 기본 모델을 GPT Image 2 로 두는 근거

기존 CardForge 는 nano-banana-pro 를 골랐다. 근거는 *"후보 중 유일하게 `typography` 태그"* 하나였다.
**한글 렌더만 보고 정했고 레퍼런스 추종은 기준에 없었다.** 이번 시스템은 레퍼런스 추종이 본체다.

- CJK 텍스트 렌더링을 fal 이 직접 명시
- 참조 이미지 **16장** (nano 14장)
- 픽셀 직접 지정 — 16:9 를 포함한 규격을 정확히
- 마스크 편집 지원 (부분 수정에 나중에 쓸 수 있음)

### 장수 계산 — AI 에게 "몇 장?"을 묻지 않는다

```
전체 = 표지 1  +  원본 그대로 쓸 장 N  +  AI 가 채울 속지  +  마지막 장 1

예) 6장 선택, 원본 그대로 쓸 장 2개
    6 = 1 + 2 + [2] + 1
    → AI 에게 "속지 2자리에 뭘 넣을래?" 만 묻는다
```

**자리 수를 알려 주고 그 안을 채우게 한다.** 매번 같은 장수가 나온다.

`AI 추천` 이면 예약분을 먼저 빼고 남은 자리만 AI 가 정한다.

| 부딪히는 경우 | 처리 |
|---|---|
| 예약분이 고른 장수를 넘김 | **02 화면에서 그 자리에 막는다.** 기획 후에 알면 돈만 나간다 |
| 내용이 자리보다 많음 | 내용을 줄이고, 못 담은 것을 화면에 표시 |
| 내용이 자리보다 적음 | 그대로 만든다. 사용자의 명시적 선택이다 |

## 6-5. 04 원고 확인

**카드마다 어떤 글자가 들어갈지 확정하고 사람이 고친다.**

```
카드 3 / 6
  제목    자동화 첫걸음, 만능 비서 말고 '한 가지 업무'부터
  본문    결과와 입력이 명확한 단일 업무를 고른다...
  강조    (선택)
  출처    docs.x.ai
```

**여기서 고친 글자가 그대로 이미지에 박힌다.** 그림을 만들기 전에 글을 확정해야
글자 틀린 것 때문에 돈이 다시 나가지 않는다.

## 6-6. 05 결과

- 카드가 하나씩 채워진다. 무엇을 하는 중인지 문장으로 쓴다
- 카드마다 **다시 만들기** (그 장만)
- 검수에서 걸린 카드는 사유를 보여주고 **사람이 판단**한다
- 내려받기 (낱장 · 전체 zip)
- **게시글 문구 · 해시태그 복사** ← 기존에 복사가 안 되던 문제. 클립보드 API 로 확실히

## 6-7. 프롬프트 — 이번 재구축의 핵심

### 기존이 왜 실패했나

코드가 고정 틀에 값을 끼워 넣었고 규칙이 계속 쌓였다.

```
기존 1,715자
  참조 규칙        330자   ← 정작 중요한 것
  앵커 "똑같이"     150자   ← 참조를 덮음
  목적 서사 규칙    150자   ← 이미지 모델에게 무의미
  검수 재시도      450자   ← 재생성 때 참조를 밀어냄
```

### 새 구조

```
코드가 강제 (짧게, 반드시)
  · 첨부 이미지 번호와 역할을 문장으로 알린다 ← fal 은 라벨을 안 받는다
  · 이 글자를 그대로 렌더. 번역·의역·축약 금지. 목록에 없는 글자 추가 금지
  · 우선순위: 그대로 넣을 것 > 따라 만들 카드뉴스 > 장면 지시
  · 비율·규격

LLM 이 작성 (길게, 자유롭게)
  · 이 카드가 무엇을 보여줘야 하는가
  · 레퍼런스를 어떻게 따라갈 것인가
  · 구도·시선·강조
```

**LLM 은 첨부 이미지를 직접 본다.** 비전으로 레퍼런스를 읽고 프롬프트를 쓴다.
코드가 미리 정한 형용사 목록을 쓰지 않는다.

**단, 07-30 정책을 지킨다 — "분석해서 재구성"하지 않는다.**
원본 이미지는 **항상 함께 fal 에 넘어간다.** LLM 이 쓴 문장은 지시를 얹는 것이지 원본을 대체하지 않는다.

### 다국어 — 언어 이름만 바뀐다

프롬프트 뼈대는 영어로 쓰되 **렌더할 글자의 언어를 이름으로 지정**한다.

```
ko   Render this Korean text exactly as written, with correct spelling and spacing:
en   Render this English text exactly as written, ...
ja   Render this Japanese text exactly as written, ...
zh   Render this Chinese text exactly as written, ...
```

**글자 자체는 원고 단계에서 그 언어로 이미 쓰여 있다.** 이미지 모델은 옮겨 그리기만 한다.
`Do not translate` 지시가 있으므로 모델이 임의로 바꾸지 않는다.

원고를 쓰는 LLM 에게는 **출력 언어를 명시**한다. 자료가 한국어여도 영어 카드뉴스를 만들 수 있다.

### 시리즈 일관성 — 앵커를 없앤다

기존은 1번 카드 결과를 뒤 카드에 넣고 *"똑같이 만들어라"* 했다. **그것이 속지를 표지로 만들었다.**

```
기존   카드 N = [속지 레퍼런스, 카드1 결과]  + "카드1과 똑같이"
새로   카드 N = [속지 레퍼런스]              + LLM 이 쓴 프롬프트
```

**같은 레퍼런스를 보면 자동으로 한 벌이 된다.** 이전 결과를 넣지 않는다.

### 검수 반려

기존은 반려 지시 450자를 프롬프트 **뒤에** 붙여 참조 규칙을 밀어냈다.

**새로는 LLM 에게 되돌려 프롬프트를 다시 쓰게 한다.** 길이가 늘지 않는다.

## 6-8. LLM 구성

```
메인    claude-sonnet-5   (Anthropic)
백업    gpt-5.6-sol       (OpenAI)
```

메인이 실패하면 백업으로 넘어간다. **CardForge 에 이미 있는 폴백 구조를 복사한다.**

`ANTHROPIC_MODEL` 환경변수로 바꾸므로 나중에 `claude-fable-5` 로 교체할 수 있다.

# 6-9. 검수 — 무엇을 보고 누가 판단하나

생성된 이미지를 **별도 비전 모델이 실제로 보고** 평가한다. 프롬프트를 평가하는 것이 아니다.

## 무엇을 보나

```
글자 정확도    기대 원고와 글자 단위로 비교 — 철자·띄어쓰기·숫자·누락·중복·임의로 더한 문구
읽기           잘림·겹침·대비 부족
그대로 넣을 것  원본과 대조 — 형태·색·비율·라벨이 유지됐는가
```

**포스터·상세페이지와 프롬프트를 공유하지 않는다.** 카드뉴스 전용 검수기를 따로 만든다 —
"카드 N/M 장", 시리즈 맥락 같은 전제가 다르다.

## 무엇을 검수하지 않나

**「원본 그대로 쓸 장」은 검수하지 않는다.** AI 를 거치지 않은 사용자 원본이다.
글자가 틀릴 리 없고, 검수하면 돈만 나간다.

**사용자가 올린 「마지막 장」도 검수하지 않는다.** 같은 이유다.

```
검수한다      generated       AI 가 그린 카드
검수 안 한다   place_as_is     원본을 여백으로 맞춰 넣은 장
             ending_image    사용자가 올린 마지막 장
```

## 판정과 처리

| 판정 | 뜻 | 처리 |
|---|---|---|
| `pass` | 문제 없음 | 그대로 |
| `review` | 사소하지만 사람이 볼 것 | **표시만 하고 넘어간다** |
| `fail` | 의미 있는 오탈자·누락·잘림 | 표시하고 **사람이 결정** |

**자동 재생성을 하지 않는다.** 기존 CardForge 는 반려되면 자동으로 다시 만들었고,
그때 반려 지시 450자가 프롬프트 뒤에 붙어 참조 규칙을 밀어냈다. 돈은 돈대로 나가고
결과는 레퍼런스에서 더 멀어졌다.

**다시 만들지는 사람이 누른다.** 그때 LLM 이 반려 사유를 읽고 **프롬프트를 다시 쓴다** —
뒤에 덧붙이지 않는다.

## 검수도 돈이 든다

카드 8장이면 검수도 8번이다. **`review` 는 재생성을 부르지 않으므로 검수 비용이 배로 늘지 않는다.**

# 6-10. 모델 레지스트리와 비용

## 쓰는 모델은 넷이다 — 세 제품이 같다

상세페이지 · 카드뉴스 · 포스터가 같은 모델을 쓴다. **레지스트리 하나를 셋이 공유한다.**

| 모델 | t2i 엔드포인트 | i2i 엔드포인트 |
|---|---|---|
| Nano Banana (원조) | `fal-ai/nano-banana` | `fal-ai/nano-banana/edit` |
| Nano Banana 2 | `fal-ai/nano-banana-2` | `fal-ai/nano-banana-2/edit` |
| Nano Banana Pro | `fal-ai/nano-banana-pro` | `fal-ai/nano-banana-pro/edit` |
| **GPT Image 2** | `openai/gpt-image-2` | `openai/gpt-image-2/edit` |

## t2i 와 i2i 는 다른 엔드포인트이고 단가도 다르다

**같은 모델이라도 엔드포인트가 둘이다.** 레퍼런스 이미지를 넣으면 `/edit`, 없으면 t2i 다.
그리고 **GPT Image 2 는 두 단가가 다르다.**

```
GPT Image 2   1024×1024    t2i $0.211    edit $0.219
              1024×1536    t2i $0.165    edit $0.178
              3840×2160    t2i $0.401    edit $0.413
```

그래서 레지스트리는 **한 모델에 두 벌**을 담는다.

```ts
interface ImageModel {
  id: string;
  label: string;
  t2i: { endpoint: string; price: PriceTable };
  i2i: { endpoint: string; price: PriceTable };   // 레퍼런스가 있을 때
  maxReferenceImages: number;
  supportedRatios?: string[];        // 열거 모델
  pixelSizeLimits?: PixelLimits;     // 픽셀 지정 모델
  batchMax: number;                  // num_images 상한
}
```

**엔드포인트 선택은 코드가 한다.** `imageUrls.length > 0 ? i2i : t2i`.
사용자에게 묻지 않는다.

| 언제 | 무엇을 쓰나 |
|---|---|
| 카드뉴스 · 포스터 | 레퍼런스가 필수 → **항상 i2i** |
| 엔딩 요약 페이지 (레퍼런스 없이 만들 때) | t2i |
| 상세페이지 텍스트 모드 | 사진이 없으면 t2i |

## 비용 — fal 이 공표한 값으로 계산한다

**fal 모델 페이지의 값을 코드에 넣고 곱한다. 그게 전부다.**

### nano 계열 — 고정 단가 × 배수

| 모델 | 기본 | 배수 |
|---|---|---|
| Nano Banana | **$0.039** | 없음 (해상도 선택 불가) |
| Nano Banana 2 | **$0.08** | 0.5K ×0.75 · 1K ×1 · 2K ×1.5 · 4K ×2 |
| Nano Banana Pro | **$0.15** | 1K·2K ×1 · 4K ×2 |

우리는 해상도를 **2K 로 고정**하므로 실제로는 이렇게 된다.

```
Nano Banana 2    $0.08 × 1.5 = $0.12 / 장
Nano Banana Pro  $0.15 × 1   = $0.15 / 장
```

**웹 검색·thinking 옵션을 켜지 않는다.** 켜면 각각 +$0.015 · +$0.002 가 붙는다.

### GPT Image 2 — 크기별 표

`quality: high` 고정. 요청 크기에 해당하는 행의 값을 쓴다.

| 크기 | t2i | i2i (edit) |
|---|---|---|
| 1024×768 | $0.145 | $0.151 |
| 1024×1024 | $0.211 | $0.219 |
| 1024×1536 | $0.165 | $0.178 |
| 1920×1080 | $0.158 | $0.158 |
| 2560×1440 | $0.222 | $0.234 |
| 3840×2160 | $0.401 | $0.413 |

우리가 실제로 보내는 크기는 표에 없다. **가로세로비가 같은 행을 쓰고, 없으면 픽셀이 가장 가까운 행을 쓴다.**

```
4:5   1088×1360   →  1024×1536 행 (세로형)      i2i $0.178
1:1   1088×1088   →  1024×1024 행 (정사각형)    i2i $0.219
9:16  1152×2048   →  1024×1536 행 (세로형)      i2i $0.178
16:9  2048×1152   →  1920×1080 행 (가로형)      i2i $0.158
```

**픽셀 수로만 고르지 않는다.** 이 표는 픽셀에 비례하지 않는다 —
1024×1536(1,572,864px)이 1024×1024(1,048,576px)보다 싸다. 정사각형이 비싸다.
**모양이 같은 행을 먼저 본다.**

### 이 값이 정확한가

nano 셋은 **정확하다.** 고정 단가다.

GPT Image 2 는 토큰 과금이라 프롬프트 길이·입력 이미지 장수에 따라 조금 달라진다.
**표 값이 근사치다.** 다만 fal 이 공표한 유일한 값이므로 이걸 쓴다.
더 정확히 하고 싶으면 fal 대시보드에서 대조한다.

## LLM 비용은 정확하다

| 무엇 | 어떻게 |
|---|---|
| 기획·원고 (Anthropic / OpenAI) | 응답의 `input_tokens` · `output_tokens` × 단가 |
| 검수 (OpenAI 비전) | 〃 |
| 질문해서 찾기 (웹 검색) | 토큰 + 검색 호출 수 |

**추정이 아니라 실제 사용량이다.** 응답에 토큰 수가 온다.

## 기록 규칙

```
이미지    생성 요청 한 행에 한 번.  카드마다 복제하지 않는다 (8장이면 합계가 8배가 된다)
LLM      호출마다 한 행
저장     Supabase 에만. 파일 원장을 만들지 않는다
```

기존 CardForge 는 파일(`data/usage-ledger.jsonl`)에 쌓고 테이블은 0건이라
**화면 값과 실제가 갈라져** 있었다.

## 어디서 보나

`/settings` 사용량 화면에서 **상세페이지·리디자인·카드뉴스·포스터를 한 곳에서** 본다.
기능별·기간별로 나눠 본다. 상세페이지가 이미 쓰는 화면을 넓히는 것이지 새로 만들지 않는다.

# 6-11. 포스터 만들기 — 기존 설계를 쓰되 세 곳을 고친다

설계와 구현 계획이 이미 있다. 외부 리뷰 두 라운드에서 결함 14건을 고친 문서다.

```
docs/2026-08-31-poster-studio-design.md    설계 (33KB)
docs/2026-08-31-poster-studio.md           구현 계획 (16 태스크 88 단계)
```

**핵심은 그대로 쓴다** — 슬롯 고정 · 비율↔모델 자동 매칭 · 레퍼런스에서 문법 추출 ·
배치 결과 계약 · 비용 추정/정산 분리 · A4 인쇄 규격.

## 그러나 전제 셋이 바뀌었다. 그대로 쓰면 안 된다

포스터 설계는 **CardForge 의 팀 권한 모델**을 전제로 썼다. 이제 상세페이지의 회원제로 옮긴다.

### ① 권한 모델 — 팀에서 소유자로

```
포스터 설계서 (CardForge)      상세페이지 스튜디오
team_id                        owner_id
is_master() or team_id = ...   owner_id = auth.uid()
has_permission('content.create') 회원이면 가능
```

`poster_references` · `poster_projects` · `poster_generation_requests` · `poster_images`
네 테이블의 **RLS 정책과 컬럼 권한을 전부 소유자 기준으로 다시 쓴다.**

**컬럼 권한을 허용 목록으로 쓰는 규칙은 그대로 유지한다** — 회수가 아니라 허용이다.

```sql
revoke update on public.poster_projects from authenticated;
grant update (title, status, data, updated_at) on public.poster_projects to authenticated;
```

### ② 갤러리 — 포스터 전용 테이블을 만들지 않는다

포스터 설계서 D6 은 `poster_references` 를 **카드용과 별도**로 두라고 했다.
그때는 카드 갤러리와 섞이면 혼란스럽다는 이유였다.

**이제는 라이브러리 하나로 합치기로 했다.** 그러므로:

```
버린다   poster_references 테이블
쓴다     라이브러리(기존) + reference_sets(묶음) + 용도 구분
```

라이브러리 항목에 **용도**를 둔다 — `카드뉴스` · `포스터` · `공용`.
포스터 레퍼런스를 카드뉴스에서 고르는 일이 없게 하되, 저장소는 하나다.

### ③ 비용 — 공표 단가로 계산한다

포스터 설계 D10 은 사후 정산(Billing Events + Admin 키)까지 설계했으나 **쓰지 않는다.**
**fal 이 공표한 단가표로 계산한다**(6-10). 모델이 넷뿐이고 셋은 고정 단가라 그걸로 충분하다.

포스터 전용 비용 테이블도 만들지 않는다. 6-10 의 통합 기록을 쓴다.
포스터 계획서 Task 16(정산)은 **범위에서 뺀다.**

## 만드는 순서에서의 위치

카드뉴스보다 **뒤에** 둔다. 카드뉴스에서 확인할 것(GPT Image 2 가 레퍼런스를 잘 따르는가,
LLM 이 쓴 프롬프트가 나은가)이 포스터에도 그대로 적용되기 때문이다.
카드뉴스에서 답이 나오면 포스터는 그 답을 갖고 시작한다.

# 7. 데이터

## 기존 테이블 — 손대지 않는다 (상세페이지와 같은 DB 를 쓴다)

```
회원 · 사용량 · 라이브러리 · 스타일 레퍼런스 · 캐릭터 · 비용 추적
```

## 새 마이그레이션

명명은 기존 방식을 따른다 — `YYYYMMDDNNNN_name.sql`

```
202608310001_ingest.sql        소스 · 후보
202608310002_sns.sql           카드뉴스 프로젝트 · 카드 · 생성 요청
202608310003_references.sql    참고 이미지 · 묶음 세트
202608310004_poster.sql        포스터 프로젝트 · 생성 요청 · 결과
```

### 수집

```
ingest_sources     id · user_id · kind · name · url · interval_hours · enabled
                   last_checked_at · next_poll_at · lease_until · last_error
ingest_candidates  id · user_id · source_id · title · url · body · summary
                   published_at · collected_at · status · thumbnail_url
```

### 카드뉴스

```
sns_projects            id · user_id · title · status · ratio · language
                        model_id · card_count_mode · card_count · data(jsonb)
sns_generation_requests id · project_id · fal_request_id · model_id
                        requested_images · returned_images · cost 관련
sns_cards               id · project_id · index · role · copy(jsonb)
                        prompt · asset_path · status · review(jsonb)
```

**비용은 생성 요청 한 행에만 기록한다.** 카드마다 총액을 복제하면 배치에서 합계가 부풀려진다.

### 참고 이미지

```
reference_images     id · user_id · storage_path · title
                     purpose(cardnews|poster|both) · width · height · created_at
reference_sets       id · user_id · name · purpose
reference_set_items  set_id · reference_image_id · role(cover|body|ending) · position
```

**기존 `library_items` 를 쓰지 않는다.** 그 테이블은 `tool check (create|redesign)` 로 막혀 있고
의미도 완성 작업물이다. 참고 이미지는 입력 재료라 성격이 다르다. **합치는 것은 화면이다.**

## 권한

기존 저장소의 RLS 패턴을 따른다. **컬럼 권한은 회수가 아니라 허용 목록으로 쓴다.**

```sql
-- 틀림: 테이블에 주고 컬럼을 뺀다 (컬럼 REVOKE 는 무시된다)
grant update on public.sns_projects to authenticated;
revoke update (user_id) on public.sns_projects from authenticated;

-- 맞음: 테이블에서 회수하고 컬럼만 준다
revoke update on public.sns_projects from authenticated;
grant update (title, status, data, updated_at) on public.sns_projects to authenticated;
```

CardForge 팀 권한 설계에서 외부 리뷰가 세 라운드 도는 동안 이 실수를 두 번 했다.

# 9. 만드는 순서

각 단계가 끝나면 **그 자체로 돌아가는 것**이 나와야 한다.

| 단계 | 끝나면 |
|---|---|
| **1. 씨앗** | 새 저장소·새 Supabase·새 EC2 에서 상세페이지가 그대로 돈다 |
| **2. 스텝 UI 통일** | `/create` `/redesign` 이 같은 스텝 막대를 쓴다 |
| **3. 수집 미디어** | 소스를 등록하고 워커가 수집한다 |
| **4. 수집함** | 수집한 내용을 읽고 제작 후보로 고른다 |
| **5. 라이브러리 확장** | 참고 이미지를 올리고 묶음으로 저장한다 |
| **6. 카드뉴스** | ← 가장 크고 위험하다. 실물로 확인하며 간다 |
| **7. 포스터** | 설계·계획대로 붙인다. 권한 모델과 갤러리만 새 전제로 고쳐서 |

**1단계가 끝나야 나머지가 성립한다.** 씨앗이 안 돌면 그 위에 뭘 얹어도 검증이 안 된다.

# 10. Codex 와 병행하는 방식

```
Claude   설계 → Codex 구현 → Claude 코드 전수 리뷰 → 수정 → 반복
```

08-27~28 에 팀 로그인 시스템을 같은 방식으로 만들었다. **설계 리뷰 3라운드에서 결함 9건,
구현 리뷰에서 2건**을 찾았다.

## 잘 되게 하려면

1. **계획이 태스크 단위로 쪼개져 있어야 한다.** Codex 는 문서만 보고 만든다.
   *"적절히 처리하라"* 가 있으면 알아서 지어낸다. 포스터 계획서를 16태스크 88단계로 쪼갠 이유다
2. **Claude 가 매번 코드를 직접 읽는다.** *"다 만들었습니다"* 를 믿지 않는다.
   지난번에도 보고는 정상이었는데 읽어 보니 팀원이 참고 그림을 못 올리는 결함이 있었다
3. **사용자가 중계한다.** Claude 와 Codex 는 직접 대화하지 못한다

## 위험

**설계서 품질이 곧 결과 품질이다.** 애매하게 쓰면 Codex 가 자기 판단으로 메운다.
그래서 이 설계서 다음에 **포스터 계획서 수준의 구현 계획**을 써야 한다 — 테스트 코드까지 넣는 방식.
