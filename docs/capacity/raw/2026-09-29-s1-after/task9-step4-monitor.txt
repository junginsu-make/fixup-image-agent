## 회복(recovered) 처리 확인

서비스를 다시 올리고 이후(배포·측정 과정에서 여러 차례 재시작/헬스체크가 더 있었다) 다음
타이머 실행에서 준비 상태가 다시 성공하며 감시 스크립트가 `down.alerted` 를 0 으로 되돌렸다.

```
sudo cat /var/lib/fixup-image-agent-monitor/down.alerted → 0
sudo cat /var/lib/fixup-image-agent-monitor/down.count   → 0
systemctl is-active fixup-image-agent caddy fixup-image-agent-monitor.timer → active active active
```
`ALERT_EMAIL` 이 비어 있어 "recovered" 발송 로그 자체는 남지 않는다(설계대로 — send() 가
alert_to 없으면 아무 것도 하지 않고 조용히 반환). 상태 파일의 0 복귀가 실제 증거다.
