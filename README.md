# FormWith

**말과 참고 그림으로 마케팅 이미지를 만드는 웹 서비스.** 카드뉴스 · 광고 소재 · 포스터 ·
상세페이지 · 캐릭터를 한 곳에서 만들고, 만든 것을 라이브러리에 쌓아 다시 씁니다.

- 서비스: <https://formwith.fix-up.kr>
- 개발 일지: [`docs/devlog`](docs/devlog/README.md) — 2026-08-31 첫 저장부터 한 주씩, 쉬운 말 요약과 작업 묶음(PR) 목록
- 옛 이름은 MCS(Marketing Content Studio)입니다. 2026-09-22 에 FormWith 로 바꿨습니다(#168).
  `detail-page-studio` 를 씨앗으로 복제했지만 그 뒤로는 별개 제품이며 원본을 참조하지 않습니다.

사용자가 올린 참고 그림 ─┐
                        ├─→ 라이브러리 ─→ 만들기 ─→ 작업물 ─┐

**한 바퀴가 닫혀 있는 것이 이 시스템의 뼈대입니다.** 올린 것과 만든 것이 모두 라이브러리에
쌓이고, 어느 도구에서든 그것을 불러 씁니다. 지난 작업은 라이브러리에서 단계별로 다시 열 수
있습니다.

## 도구

사이드바 이름 그대로 적었습니다. 로그인하면 사용 설명서(`/guide`)가 먼저 열립니다.

| 도구 | 하는 일 |
|---|---|
| **쉽게** (`/easy`) | 말로 주문하면 대화하며 이미지와 카드뉴스를 만들고, 만든 이미지를 이어서 고칩니다 |
| **다양하게** (`/poster`) | 광고 소재 · 포스터 · 일반 이미지 한 장. 따라 만들 그림을 고르고 한 줄 적으면 나머지 칸은 AI 가 초안으로 채웁니다. 글만으로도 시작합니다 |
| **카드뉴스** (`/sns`) | 여러 장의 카드로 이야기합니다. 원고를 사람이 확인한 뒤 그림을 만들고, 글자가 원고대로 들어갔는지 검수합니다 |
| **캐릭터** (`/characters`) | 인물 · 동물 · 사물을 여러 각도로 고정해 두고 다시 씁니다. 묘사를 AI 가 정리하고, 다른 화풍 · 체형으로 바꿉니다 |
| **광고소재** (`/ad`) | 만든 그림을 포털 광고 규격(필수 소재 9종)으로 뽑아 내려받습니다 |
| **상세페이지 만들기** (`/create`) | 상품 사진 한 장 **또는 글만으로** 상세페이지를 새로 |
| **리디자인** (`/redesign`) | 기존 상세페이지(이미지 · PDF)를 분석해 전환율 중심 원칙으로 다시 구성 |
| **라이브러리** (`/library`) | 작업물 · 캐릭터 · 참고 이미지. 만든 기능으로 거르고, 지난 작업의 과정을 다시 엽니다 |
| **사용 설명서** (`/guide`) | 로그인 없이도 열립니다. AI 도우미가 설명서를 근거로 사용법을 답합니다 |
| **계정** (`/settings`) | 월 이미지 크레딧 · 구독 · 사용 기록 · 탈퇴 |
| **관리자** (`/admin`) | 회원 관리 · 시스템 관리(AI 비용 · 전체 멈춤 · 그림 서비스 계정 · 문의) · 비용 전략 · 방문 분석 |

참고 이미지와 작업물을 나누는 기준은 하나입니다. **참고 이미지는 사용자가 첨부한 것, 작업물은
이 시스템이 만든 것.**

**꺼 둔 것.** 수집함 · 수집 리스트(`/inbox`, `/sources`, 2026-09-10)와 팀(`/team`, 2026-09-22)은
코드와 표는 남기고 입구만 닫았습니다. 켜는 방법은 `apps/web/lib/access/routes.ts` 의 주석에 있습니다.

> **성과 검증은 하지 않았습니다.** 이 시스템이 만든 상세페이지가 실제로 더
> 팔리는지는 재지 않았고, 저장소에 전환율·매출 데이터는 한 줄도 없습니다.
> 화면의 「판매 원칙 심사 통과」는 **AI 가 제 결과를 다시 읽고 매긴 점수**이지
> 판매 효과가 아닙니다. 자세한 것은
> [`docs/bugs/pdp-validation/w9-performance.md`](docs/bugs/pdp-validation/w9-performance.md).

## 회원 · 크레딧 · 비용

- **가입:** 이메일, Google · 카카오 간편가입. 전화번호는 선택입니다.
- **크레딧:** 그림을 만들 때마다 장부에 적고, 모델마다 가중치를 둡니다. 구독은 관리자가 직접 배정합니다.
- **AI 사용 통제:** 크레딧이 없거나 관리자가 전체 멈춤을 켜면 돈이 드는 AI 호출을 막습니다.
  호출마다 비용을 기록해 관리자 화면에서 한국 시각으로 봅니다.
- **AI 생성 표시:** 만든 그림 파일 안(EXIF)에 AI 생성 사실을 적습니다.
- **방문 분석:** 쿠키 없이 하루 단위로 세고, 동의한 브라우저만 여러 날을 잇습니다.
  자세한 것은 `docs/superpowers/plans/2026-10-06-site-analytics.md`.

## 품질 장치

### 원고와 그림을 나눠서 만든다

카드뉴스는 기획 → 원고 → 그림 순서로 갑니다. **원고 단계에서 사람이 글자를 직접 고칩니다.**
고친 글자가 그대로 그림에 들어갑니다. 그림을 만든 뒤에 글자를 고치려면 다시 만들어야 하는데,
그건 돈이 드는 일입니다.

만든 그림은 다른 호출로 검수합니다 — 원고에 없는 글자가 들어갔는지, 글자가 바뀌었는지.
검수 결과는 한 줄로 먼저 보여주고 자세한 것은 접어 둡니다. 스키마의 영문 값(`extraCopy`,
`uncertain`)은 우리말로 바꿔서 보여줍니다.

### 구성안 심사 (상세페이지)

구성안을 만든 호출과 **다른 호출**로 심사합니다. 같은 호출 안에서 매기는 점수는 방금 쓴 글을
스스로 칭찬하는 것에 가깝습니다.

심사자에게는 구성안과 판매 원칙만 줍니다. 브리프 원문은 주지 않습니다 — 주면 "이 브리프로는
이 정도면 잘 쓴 것"이라는 변호를 합니다. 사는 사람은 브리프를 못 봅니다.

항목은 여섯입니다: **대상 · 문제 · 차별점 · 반론 · 흐름 · 행동 유도**. `fail` 이 하나라도 있으면
지적사항을 담아 다시 만듭니다(최대 2회). 끝까지 남은 지적은 **숨기지 않고 화면에 띄웁니다.**

판매 원칙은 `packages/pdp-core/src/pdp.sales-principles.ts` 가 단일 출처입니다.

### 참고 이미지를 어떻게 쓰는지 말로 정한다

레퍼런스 이미지는 효과가 세서 어떻게 쓸지 못박아 둡니다. 역할 어휘는 다섯 가지로 통일돼 있습니다
(`packages/shared/src/attachment-role.ts`).

```
따라 만들기                  레이아웃·서체·색만 가져오고 내용은 새로 만든다
제품 그대로 지키기            그 물건은 바꾸지 않는다
인물 그대로 지키기            그 사람은 바꾸지 않는다
사람은 그대로, 그림 느낌만     얼굴·옷차림은 두고 그림 느낌만 다른 첨부를 따른다
원본 그대로 넣기              생성하지 않고 그 그림을 그 자리에 넣는다
```

상세페이지의 스타일 레퍼런스는 **페이지당 한 장**만 씁니다. 섹션마다 다르면 통일이 깨집니다.
어울리는 것이 없으면 아무것도 쓰지 않습니다. 고르는 것은 유사도 검색이 아니라 LLM 입니다 —
질의는 상품 얘기인데 레퍼런스 서술은 디자인 얘기라 임베딩으로는 변별되지 않습니다(측정 근거:
`docs/superpowers/specs/2026-07-27-style-reference-rag-design.md`).

### 이미지 모델

생성은 fal.ai 를 경유합니다. 원가가 4.6배까지 벌어져 크레딧 가중치를 둡니다.

화면은 **이름표**로 보여 줍니다(모델 id 가 아니라). 아래 표는 코드의
`IMAGE_MODELS` 와 같아야 하며, 어긋나면 `pdp.model-doc.test.ts` 가 빨개집니다.

| 모델 | 가중치 | 특징 |
|---|---|---|
| 표준형 (기본) | 4 | 어떤 그림이든 고르게. 글자 많은 그림에서 한글이 정확. 6장에 약 2분 |
| 디테일형 | 3 | 질감·인물이 섬세. 여러 장에서 같은 인물 유지. 6장에 약 2분 |
| 속도형 | 2 | 고른 품질로 여러 장을 빠르게. 참고 그림 많이 받음 (시간은 아직 실측 전) |
| 이전 방식 | 4, 2, 1 | 숨긴 옛 모델 다섯(정밀형·속도형 라이트·경제형·일관형·화풍형 자리). 저장된 작업이 id 를 들고 있어 남김. 고르는 화면에는 안 나옴 |

상세페이지 섹션은 한 장씩이 아니라 **묶음으로 한 번에** 만듭니다. 순차 호출은 장마다 크레딧을
예약해 동시 실행 제한에 스스로 걸렸습니다.

### 만드는 도중에 화면을 옮겨도 된다

fal 에 요청을 보내 두면 fal 은 알아서 그리지만, 예전에는 **결과를 받아 오는 것이 화면**이라
화면을 옮기면 받아 오는 일이 멈췄습니다.

지금은 목록을 셸(사이드바)이 들고 있습니다. 셸은 화면을 옮겨도 다시 만들어지지 않으므로 계속
받아 옵니다. 사이드바 아래에 무엇이 돌고 있는지, 얼마나 됐는지 보이고 중지할 수 있습니다.
상세페이지 · 캐릭터 · 리디자인 그림은 2026-10-01 부터 서버 대기열이 맡습니다(#234). 사람이
몰려도 그림 서비스 계정 여러 개를 돌려 씁니다(#237).

**중지는 되돌리기가 아닙니다.** fal 에 이미 보낸 요청은 취소하지 못합니다. 멈추는 것은 받아
오는 일뿐이고 보낸 요청의 비용은 그대로 나갑니다. 그 자리에 그렇게 적어 뒀습니다.

## 데이터

**하나의 Supabase 프로젝트**에 전부 들어갑니다. 회원 · 참고 이미지 · 만든 결과물 · 크레딧 장부.
상세페이지 서비스와 같은 프로젝트를 쓰므로 **계정이 공유됩니다.** 그래서 표는 더하기만 하고,
남의 서비스가 쓰는 것은 바꾸지 않습니다.

파일은 비공개 버킷에 두고 짧은 수명의 서명 URL 로만 엽니다. 경로 첫 칸이 소유자이고,
버킷 정책이 그 칸으로 남의 것을 막습니다.

```
{user_id}/references/{id}.{ext}       참고 이미지
{user_id}/sns/{작업}/{카드}.png        카드뉴스 결과
{user_id}/poster/{작업}/{변형}.png     이미지 만들기 결과
```

리디자인이 참고하는 디자인 지식만 별도 DB(Neon pgvector)에 있습니다. 회원 데이터나 생성
결과물은 들어가지 않습니다.

로컬에서는 `LOCAL_STORE=1` 로 파일 저장소를 씁니다. `NODE_ENV=production` 에서는 이 값들이
무시되므로 운영에서 실수로 켜지지 않습니다.

## 개발

```bash
corepack enable pnpm      # 최초 1회
pnpm install
pnpm dev                  # http://localhost:3000
```

검사: `pnpm -r typecheck`, `pnpm test`, `pnpm build`. CI 가 도는 것은 PR 전에 로컬에서 다 돌립니다.

로컬은 `apps/web/.env.local` 에서 `LOCAL_STORE=1` · `LOCAL_AUTH_BYPASS=1` 로 로그인 없이
파일 저장소를 씁니다. **Supabase 값은 일부러 비워 둡니다** — 채우면 로컬의 삭제 단추가 운영 DB 의
진짜 데이터를 지웁니다. 그래서 로컬에서는 라이브러리 · 캐릭터 목록이 비어 보이며, 고장이 아닙니다.

## 배포

**운영은 EC2 입니다.** 저장소에 연결된 Vercel 프로젝트는 구버전이며 운영이 아닙니다.
PR 체크에 Vercel 이 뜨더라도 배포 판단 근거로 삼지 마십시오.

```
브라우저 ─HTTPS→ Caddy(formwith.fix-up.kr) ─→ Next.js standalone(127.0.0.1:3000)
                                              ─→ Supabase (DB · 파일 · 로그인)
                                              ─→ fal.ai (그림) · LLM
```

절차와 확인 목록은 [`docs/DEPLOY.md`](docs/DEPLOY.md) 의 「매 배포」에 있습니다. 요약하면,

```bash
# master 에 합치면 GitHub Actions 가 검사한 뒤 꾸러미를 릴리스 자산(release-<sha12>)으로 올린다
gh release download release-<sha12> -D <작업폴더> -p '*.tar.gz'
scp -i <키> <작업폴더>/fixup-image-agent-*.tar.gz ubuntu@<호스트>:/tmp/
# 서버에서 ops 꾸러미를 풀고 deploy-release.sh 를 sudo 로 돌린다 (명령은 DEPLOY.md)
```

배포 스크립트가 기동을 확인하고, 실패하면 **직전 릴리스로 자동 롤백**합니다. 수동 롤백은
`deploy/ec2/rollback-release.sh`. 확인까지 해야 배포가 끝납니다 — 서비스 `active`, 로컬 200,
`current` 가 새 릴리스, 이번 변경 문구가 빌드 안에 실제로 있는지.

**하지 않는 것:** Windows 나 EC2 에서 빌드하지 않습니다(꾸러미는 Linux 전용이고, EC2 는 램이
작아 돌고 있는 서비스가 죽습니다).

### 꾸러미가 이식 가능해야 하는 이유

`dist/ec2` 에는 standalone 서버, workspace 런타임 의존성, `public`, `.next/static`, 그리고
묶어 둔 수집 워커만 모이며 로컬 `.env*` 는 제거됩니다.

여기서 두 번 데었습니다. 둘 다 **배포해 봐야 아는 실패**였고, 지금은 둘 다 빌드가 막습니다.

**하나. 심볼릭 링크가 빌드 머신을 가리켰다.** pnpm 이 만든 링크가 절대 경로여서 꾸러미가 빌드한
기계에서만 돌았습니다. 2026-07-28 운영 배포에서 `Cannot find module 'next'` 로 죽고 롤백된 뒤에야
드러났습니다. 지금은 상대 경로로 바꿉니다. 링크 구조 자체는 유지해야 합니다 — pnpm 은 그 구조로
모듈을 해석해서, 실제 파일로 풀어버리면 `next` 는 찾아도 그 옆의 `styled-jsx` 를 못 찾습니다.

**둘. sharp 의 네이티브 라이브러리가 자리를 잃었다.** `.node` 바인딩은 `libvips-cpp.so` 를 OS
수준에서 엽니다. 자바스크립트 require 가 아니라 Next 의 추적에 안 잡히고, 그래서 그 `.so` 가
빠진 채 배포됐습니다. 이미지를 다루는 API 가 죽고 Next 가 HTML 오류 페이지를 돌려주니, 화면에는
`Unexpected token '<'` 만 떴습니다 — 원인과 증상이 멀어 찾는 데 오래 걸렸습니다.

두 번째는 한 번 더 틀렸습니다. 처음 고쳤을 때 "꾸러미 어딘가에 있는가" 로 검사했는데 그건
통과했습니다. 파일은 있었으니까요. 정작 필요한 것은 **바인딩이 찾는 그 자리에 있는가** 였습니다.
지금은 그 자리를 봅니다.

### 운영 환경변수

호스트의 `/etc/fixup-image-agent/app.env`(root 소유, `640`)에서만 읽습니다. systemd
`EnvironmentFile` 로 주입되며 꾸러미에는 들어가지 않습니다.

이름은 전부 코드가 실제로 읽는 것만 적혀 있습니다 — 안 읽는 이름을 적어 두면 채워 놓고도 안 되는
이유를 찾느라 시간을 씁니다. 템플릿은 `deploy/ec2/app.env.example`.

`FAL_KEY` 가 없으면 이미지가 한 장도 안 만들어집니다.

## 아직 안 된 것

- **성과 측정** — 위의 「성과 검증은 하지 않았습니다」 그대로입니다.
- **자동 수집** — 꺼 두었습니다. 다시 켜도 공식 AI 블로그 수집은 브라우저(playwright)가 필요해
  작은 서버에서는 빠집니다.
- **마이그레이션 기록** — 표는 대시보드 SQL 편집기와 MCP 로 넣었습니다. `supabase db push` 는
  기록이 어긋나 쓰지 않습니다. 파일은 `supabase/migrations/` 에 남깁니다.

## 참고

소스 코드의 모델 ID 는 실제로 접근 가능한 것들입니다. 동작은 키와 모델 접근 권한에 의존합니다.

구현 중 측정으로 뒤집힌 설계는 문서에 이유와 함께 남겨 뒀습니다 — 특히 **작고 전부 필요한
지식은 검색(RAG)하지 말고 프롬프트에 통째로 넣어야 한다**는 것이 두 번 확인됐습니다.
